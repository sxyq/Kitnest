### 1.2 代码风格（从反汇编模式推断）

- Swift 5/6，**Swift Concurrency 混合 GCD**（反汇编见 `swift_task_create`、`DispatchQueue.async` 并存）
- 错误处理：大量 `swift_allocError` + `swift_willThrow`（throws 风格）
- 状态管理：Combine `@Published` 模式（Publisher 特化符号密集）
- 类设计：单例 Manager 模式（ClipboardManager/ScreenshotManager 等，从调用形态推断）
- **本机原版 Swift 版本**：未能从二进制提取（strip），用现代 ABI（带 `__swift56_hooks` 段 → Swift 5.6+ 编译器）

## 2. Swift 元数据测绘（本轮实测）

### 2.1 段清单（arm64 slice）
```
__swift5_typeref / __swift5_fieldmd(107KB) / __swift5_reflstr(110KB)
__swift5_builtin / __swift5_assocty / __swift5_capture / __swift5_proto
__swift5_types(5.8KB) / __swift5_mpenum / __swift5_entry / __swift5_protos / __swift56_hooks
```

### 2.2 解析结果与结论
- 自研解析器（`tools/swift_fieldmd.py`）成功解析 **96 个类型的字段元数据**（输出：
  `frset/rea-evidence/rea-early/frset-metadata-fields.json`）；
- **但 96 个中绝大多数是 Sentry/PostHog 的协议/结构**——Frset 自有类的字段反射**被 strip 裁剪**（release 构建剥掉了大部分反射元数据）；
- 实测 `$s5Frset` 前缀 mangled 符号仅 **11 个**（符号表同样剥离）；
- **结论**：字段级"抄写式还原"不可行；源码级贴近 = **行为级还原**（反汇编精读）+ 数据模型（已有 schema）+ 技术栈对齐（§1）。这与"UI 照截图、逻辑照汇编"策略一致。

### 2.3 仍可利用的元数据
- 类型名（191 类清单，反射类型表保留）✅ 已有
- `__swift5_capture`（闭包捕获结构）——待用
- `__swift5_proto`（协议一致性）——待用
- 协议类型（96 个里的 Frset 协议，如 `LLMProviderAdapting`/`AICredentialStoring`）——**揭示架构接口定义**，已入库

## 3. 测绘工具箱（四件套，全部验证可用）

| 工具 | 位置 | 用途 | 验证案例 |
|---|---|---|---|
| `swift_fieldmd.py` | `frset-rebuild/tools/` | 解析 Swift 字段元数据（类型/字段名/类型签名） | 本轮 96 类型解析成功 |
| `da.py` / `refs.py` / `find_tabstrings.py` | `frset/rea-evidence/tab-removal/` | 反汇编查询（函数窗/调用者/引用扫描/立即数扫描） | 页签根治、多处定位 |
| `inj_kt3.m` 模式（注入钩子打调用者返回地址） | `frset/rea-evidence/keychain-neuter/` | **运行时精确到调用点**（减 ASLR slide） | 钥匙串补丁 J 定位 |
| `swift-demangle` | `/Library/Developer/CommandLineTools/usr/bin/` | mangled → Swift 签名 | 本轮批量使用 |

**方法论（按优先级）**：
1. **类型名 xref 法**：类型名字符串 → adrp/add 引用 → 类方法区（FloatingPanel 实证：`0x10023c000` 区）；
2. **注入钩子法**：对目标 API（如 `sqlite3_open_v2`/`SecItem*`）hook 打印调用者返回地址（需先算 slide）；对未知入口（如 ClipboardManager）先 hook 通用 API（NSPasteboard/定时器）再反推；
3. **字符串考古**：已知锚点——`clipboard.sqlite` @ `0x100b42d20`、SQL 片段（`is_generated_by_tool` 等，拼接式存储）、错误消息；
4. **数据法**：SQLite schema（已全）+ 偏好键 + 统计表（`usage_daily_metrics` 事件名可反推功能埋点）。

## 4. "贴近源码还原"工作流（开发时执行）

```
开发模块 X
  ↓
1. 查 01 号文档：X 的类清单 + 已知地址 + 逆向待办
  ↓
2. 定位类区：类型名 xref（若失败 → 注入钩子打点）
  ↓
3. 逐函数精读：da.py fwin 扫读 → 识别"输入/输出/分支/依赖调用"
  ↓
4. 交叉验证：实机行为 + schema + 截图 + 报告（四源对齐）
  ↓
5. 产出：该模块 02-XX 号规格（含"原始行为描述 + 建议 Swift 实现"）
  ↓
6. 实现 → tests/ 行为对照（同一场景，原 App vs 新实现）
  ↓
7. 若发现与规格不符 → 回到 3 继续读（记录新发现，回填 01 号文档）
```

**输出物模板**（规格内新增"还原依据"节）：
```
## 还原依据
- 类区：0x100xxxxxx-0x100yyyyyy（类型名 xref 定位）
- 关键函数：0x100zzz（行为：…，依据：da.py fwin + 实机验证）
- 数据锚点：clipboard_items.is_note（schema）
- 技术栈：Combine @Published 驱动刷新（依据：Publisher 符号 + 反汇编）
```
