## 5. 外观三态实现（探明问题 ②）

- 设置行：radio 四选一 `系统 / 浅色 / 深色 / Midnight`〔截图通用页〕，defaults 键 `appearance`（值 raw ⬜：推断 `system/light/dark/midnight`，未从二进制解出字面值）。
- **Midnight 不是自定义 NSAppearance**：二进制 NSAppearance 符号引用仅有系统 `NSAppearanceNameAqua`/`DarkAqua`/`VibrantDark`（disasm 12 处，行 548389/715888/773555 等）；AppearanceManager 观察 `NSApp.effectiveAppearance`（函数 @0x10021a020：比较 cached name 与 Aqua/DarkAqua）。
- Midnight = 深色基底 + 主题覆盖层：SwiftUI 环境注入 `midnightBaseBackgroundOverride`（基础背景色覆盖）与 `usesMidnightTextColor`（文本用色开关）两反射字段（@0x100aebc80/@0x100aee2e0）→ 重建按「Color(UInt(midnight 色板)) + environment 覆盖」实现。
- **Pro 门控**：`midnight_appearance` 为 feature-flag/entitlement 键（键簇位于 Pro 键区 @0x100b4b8d0：unlock_available/trial_duration_seconds/com.frset.pro.lifetime/history_unlimited 相邻；flag 解析 switch @0x1002d1e00 case 4 → midnight_appearance）；lproj 有 'Try Midnight'（试用 Midnight 外观）→ 非 Pro 用户可选择试用。重建决策：Midnight 免费放开（无 Pro 体系），门控逻辑不移植。
- 生效范围：全窗（NSApp.effectiveAppearance + SwiftUI preferredColorScheme 双通道）〔⬜ 悬浮剪贴板/钉图等子窗是否跟随未逐窗验证〕。

## 6. 语言与 L10n 基建（探明问题 ③）

### 6.1 原作机制
- 22 .lproj（§3.4）；键面=英文；`language` 键存覆盖值（"auto"=跟随系统，其余为语言码）；`LanguageManager.overrideDisplayLanguage`；切换广播 `languageDidChange` 通知触发全 UI 刷新（不重启 App）〔通知观察点众多，机制为行为级推断〕。

### 6.2 重建方案（本轮只落基建 + 中文）
```
apps/FrsetNext/Sources/Core/L10n/
├── L10n.swift            // enum L10n { static func t(_ key: String) -> String }
│                         //   实现：Bundle(for:) 按当前覆盖语言取 .lproj/Localizable.strings
│                         //   缺失回退：键本身（英文句面）——与原作回退一致
├── LanguageManager.swift // @Published overrideDisplayLanguage: String
│                         //   defaults 键 "language"（对齐原作）；didSet 发
│                         //   Notification.Name("languageDidChange")（对齐原作通知名）
└── Localizable.strings   // zh-Hans 起步：从原作 zh-Hans.lproj 抽取设置域键（§3.4 键面）
```
- 键名规范：**沿用原作英文句面键**（对齐二进制锚点，保证文案逐字还原与跨模块一致）；代码内 `L10n.t("Advanced Settings")`。
- 22 语言其余 21 个翻译后补（specs/11 §4 铁律）；RTL（ar）预留 `isRightToLeft` 检查（flipsForRightToLeftLayoutDirection）。
- 语言下拉数据源：固定 23 项（Auto + 22 语言码），显示名用各语言自称（如 "日本語"）〔⬜ 原作下拉显示名来源未探明〕。

## 7. SettingsRouter 与辅助管理器（探明问题 ④）

### 7.1 路由
- `SettingsRoute`（enum，RawString）：`general / search / tools / shortcuts / about`（+`pro` 残留 case，UI 已不可达）；子路由 `aiProviders / toolSettings / customAITool / tagManagement`（反射串簇 @0x100afb240-0x100afb29e）。
- 页内跳转场景清单：
  1. 通用页「AI 服务商 → 管理」按钮 → `.aiProviders`（截图：管理按钮 + "1 个服务商"；lproj 'AI provider'）；
  2. 工具页工具行 → `.toolSettings`（时间戳/变量命名等工具设置，"Timestamp Settings"/"Variable Naming Settings"）；
  3. 工具页自定义 AI 工具 → `.customAITool`（`customAITools` 键簇 @0x100b4dbc1）;
  4. 通用页「标签管理 → 编辑」→ `.tagManagement`（TagManagementNameField 类名 @0x100ace000）；
  5. 快捷键页（由 Toolbox 模块供数据，见重建 SettingsModule 注记）。
- 实现：`@Published var route: SettingsRoute?` + 窗口内容 switch；子路由以 sheet/导航切换〔⬜ 原作切换动画/返回方式未逐帧验证〕。

### 7.2 辅助管理器
- `SettingsToastManager`：窗内 Toast 队列；成功样式 checkmark.circle.fill + 文案（Saved/Reset/Added/Deleted Successfully 四组，各伴随独立 CoordinateSpace 锚点 `SettingsInstantTooltipCoordinateSpace` @0x1004e9608 等——即"即时提示"吸附在被操作行附近）。
- `SettingsFocusSentinelNSView`：隐藏 NSView 哨兵，接住/归还焦点，防 SwiftUI TextField 焦点逃逸〔⬜ 具体焦点场景未逐点验证〕。
