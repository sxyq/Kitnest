# frset-rebuild — Frset 重建工程（Mini-Frset）

> 2026-10-14 创建。目标：用**正向 Swift 工程**重建 Frset 的核心体验 + 原生集成 Stats 监测，
> 终止"每个新功能都要逆向注入"的边际成本上升。
> 规格来源：`~/Desktop/Project/frset/`（完整逆向档案——报告/UI 截图/偏好键/补丁点/行为记录）。

## 这是什么

| | 轨道 A：原 Frset（借用） | 轨道 B：本工程（重建） |
|---|---|---|
| 定位 | 过渡与对账基准：补丁+注入版，功能完整、立即可用 | 未来主力：正向 Swift 工程，功能按优先级重建 |
| 维护方式 | 二进制补丁 + DYLD 注入（工具链成熟） | 普通 Xcode 工程（写代码 → 编译 → 运行） |
| 新功能成本 | 每个 = 逆向 + 注入 + 重签授权税 | 每个 = 普通开发 |
| 状态 | ✅ 可用（20 项防呆 + 全套维护脚本） | 🌱 骨架（本目录） |

## 核心原则

1. **规格书驱动**：每一处重建，先在 `specs/` 写清楚（来源=反汇编/截图/偏好键），再写代码；
2. **行为对照**：每个模块重建后，与原 App 同操作对账（`tests/` 清单化）；
3. **双轨并行**：轨道 A 不停止（保障日常可用），轨道 B 分模块蚕食；
4. **迁移优先**：能整体搬迁的不重写（如 M1 的监测 framework 两轨共享）；
5. **低频功能最后搬**（AI 服务商配置/工具箱全模块可延后甚至不搬）。
