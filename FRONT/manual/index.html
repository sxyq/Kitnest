快速上手

安装与启动

  1. 把 Kitnest.app 拖进「应用程序」文件夹，首次双击打开。
  2. 它是菜单栏应用：启动后不会出现主窗口，也不会在 Dock 显示图标，只在屏幕顶部菜单栏出现一个图标。
  3. 若系统提示「无法验证开发者」，到「系统设置 → 隐私与安全性」里点「仍要打开」。
  4. 退出：点菜单栏图标 →「退出 Kitnest」，或 ⌘Q。

首次启动会看到什么

  1. 欢迎窗：功能导览 + 快捷键速查（WelcomeWindowController）。
  2. 权限引导窗：四类权限的状态、用途、一键授权（PermissionGuideWindowController）。权限状态来自实际检测，不读取配置。
  3. 之后菜单栏图标右键 →「欢迎与权限…」可随时回看。

需要授权什么

权限用途不授予会怎样
屏幕录制截图、录屏、长截图、OCR、取色截图全黑或直接失败；应用会弹一次统一引导，不会反复骚扰
辅助功能全局快捷键、双击修饰键、划词工具条、复制后自动粘贴快捷键无响应；首次自动粘贴时弹一次引导
麦克风录屏时收麦克风声音（可选）自动降级为只录系统声音
日历主面板日历卡显示系统日程日历卡只显示日期，UI 内有「去授权」入口
完全磁盘访问存储管理索引 TCC 保护目录、文件搜索更全存储索引少约 33GB（沙盒容器），搜索少一块；界面上会明确标出「未获授权」
全部可在「系统设置 → 隐私与安全性」随时开关。

第一章 菜单栏与图标

功能是什么

菜单栏是 Kitnest 的总指挥部。主图标负责呼出主面板和功能菜单；图标右侧可以挂一排监控部件，实时显示系统数据；图标本身有四种样式。

用户怎么用

操作入口效果

第四章 剪贴板历史

功能是什么

自动记录复制过的文本、富文本、图片、文件和链接。支持搜索、类型筛选、标签、编辑、批量操作和暂停记录。默认保留 30 天，上限 2GB；两个数都能改。

用户怎么用

入口操作效果
⌥A / ⌥V打开面板首页剪贴板历史列表
⇧⌘V悬浮剪贴板鼠标旁迷你列表（第五章）
双击一条 / 回车回贴写回系统剪贴板
右键菜单置顶、标签、编辑、隔空投送、删除
⇧⌥R暂停/恢复记录处理敏感内容时用
底部工具条筛选 / 标签 / 编辑 / 上传批量与整理

演示

关键能力点

  • 自动记录 + 去重（ClipboardManager.pollTick / ingest）

轮询系统剪贴板，按内容指纹去重。重复复制同一条只更新位置和计数，不新增一行（ClipboardPasteboardReader.fingerprint）。

  • 多类型识别（ClipboardPasteboardReader）
  • 纯文本、富文本（RTF 保真存储）、图片（记尺寸）、文件（记路径）、URL、颜色值分别入库。
  • 富文本粘贴时保留原始格式，不转换为纯文本。
  • 来源应用：每条显示来源 App 图标（ClipboardAppIconCache）。隐私名单里的应用复制的内容不记录。
  • 类型筛选（ClipboardFilterKind）：全部 / 文本 / 图片 / 链接 / 文件 / 代码 / 颜色 / 工具生成 / 笔记。
  • 标签系统（TagStore）：建标签、改名、设颜色、给条目打标签；支持批量加/减标签（historyBatchTagAdd）。
  • 条目编辑（ClipboardItemEditWindowController）：改正文、设别名标题、写备注。
  • 图片自动 OCR：图片入库后自动调度识别，识别出的文字能被全局搜索命中（scheduleOCR）。所以「截图里的一句话」也能搜到。
  • 工具产出回流（ingestToolOutput）：截图 OCR 结果、AI 总结、小工具输出会以「工具生成」类型进历史，和手动复制区分开。
  • 清理策略（ClipboardPruneSchedulers.prune）：按条数 / 天数 / 体积三个维度自动清理，设置里可调。
  • 文件落盘：图片和大文件存在 ~/Library/Application Support/FrsetNext/ 下，数据库里只存相对路径（ClipboardFileStorages）。所以备份数据目录 = 备份全部内容。
  • NSTableView 骨架（ClipboardTableHostView）：列表采用 NSScrollView + NSTableView 而非 SwiftUI List，以保证多选、拖拽、行内编辑与长列表滚动性能。

注意事项

  • 默认关闭，开关在「设置 → 截图与钉图 → 图帘」。

  • 翻译失败会保留原文，不会吞掉识别结果。

第十七章 内存维护

功能是什么

内存详情页底部的「内存维护」区：一个按钮执行两项操作——清理缓存与暂停闲置应用。执行完成后提供分项对比报告，如实列出各项内存变化与未变项目。

用户怎么用

操作效果

注意「压缩 +497MB」：purge 将内存页挤出后，部分数据会转入压缩器。因此「释放量」并不等同于「空闲增加量」，报告将各分项单独列出，以便准确评估。

演示

关键能力点

  • 两档动作
  • 清缓存：malloc_zone_pressure_relief + 内存压力广播 + purge（需要 root helper）。
  • 暂停闲置：给符合条件的进程发 SIGSTOP，让它彻底不占 CPU；唤醒发 SIGCONT。
  • 暂停白名单（ProcessFreezer）

终端、IDE、虚拟机、会议软件、输入法与宿主进程不纳入冻结候选。

  • 「屏幕有窗口」和「5 分钟内激活过」的不冻：判断依据是进程有没有可见窗口、最近有没有交互，避免冻掉你正在用的东西。
  • 30 分钟自动解冻：暂停不是永久的，到点自己恢复。
  • watchdog 自愈：用 posix_spawn 起一个独立守护进程（不是 Process.run()，那个在 App 内会被吞错），App 崩了 5 秒内把冻结的进程全部 SIGCONT。
  • root helper：FrsetNextHelper 是一个 LaunchDaemon，装一次长期可用；没装时降级为「只清用户态缓存」。
  • 分项对比报告（MemoryOptimizer）

按「采样前 → 执行 → 采样后」分项对比。各项内存释放量单独统计呈现，不将转入压缩器的内存算作已完全释放。

注意事项

  • 冻结的进程不是被杀，是暂停：内存还在、窗口还在，点它一下会自动解冻。
  • 频繁点「深度释放」没有额外收益：第一次能吐出来的，第二次基本没有。
  • 内存压力升高时系统内核会自动回收页面，第三方工具的作用相对有限；该功能的核心在于提供主动清理入口并清晰展示内存前后变化，而非承诺绝对加速。

  • 截图完成后右下角不留任何浮窗；动作工具条在屏幕下方居中，点外部或 Esc 收起。
  • 仅文本马赛克首笔会有约 0.2 秒识别停顿；手写体、艺术字可能漏识别。

附录 F · 演示 GIF 怎么来的

演示素材全部来自本机真机录屏，包含 37 章一章一段，每段均配置了自动运镜算法，未采用静态示意图或手工拼帧。

两遍处理（参考 Screenize / OpenScreen 的实现思路）

遍做什么
第一遍screencapture -v -C 录屏（带光标），同时把每一次 move / click / drag / scroll / type 连同时间戳写成 *.json
第二遍按事件生成镜头段落，逐帧裁切放大，再叠点击涟漪与光标环，最后量化成 GIF

参考的三个开源项目：Screenize（syi0808，Apache-2.0，连续/分段两种相机 + 多轨时间线）、 OpenScreen（siddharthvaddem，MIT，点击驱动自动缩放 + 光标高亮）、 Recordly（跨平台，自动缩放 + 平滑光标 + 点击效果）。

与上述开源项目的区别在于：此处的鼠标光标完全由程序根据事件坐标合成，坐标与时间戳完全确定，无需借助 Vision 识别猜测 UI 元素，避免了镜头跟丢光标的情况。

事件推近说明
点击1.95×镜头停在点击处，直到下一个动作

问题原因处理
玻璃面板透出别的 App 文字、桌面小组件窗口是半透明材质录制时铺一块纯色渐变背景板（backdrop.swift），录完关掉

搜索框打字全丢键盘事件是全局 CGEvent，深链打开窗口并不保证 App 在前台开镜前显式 activate Kitnest

体积控制

手段效果

增量帧（透明索引）只贴变化像素
