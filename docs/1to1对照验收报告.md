## 4. 双开实测发现（planning 本人执行）

### 4.1 P0 崩溃（已修复并回归）

- **现象**：双开 3 分钟内崩溃两次（11:13:00 / 11:16:11），栈完全相同
- **栈**：`Timer(1s) → pollTick → poll → ingest → read → fingerprint → String.sha256`
- **根因**：Core/Support.swift 手写纯 Swift SHA-256 消息字被 `& 0xffffffff` 掩成 32 位；fingerprint 又先将头尾各 8KB 转十六进制串（输入膨胀至约 32KB），在每秒轮询热路径上按长度相关崩溃（间歇性）
- **修复**：改用 CommonCrypto CC_SHA256 + 指纹直接对字节流摘要；标准向量对照 shasum/hashlib 5/5 吻合
- **回归**：双开 + 剪贴板压力（4MB 图片数据 / 1MB 文本 / 500KB 单行 / 40 次高频写入）+ 40s 守候 → 零新增崩溃

### 4.2 争议裁决：贴图缩放上限（误引原作地址）

- 实现代理注释引 `0x1002f5a00` 作「8 倍上限」证据；审计代理 v-a 判为误引
- **实测反汇编裁决**：`0x1002f59e4 fmov d3,#1.0` / `0x1002f5a00 fcmp d2,d3` / `0x1002f5a04 fcsel d2,d3,d4,ls` —— 该处是**下限钳制**（宽高 ≥1.0 与 50pt），**原作无上限**
- **处置**：移除重建自加的 8 倍上限（PinWindow.swift），恢复原作无上限行为

## 10. 修复波次 A 收口记录

### 10.1 键盘预览取消的来源区分（条件性修复，已落）

**问题**：`:459` 的 `tableViewSelectionDidChange` 无条件 `cancelKeyboardPreview()`，使空格预览的
0.30s 延时 WorkItem 在任何选中变化下被取消（静默无日志）。

**修法**（执行代理按优先级 1 实现）：`keyDown` 的 default 分支（↑/↓/PageUp/PageDown/Home/End）同步置
`isKeyboardNavigating` 标记 → `selectionDidChange` 仅在标记为真时取消 → 末尾兜底复位。

**两个前提均经核实**（这决定了"限定后不改变任何现有行为"）：
1. 鼠标路径不依赖该回调——`MainPanelPreviewPopoverCoordinator.present()` **第一行即调
   `cancelKeyboardPreview()`**（`:164`），单击/双击在到达 `selectRowIndexes` 之前已取消未决预览；
2. `reloadData` 路径不经 `present()`，旧代码在此处的取消是「无对应补偿的误伤」。

**兜底复位是正确性前提**（非保险冗余）：末行按 ↓ / 首行按 ↑ 不产生选中变化 → `selectionDidChange` 不触发
→ 若不复位，标记会泄漏并把下一次**鼠标点击**误判为键盘导航。

**残留行为变化（team-lead 按 §11.2 第一问裁决：保留）**：`reloadData` 不再取消未决键盘预览。
- 原行为：预览被静默吞掉，无任何提示；
- 现行为：极窄窗口（0.30s 内恰好捕获新内容）内预览仍会弹出，锚点可能指向已被顶替的位置。
- **裁决依据**：差异服务于「用户按下空格的意图应被兑现」这一意图，方向是补缺而非偏离；
  且新行为的异常是"看得见的（锚点可能不准）"，旧行为的异常是"看不见的（什么都不发生）"。
  故**保留现行为，不加补偿**，并新增实测项 R13 兜底验证。
