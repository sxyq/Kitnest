## 4. 双开实测发现（planning 本人执行）

### 4.1 P0 崩溃（已修复并回归）

- **现象**：双开 3 分钟内崩溃两次（11:13:00 / 11:16:11），栈完全相同
- **栈**：`Timer(1s) → pollTick → poll → ingest → read → fingerprint → String.sha256`
- **根因**：Core/Support.swift 手写纯 Swift SHA-256 消息字被 `& 0xffffffff` 掩成 32 位；fingerprint 又先将头尾各 8KB 转十六进制串（输入膨胀至约 32KB），在每秒轮询热路径上按长度相关崩溃（间歇性）
- **修复**：改用 CommonCrypto CC_SHA256 + 指纹直接对字节流摘要；标准向量对照 shasum/hashlib 5/5 吻合
- **回归**：双开 + 剪贴板压力（4MB 图片数据 / 1MB 文本 / 500KB 单行 / 40 次高频写入）+ 40s 守候 → 零新增崩溃

### 4.2 争议裁决：贴图缩放上限（误引原作地址）

- 实现代理注释引 `0x1002f5a00` 作「8 倍上限」证据；审计代理 v-a 判为误引
- **实测反汇编裁决**：`0x1002f59e4 fmov d3,#1.0` / `0x1002f5a00 fcmp d2,d3` / `0x1002f5a04 fcsel d2,d3,d4,ls` —— 该处是**下限钳制**（宽高 ≥1.0 与 50pt），**原作无上限**
- **处置**：移除重建自加的 8 倍上限（PinWindow.swift），恢复原作无上限行为
