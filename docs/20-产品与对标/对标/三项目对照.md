## 二、图2 · omdrop-owl（空投互传）——已接入 ✅

**它是什么**：开发者 @t4t5 完全逆向 AirDrop 协议，开源 `omdrop-owl`。基于 OWL 框架的**用户态 AWDL 无线后端**，
即使在联发科 Wi-Fi 芯片的非苹果 Linux 笔记本上，也能与 iPhone 无缝双向互传，**且完全不干扰正在连接的 Wi-Fi**。

**FrsetNext 接入情况**（v112 已落地）：
| 能力 | 状态 | 代码坐标 |
|---|---|---|
| →iPhone（空投发送） | ✅ | `TransferDockService` 空投通道 |
| ←iPhone（空投接收） | ✅ | Downloads 监听入库 |
| 零安装（手机侧无需装 App） | ✅ | 协议级兼容 |
| 不干扰现有 Wi-Fi | ✅ | AWDL 与 STA 并存 |

**结论**：图2 的核心价值（iPhone 零安装互传 + 不断网）**已完整接入**，无需重复实施。

## 三、图3 · AndroMeld（Android↔Mac 融合）——部分接入 ⚠️

**它是什么**：「手机上的事，Mac 上接着做」——回消息、传照片、接电话、复制粘贴。闭源商业，¥88 买断。

**14 项能力接入明细**：

| # | 功能 | 状态 | 说明 |
|---|---|---|---|
| ① 屏幕镜像 | ✅ | `ScreenCastEngine.startMirror()`（scrcpy，分辨率/码率可配） |
| ② Meld Mode（每 App 独立窗口） | ❌ | 需虚拟显示 + 窗口合成，工程量大 |
| ③ Finder 集成（存储进侧栏） | ❌ | 需 Finder Sync 扩展（**构建系统限制不可行**） |
| ④ 通知同步 | ❌ | 需手机 NotificationListener 或 `dumpsys` 轮询 |
| ⑤ 双向剪贴板 | 🟡 半 | scrcpy 默认开 autosync，**未显式传参/未在 UI 明示** |
| ⑥ 电话 | ❌ | 通话状态/控制桥 |
| ⑦ 输入法 | ✅ | scrcpy 镜像已附带（Mac 键盘打字到手机） |
| ⑧ 摄像头 | ❌ | 虚拟摄像头设备（系统插件） |
| ⑨ 手势 | 🟡 半 | scrcpy 基础触摸；触控板手势映射需自研 |
| ⑩ 部件（App Widget） | ❌ | Widget 桥 |
| ⑪ 存储视图 | ❌ | `adb shell df` 可做，轻量 |
| ⑫ APK 安装 | ❌ | `adb install-multiple` + 权限预检 |
| ⑬ MCP 服务器 | ❌ | 与 FrsetNext 的 AI 体系天然契合 |
| ⑭ 远程（FCM+WebRTC） | ❌ | 重度且依赖外部服务，不建议 |

**本轮要接的 P0（成本低价值高）**：
1. **无线配对 UI**（`adb pair` + `adb connect` + mDNS 发现）——无线是日常主路径，当前缺入口
2. **剪贴板显式化**（传 `--clipboard-autosync`，UI 明示）——半接入转正

## 四、图1 · Agent HUD（刘海 HUD）——未接入，本轮接入

**它是什么**（`jazzenchen/agent-hud-open`，Apache-2.0，**Swift 原生**，148★）：
在 Mac 刘海屏上显示 AI Agent 的用量/状态/会话。**支持 17 个 agent**（Claude Code、Codex 最全）。

**核心能力**：
| 能力 | 说明 | FrsetNext 对应 |
|---|---|---|
| **刘海 HUD** | 显示额度/用量/会话，简约/动态模式，可拖到屏幕边缘 | FrsetNext 状态栏（非刘海），可扩展 |
| **批准/提问拦截** | agent 要批准时请求停在 HUD（含命令 + 文件 diff），点允许/拒绝 | ❌ 无 |
| **新回复提醒** | 一轮跑完提醒，点击回到会话（终端/iTerm2 分屏/Codex 线程） | ❌ 无 |
| **Token 统计** | 按时间/agent/模型/会话/每轮拆分，按 API 价折算 | 🟡 FrsetNext 有 AI 模块但无用量统计 |
| **额度告警** | 90% 或撑不到重置时提醒 | ❌ 无 |
| **数据源** | 读 agent 本地记录 + 账号 API；写 hook 到 agent 设置 | ❌ 无 |
| **隐私** | 不发消息给模型、不存凭据、源码构建不上传 | — |

**接入方案（FrsetNext 形态适配）**：
- **形态差异**：Agent HUD 是独立 App + 刘海屏；FrsetNext 是**菜单栏工具**。接入应做**菜单栏 agent 状态项**而非刘海。
- **可接的能力**（按价值排序）：
  1. **Agent 用量监控**（P1）：读 `~/.claude/`、`~/.codex/` 等本地记录，在 FrsetNext 状态栏/面板显示
  2. **额度告警**（P1）：90% 阈值 Toast + 菜单栏徽标
  3. **批准/提问拦截**（P2）：hook 到 agent 设置，弹通知 + 快速允许/拒绝
  4. **Token 统计**（P2）：按 agent/模型/会话统计
- **不做**：刘海 HUD（形态不符）、手机/手表端（需另做 App）、MCP（与自家 AI 体系重叠时再说）

## 五、Snow Shot 差距分析（用户重点）

**Snow Shot**（`hnztlyh/snow-shot-`，注意尾连字符是仓库名一部分）：Rust + Tauri，跨平台截图工具。

### 5.1 我们反超的（无需做）

| 能力 | Snow Shot | FrsetNext |
|---|---|---|
| 标注工具 | 5 种（矩形/圆/箭头/文字/马赛克） | **9 种**（+画笔/荧光/橡皮/**AI 抹除**） |
| 截图模式 | 4-5 种 | **7 种**（+OCR/钉图/取色/长截图） |
| OCR | 插件 | ✅ 内置（免插件） |
| 翻译 | 插件 | ✅ 内置（截图翻译 + 划词翻译） |
| 录屏 | 插件 | ✅ 内置（区域/设置/计时/GIF） |
| 保存方式 | 3 种 | **6 种**（+空投/入库剪贴板/上传中转） |

### 5.2 ❌ 我们缺的（**本轮要接**）

| # | Snow Shot 能力 | 说明 | 实施方案 | 优先级 |
|---|---|---|---|---|
| 1 | **智能窗口/元素识别吸附** | 框选时自动识别元素边界，吸附高亮 | `AXUIElementCopyElementAtPosition` + 遍历子元素取 frame，悬停吸附 + 描边高亮 | **P0** |
| 2 | **截图历史** | 记录每次截图，可搜索、继续未完成的标注 | SQLite 表（`capture_history`）+ 历史窗（缩略图网格 + 搜索 + 双击继续编辑） | **P0** |
| 3 | **十字准星 + 实时尺寸** | 框选时十字准星辅助定位 + 实时显示宽高 | 区域框选 overlay 加十字线 + 尺寸气泡 | **P0** |
| 4 | **延时截图** | N 秒后截图 | `CaptureMode.delayed` + 倒计时 HUD | P1 |
| 5 | **二维码识别** | 截图内二维码解析 | Vision `VNDetectBarcodesRequest` | P1 |
| 6 | **颜色拾取增强** | 取色后显示色值 + 复制格式（HEX/RGB/HSB） | 现有 Eyedropper 加色值面板 | P1 |
| 7 | **标注图层管理** | 标注对象可分层/排序/锁定 | 标注编辑器加图层面板 | P2 |
| 8 | **毛玻璃模糊** | 除马赛克外的毛玻璃效果 | 标注工具加 `.glassBlur`（CIFilter） | P2 |
| 9 | **主题配色自定义** | 用户自定义主题色 | Settings 加主题色选择器 | P2 |
| 10 | **OCR 表格/数学公式** | 结构化表格 + 公式识别 | Vision 表格检测 + LaTeX 转换 | P2 |
| 11 | **插件系统** | 核心轻量 + 插件装载 | **不做**（架构取向不同，见 §5.3） | ❌ |
| 12 | **自动更新** | Sparkle 类 | P2（需签名/更新服务器） | P2 |

### 5.3 插件系统为什么不做

Snow Shot 插件化是为「跨平台 + 社区生态」；FrsetNext 是**单体 Swift 工程 + 内部 Registry**
（面板区段/设置页/状态项三级注册表），已满足「功能模块化」。做用户级插件沙箱的安全/签名/维护成本远超收益。
**替代**：继续按 Registry 规范模块化（AI 对话/翻译等已如此）。
