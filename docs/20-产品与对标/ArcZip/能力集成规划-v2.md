### P1 · 正确性（5 项）

#### ⑤ UC-25 写后校验与回滚（**最高优先级的技术债**）

- **现状**：`updateEntry` 直接 `7zz a -y` 覆盖；失败时用户可能拿到半个包（无 `.bak`，因为你先前明确要求不产生备份文件）。
- **要做什么**：不引入备份文件，改用**轻量校验 + 可重放**：
  1. 写前记录 `(条目数, 路径集合哈希, 归档大小)`；
  2. 写后 `list` 重新列举，比对三项；
  3. 不一致 → 用 staging 里的原文件重放一次（staging 在写期间本就在）；
  4. 仍失败 → 弹「写入未通过校验」并给出 staging 路径供手动恢复。
- **改动**：`ArchiveCore.updateEntry / addFiles / removeEntries` 统一走一个 `performWrite(_ changes:)` 包装（约 120 行）；`ArchiveTaskQueue` 的 message 增加「校验中…」阶段。
- **验收**：注入失败（临时改坏 staging）→ 条目数不符能被检出并重放；正常路径无额外文件残留。

#### ⑥ UC-14 同名冲突策略

- **现状**：`7zz -y` 一律覆盖。
- **要做什么**：解压前探测目标是否已存在；存在则按设置（合并编号 / 同时保留 / 覆盖 / 跳过）。「同时保留」= 新建 `名字 2` 文件夹。
- **改动**：`ArchiveCore.extract` 增加 `conflict:` 参数（默认 `.ask`）；`ArchiveBrowserModel` 与 `ArchiveServicesProvider` 两处调用点接上；设置页给默认值。
- **验收**：目标已有同名文件 → 四种策略各跑一遍，文件数/命名正确。

#### ⑦ UC-15 解压后处理原包

- **要做什么**：解压完成后按设置「每次询问 / 始终保留 / 移入废纸篓」。
- **改动**：`ArchiveCore.extract` 完成回调处（约 20 行）+ `FileManager.trashItem`；设置页开关。
- **注意**：批量服务（NSServices）场景**默认保留**，别把用户右键解压的包丢了。
- **验收**：三种策略各一次；废纸篓里能找到。

#### ⑧ UC-27 合并到最新版

- **要做什么**：写回前比对 `(size, mtime)` 指纹；变了则三类冲突检测（他人已改 / 已删 / 已新增同名），冲突时停止保存并提示「重新载入」；无冲突则合并写入。
- **改动**：新增 `ArchiveMergeGuard.swift`（约 140 行）；`ArchiveBrowserModel.saveDraft` 前置调用。
- **验收**：外部 `touch` 改包 → 保存被拦；无冲突时保存成功。
- **注意**：这条 ArcZip 原版也标「价值中」，若 P1 排期紧可降到 P2。

**只改不新增**：`ArchiveBrowserWindow`（检查器/悬停/空格/框选）、`ArchiveCore`（CRC 字段、冲突参数、写后校验、后处理）、`ArchiveEntryTable`（框选）、`Info.plist`（文档类型）、`SettingsSidebarView`/`SettingsRootView`（注册 1 个 case）、`Database.swift`（删商业事件）。

### 4.2 索引：建议做，但独立库

- **为什么需要**：现在每次打开都 `7zz l -slt` 全量解析。1 GB / 5 万条目的包，列举本身就要数秒，而搜索/预览/拖出都依赖条目表。
- **怎么做**：`~/Library/Application Support/FrsetNext/archive-index.db`（**独立文件**，不混统计库），表 `archive(path PK, size, mtime, built_at)` + `entry(archive_path, entry_path, size, packed, crc, method, encrypted, kind)`。
- **失效策略**：`(size, mtime)` 变了即删该包的索引重建。
- **收益**：二次打开毫秒级；顺带让「最近打开」可以显示条目数。
- **风险**：多一个需要维护的缓存层。**若不做，P0 的检查器与空格预览也能工作**（只是大包慢）。建议放 P2。

### 4.3 依赖方向（遵守项目既有的跨模块纪律）

```
Features/Archive  ──►  Storage(Database)  ✅ 允许（读统计无关）
                  ──►  Core(Theme/Toast)  ✅ 允许
Features/Settings ──►  Features/Archive   ⚠️ 只允许注册点，不引用具体 View
Features/Archive  ──►  Features/Settings  ❌ 禁止
```

设置页放在 `Features/Archive/` 内，Settings 侧只留 `case .archive: ArchiveSettingsPane()` 一行 —— 避免 Settings ↔ Archive 双向依赖（项目里已有类似纪律：Settings 不引用 StatusBar 具体类型）。

## 五、分期与依赖

```
P0 清理 ──► P0 补齐（4 项）──► P1 正确性（5 项）──► P2 形态（4 项）──► P3 收尾（3 项）
   │                              │
   │                              └─ ⑤ 写后校验是其它写操作的前置（改了就都受益）
   └─ Info.plist 文档类型要先做，否则「设为默认」无对象
```

| 期 | 内容 | 项数 | 完成标志 |
|---|---|---:|---|
| **P0-a** | 删商业事件 12 个 + 更新过期统计文档 | 2 | `grep paywall` 为 0；文档标注 v127 |
| **P0-b** | 检查器 / 最近打开 / 空格预览 / 格式关联 | 4 | 四项各有一条深链或截图验收 |
| **P1** | 写后校验 / 冲突策略 / 后处理 / 合并最新版 / 路径安全补强 | 5 | 注入失败能被检出；四种冲突策略各跑通 |
| **P2** | 框选 / 悬停 / 设置页 / 错误详情（+ 索引可选） | 4~5 | 设置页改项即时生效；三种错误出详情 |
| **P3** | 引导（可不做）/ 临时清理 / 文件盒补全 | 3 | 临时占用可见并可清 |

**建议的推进顺序**：P0-a → P0-b ④（plist，10 分钟）→ ①（检查器，用户感知最强）→ ③（空格预览）→ ②（最近打开）→ P1 ⑤ → 其余。

## 六、验收与回归

沿用项目既有手段，不新建体系：

| 手段 | 用途 |
|---|---|
| `./build.sh` | 编译（约 3 分钟）；新增文件自动纳入 |
| `./check.sh` | 契约检查（含耦合检查） |
| `apps/FrsetNext/tools/ui_lint.py` | UI 常量/依赖方向回归 —— 新增文件后必跑 |
| 深链 `frsetnext://archive?path=…&action=inspect` | 免点击直达新面板（建议为检查器/最近打开各加一个 action） |
| `screencapture -l<窗id>` | UI 截图对照 |
| 手工用例 | 每项 2–4 条，写进 commit message |

**每次改动必须**：构建 → 验证 → commit（写需求原话 + 文件 + 数值）→ 重打 DMG → 重启 App。

## 七、风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 22 个 lproj | 新增文案要写 22 份 | 只维护 `en` + `zh-Hans`，其余靠回落；一次性文案（错误详情）优先英文键 |
| 7zz `-y` 语义 | 冲突策略与写后校验都要改调用点 | 先收敛到一个 `performWrite`，再改语义，避免 5 处各改一遍 |
| 无 `.bak` 备份 | 写坏无法回退 | 用「staging 重放 + 校验」代替；另在设置页提供「保存副本」手动逃生口 |
| macOS 13 下限 | 不能用新 API | 悬停/检查器全用 AppKit 稳定 API；Mini 的 Liquid Glass 不做 |
| 索引一致性 | 缓存脏了会显示错条目 | `(size, mtime)` 双字段校验 + 打开时后台重建 |
| Foldspace 形态冲突 | 硬搬会破坏面板设计 | 明确不做，只保留 Flow 动作层 |

## 八、需要你拍板的三件事

1. **索引做不做？**
   做：大包二次打开毫秒级，但要维护一个 SQLite 缓存（P2，约 150 行 + 失效逻辑）。
   不做：P0 四项照常可用，只是 1 GB 以上的包打开慢。

2. **写回要不要留「另存副本」逃生口？**
   你先前明确要求「原地覆盖、不产生 `.bak`」。我建议保留一个**手动**入口（工具栏「另存副本…」），
   默认不生成任何额外文件 —— 既不违背原意，又给误操作一条退路。

3. **设置页放哪？**
   A. `Features/Archive/ArchiveSettingsPane.swift`（推荐：不动 Settings 的依赖方向，只加注册点）
   B. `Features/Settings/`（集中，但 Settings 会依赖 Archive 的具体 View）
