## 10. 审计方法论铁律（2026-10-15 1:1 对照验收轮追加）

> 来源：本轮 44 项双侧举证审计 + 双开实测 + 反汇编裁决中付出代价换来的五条。每条都对应一次真实的误判或缺陷。

### 10.1 视图/对象反查：先验证「来源能否拿到目标」，再验证取值逻辑

读取形如 `table.subviews.first { $0.frame.intersects(r) } as? RowHostingView` 的代码时，
**光验证边界检查、frame 相交、判空是不够的**——必须先问：这个来源本身能不能拿到目标对象？

本轮真实案例：view-based NSTableView（`tableView(_:viewFor:row:)` 而非 `cellFor`）会把 delegate 返回的视图
包进 `NSTableRowView`，`table.subviews` 的直接子元素是 NSTableRowView，该强转**恒为 nil**。
后果：hover 高亮从未亮过、单击预览贴在面板左上角而非被点行、键盘预览锚点为 nil——三条链路同时哑，
而审计代理据此签发的 ✅ 是错的（已撤回）。

**规则**：凡涉及 `subviews` / `superview` 链 / `hitTest` / `rowView(at:)` / `cellView(at:)` 等反查，
必须先确认 ①容器的数据源模式（view-based vs cell-based）②视图的实际包装层级。
数据源模式的差异就写在方法签名里（`viewFor` vs `cellFor`），不能忽略。

### 10.2 事件归属三查：谁是第一响应者 / 谁收得到鼠标移动 / 局部监视器通路是否成立

本轮三个缺陷同属「事件与视图归属」这一类，且都通过了静态阅读：

1. **first responder**：行视图 `acceptsFirstMouse = true` 会抢走键盘归属，即使 `selectedRow` 已成立，
   表格也收不到空格/↩。规则：凡依赖键盘的交互，必须同时确认「选中态成立」与「目标视图是 first responder」两个独立条件。
2. **acceptsMouseMovedEvents**：面板窗未设该属性时，`addLocalMonitorForEvents(.mouseMoved)` 收不到事件，
   导致「关闭预览后须移动鼠标才复弹」的抑制永久无法解除。规则：凡依赖本地事件监视器的逻辑，
   必须确认宿主窗口开启了对应接收开关（原作贴图窗有 `acceptsMouseMovedEvents=true` 的实证）。
3. **SwiftUI 焦点仲裁**：`TextField` 获得焦点后可能持续持有 first responder，NSView 侧显式
   `makeFirstResponder` 是必要的反向夺权。规则：跨 SwiftUI/NSView 边界的键盘通路必须真机验证焦点归属。

### 10.3 字面量级事实必须字符级比对，不靠"看起来对"

11 个搜索引擎 URL、10 组热键的键码与 Carbon 掩码、59 个埋点事件名——这类事实的正确性只有逐字符比对能证明。
本轮 3/3 全对（引擎 URL 字符级一致、热键键码全对、53 枚举全覆盖），是最廉价的高价值验证。

### 10.4 引用原作地址前必须回读反汇编确认语义（禁止"顺手引一下"`

本轮出现一处误引：实现代理把 `0x1002f5a00` 注为「8 倍缩放上限」证据，审计代理判为误引。
实测反汇编该处为 `fmov d3,#1.0` / `fcmp d2,d3` / `fcsel d2,d3,d4,ls`——是**下限钳制**，原作根本没有上限。
误引导致重建凭空多了一条用户可感知的约束（无法放大超过 8 倍）。

**规则**：任何写入注释的「原作地址 = 某语义」都必须回读该地址附近的指令确认；
相邻地址语义相似时尤其危险（钳制 vs 限幅、比较 vs 传送）。

### 10.5 审计结论不得预支：代码修好 ≠ 判定 ✅

静态审计能证明「接线正确」，不能证明「运行时表现正确」。
本轮 PV-1/PV-2/PV-3/PV-4 在代码修复后静态接线均已验完，但 hover 是否真亮、popover 是否真贴行、
空格是否真能弹预览，必须真机确认才能改判。审计代理明确拒绝预支 ✅，这是正确姿态。

**规则**：判定表中的 ✅ 只能由「静态证据 + 运行时验证」共同支撑；仅有静态证据时最多标 ⚠️（待实测）。
