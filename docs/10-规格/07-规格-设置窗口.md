### 4.3 2026-10-16 根治：设置窗布局死循环崩溃（防回归，勿改回）

**现象**：首次真正打开设置窗即 SIGABRT，`NSGenericException`：
> The window has been marked as needing another Update Constraints in Window pass, but it has already had more Update Constraints in Window passes than there are views in the window.

崩溃时窗口 frame 实测被撑到 **800×1554pt**（内容自然高），触发 AppKit「更新次数超过视图数」保护。

**根因**（`/tmp/minirepro` 五组对照实验定位）：
1. SwiftUI App lifecycle（`@main` + `Settings` scene）下 `NSHostingView` 把**根视图 fitting size 折成窗口尺寸请求**（`updateWindowContentSizeExtremaIfNecessary` → `setNeedsUpdate` → `NSWindow._postWindowNeedsUpdateConstraints`）；
2. 根视图原为 `.frame(width: 800) + .frame(maxHeight: .infinity)`（高度自由，ScrollView 内容决定 ≈1554pt），窗口被反复请求撑到内容高，与固定尺寸冲突 → 无限 Update Constraints 循环 → 异常；
3. 与视图内容无关（最小视图同样复现）、与 Apple Event 上下文无关、NSPanel 同样复现、`sizingOptions=[]` 不能阻止。

**修复**（三处，缺一不可）：
1. `SettingsRootView` 根视图固定 `.frame(width: 800, height: 530)`（530 = 整窗 562 − 标题栏 32），各页内部滚动由 ScrollView 承担；
2. `StatisticsRootView` 同步（同模式同险）；
3. `SettingsWindowController` / `StatisticsWindowController`：contentRect/min/max 固定 800×530；移除 `setFrameAutosaveName`（原版窗口不可 resize，无尺寸记忆需求；autosave 还会在 cycle 内用旧帧覆盖目标尺寸）。

**同类历史**：2026-10-16 00:03 崩溃（`_persistFrame → 偏好通知 → MenuBarIconStyleApplier → 按钮布局`）机制同族（display cycle 内次级约束更新）；applier「仅真实变化时应用」修复继续有效。
