## 1. 实测结论（原版自带的截图能力）

原版 App **原生具备完整截图工具链**（二进制类名实证，非注入层实现）：

| 能力 | 原版类名 / 证据 |
|---|---|
| 长截图采帧 | `LongScreenshotCoordinator` / `LongScreenshotCaptureStream` / `LongScreenshotCaptureConfiguration` / `LongScreenshotCaptureState` / `LongScreenshotCaptureError` |
| 长截图编辑器 | `LongScreenshotEditorWindowController` / `LongScreenshotImageScrollView` |
| 截图放大镜 | `ScreenshotMagnifierContainerView` / `ColorPickerMagnifierView` |
| OCR | `ScreenshotOCRResultWindow` / `ClipboardOCRTask` / `ClipboardOCRTemporaryText` |
| 贴图 | `PinnedScreenshot*` / `FloatingClipboardPinState` |
| 标注 | `ScreenshotBrushCursorConfiguration` / `ScreenshotCapturePreparation` / `ScreenshotCompletionBehavior` |
| 文案 | `Screenshot and Copy` / `Screenshot and Pin` / `Screenshot copied` |

**即：选区截图、窗口截图、整屏、长截图、贴图（Pin）、截图编辑器、OCR、取色全部是原版自带的。**
（与 stats-recon/性能监测总文档.md 附2 结论一致；发布说明里亦有"优化截图性能，提升长截图拼接效果"。）

## 2. 调用方式实测（怎么触发）

### 2.1 快捷键（权威来源：`~/Library/Application Support/Frset/settings.json` → `shortcuts.bindings`）

| 动作 | 键码 | 修饰键 | 组合 | 当前状态 |
|---|---|---|---|---|
| openFrset | 0 (A) | 2048 (⌥) | ⌥A | 启用 |
| openAndSearch | 3 (F) | 2048 (⌥) | ⌥F | 启用 |
| floatingClipboard | 9 (F) | 768 (⇧⌘) | ⇧⌘F | **已停用** |
| screenshot | 18 (1) | 256 (⌘) | ⌘1 | **已停用** |
| screenshotCopy | 18 (1) | 256 (⌘) | ⌘1 | 启用 |
| screenshotOCR | 19 (2) | 256 (⌘) | ⌘2 | 启用 |
| screenshotPin | 35 (P) | 2560 (⌥⇧) | ⌥⇧P | **已停用** |
| screenshotTranslate | 17 (T) | 2560 (⌥⇧) | ⌥⇧T | 启用 |
| translateSelection | 2 (D) | 2560 (⌥⇧) | ⌥⇧D | 启用 |
| colorPicker | 8 (C) | 2048 (⌥) | ⌥C | 启用 |

- `preferredModes`：screenshot / openFrset = `combination`（组合键直接触发，无双击模式）。
- 与设置页实拍逐行一致（原截图未入库）：⌥A / ⌥F / ⌘2 / ⌘1 / ⌥C / ⌥⇧T / ⌥⇧D；截图、截图并贴图、悬浮剪贴板显示"无"（停用）。
- 注意：⌘1/⌘2 是**用户当前组合**，不是出厂默认；恢复默认后组合会变（设置页有"恢复默认快捷键"）。

### 2.2 UI 入口

- **主面板顶部工具条**：截图相关图标（viewfinder 等）+ 编辑 + 窗口图标，右侧 ⤢ / ▭ 图标（长截图 / 区域截图入口，见性能监测总文档 附4）。
- **截图工具自身 UI**：触发后全屏覆盖层出现（选区 / 模式选择 / 放大镜），长截图采帧中显示进度，收尾后进编辑器窗（`LongScreenshotEditorWindowController`）。

### 2.3 触发链路（调用情况）

```
入口（快捷键 ⌘1/⌘2/⌥⇧P/⌥C 或面板图标）
  → 原版全局热键分发（shortcuts.bindings → preferredModes=combination）
  → ScreenshotCapturePreparation（权限/配置）
  → 覆盖层选区（ScreenshotMagnifierContainerView 放大镜）
  → 抓帧（ScreenCaptureKit，原版技术栈）
  → 长截图：LongScreenshotCoordinator（55ms 去抖/恒等帧丢弃/<15 行不追加/
     动态搜索 min(24+4|δ|s,64)/三次失败终止）→ LongScreenshotCaptureStream 采帧
  → LongScreenshotEditorWindowController 编辑器（标注/保存/复制/Pin）
```

4. **文案约束**：任何入口/日志/设置文案**不得出现"App 自带"字样**（注入版 v117 已因该字样

## 5. 落地结果（2026-10-17 晚）

按逆向版 v124 收官状态落地（见 `docs/90-历史归档/接手清单-剩余工作.md` R7/G3）：

- **入口形态**：主面板工具条「截图」改为**功能菜单**——截图 / 截图并复制 / 截图并贴图 /
  截图提取文字 / 长截图 +（分隔线）截图翻译 / 划词翻译。命名与顺序对齐原版文案，
  **全文案无"App 自带"字样**。
- **实现归属**：重建版不存在"另一个 App"可调起，长截图与截图链路即 docs/10-规格/15 按原版
  `LongScreenshot*` 语义移植的**原版能力等价物**（不自研第二套、不重复实现）；
  菜单动作直接调 `CaptureModule` 公开 API，不经热键（用户改绑定不影响菜单）。
- **翻译两项**：`CaptureModule` 发通知 → `AppBootstrap` 会话（与热键同一实现），
  需配置 AI/翻译服务后生效。
- **录屏**：原版无此能力（`截图功能对照与整理清单.md` §1.3 结论），重建版不设该项。
- **验证**：菜单展开截图逐项核对（`/tmp/menu_open_crop.png`），构建通过。
