## 0. 本轮方法论增量（对 02 号的修正，重要）

1. **chained-fixup 指针双格式**：
   - 结构指针（class_ro / methodlist / ivars）：`VA = ((raw & 0xFFFFFFFFF) & ~0x3) | 0x100000000`（低 2 位是对齐标志，须掩掉）；
   - 字符串指针（selrefs→methname 等）：`VA = (raw & 0xFFFFFFFFF) | 0x100000000`（低 2 位是真实地址位，**不可掩**）。
   - 识别特征：raw 高 32 位 `0x0040_0000` 型多见于结构指针，`0x0010_0000` 型多见于字符串指针。
2. **`__objc_classrefs` 前段槽是外部 bind**（Sentry/Swift 协议 conformance 等，ordinal 顺序编码 `0x8010_0000_0000_ordinal`）；**本 App 自有类的引用是 adrp+add 直指 classobj**，不走 GOT。otool 的 `Objc class ref: bad class ref` 注记多为 Swift conformance/metadata GOT，**不可当类引用信**。
3. **`__objc_stubs` 段可整体解码**（每项 16 字节：`adrp x1, selref_page; ldr x1, [x1, #off]; adrp x16, got; ldr x16; br x16`）——直接给出 `objc_msgSend$selector` 的 selector 名，是读 AppKit 调用序列的最快路径（本轮实证：show 函数全部窗口配置调用由此还原）。
4. **Swift 类定位新路径（比 typeref xref 可靠）**：`__swift5_types`(0x100b1e3a0) rel32 → ContextDescriptor；descriptor+8 rel32 = mangled 名，+12 = 元数据访问函数 accessFn，+16 = fieldDescriptor。**accessFn 地址即该类编译器函数簇锚点**；fieldDescriptor（头 16B + 每字段 16B 记录：flags/typeRel/nameRel/declRel）直接给出全部存储属性名——本轮凭此拿到 MenuBarToastManager(4 字段)/EasterEggManager(22 字段)/StatusBarController(36 字段) 完整字段表。
5. **本机原作 bundle 的 Localizable.strings（zh-Hans）可用**：`plutil -convert json` 后按 key 对照，是触发场景文案的最强证据源。

**定位算法**（0x1002bda4c-0x1002bdb7c，纯汇编逐条）：
1. 基准矩形 = 0x1002bf3d0(self) 返回对象的 `visibleFrame`（v10-v13 保存），辅助取其 `frame` 的高度；
2. 常量集：`26.0`（菜单栏厚度）、`18.0`、`-18.0`、`-0.5`、`10.0`、`-10.0`、高度系数 `0.18330`（`0x3fc7765ab891fcdf`，fmul 于 frame.height）；
3. **水平**：理想 x = midX - toastWidth/2（**以基准矩形中线居中**，即对准状态项图标）；clamp 到 `[minX-26+18, maxX-toastWidth-18+26]` = `[minX-8, maxX-toastWidth+8]`；
4. **垂直**：落在菜单栏正下方的窄带内：下界 `minY-26+10 = minY-16`，上界 `maxY - height×0.1833 - 10 + 26`；最终 `setFrameOrigin:`（0x1002bdb7c→0x100951bc0）。
5. 内容高度常量 **32.0f**（`ldr d0, [0x100964d80]`，f32=32.0，传入隐藏块上下文）。

结论：**通知条是一条出现在主状态项图标正下方、随图标水平居中（±8pt 边距防溢出）、高度约 32pt 的浮层**；窗口 borderless + 透明背景 + 无阴影 + level 14 + 不接受鼠标事件。 appearance 跟随系统（`AppleInterfaceStyle` 读取 @0x1002bd928，Aqua/DarkAqua 分支 @0x1002bd9c4/0x1002be048）。

⚠️ 未完全探明：`0x1002bf3d0` 返回对象是"状态项按钮所在屏"还是"按钮窗口"（两者 visibleFrame 几何接近，不影响骨架实现）；level=14 非标准 NSWindow.Level 枚举名。

        hideWorkItem?.cancel()
        ensureWindow()                                  // borderless/clearColor/opaque:false/

                self.animationState.isVisible = false
            }
        }
        hideWorkItem = item
        DispatchQueue.main.asyncAfter(deadline: .now() + 3.0, execute: item)
    }

## 13. 定位勘误（2026-10-18，双重复核：反汇编 + 官方原版实机实测）

§3 的定位结论「随状态项图标水平居中、贴菜单栏正下方」**是错的**，当年对两处关键证据误读：

1. **基准矩形来源 0x1002bf3d0**（§3 遗留的 ⚠️ 未探明项）实测语义 =「目标屏解析」：
   传入对象非空直接用 → 全局单例(0x100d3be40)窗口字段的 `.screen` → 遍历 `NSScreen.screens`
   找包含 `NSEvent.mouseLocation` 的屏 → `mainScreen`。**全程与状态项图标无关**。
   关键 selector 已解码实证：0x10094fa60=`screen`、0x10094fa80=`screens`、0x10094d420=`mouseLocation`、
   0x10094cda0=`mainScreen`、0x1009567c0=`visibleFrame`、0x100949580=`frame`、0x100951bc0=`setFrameOrigin:`。
2. **show 的参数 x22 = x4**（0x1002bd058 `mov x22, x4`），复制场景调用点 0x1000f8070 处
   `mov x4, #0x0`（nil）→ 走上述回落链。§4 表中所有调用点同此。

**定位真值**（0x1002bda4c-0x1002bdb7c 逐条 + 实机 CGWindowList 验证，1710×1112 屏、Dock 左侧 82pt）：

| 项 | 公式 / 实测 |

| 垂直 | `y = max(minY-16, min(maxY-h+16, minY + frameH*0.1833 - 26))` → 实测窗口底距屏底 176 ≈ 1112×0.1833-26=177.9 ✓ |
| 层级 | `CGWindowLevelForKey(0xe)`，本机实测 rawValue 14 → **2147483631**（kCGUtilityWindowLevel）✓；§5 ⚠️「level=14」系把 key 误当 level 值 |
