聚焦搜索 / 日历选日 / 中转变化 / 监测偏好变化 / 截图翻译请求 / 划词翻译请求 / 中转设置变化 /
语言切换 / 空投文件 / 打开统计。

### 1.5 退出

`applicationShouldTerminate` → `ArchiveTaskQueue.confirmQuitIfNeeded()`（有未完成归档任务弹确认）；
`applicationWillTerminate` → `Personalization.flushPendingPersist()`（150ms 防抖窗口落盘）→
`LogArchive.stop()` → `AppBootstrap.stop()`（**只打一行日志**，不摘热键、不关监听，见 §7 P2）。

## 2. 数据层

### 2.1 两个 SQLite（`Storage/Database.swift`）

| 库 | 表 | 用途 |
|---|---|---|
| `clipboard.sqlite` | `clipboard_items` | 剪贴板条目（24 列：类型/内容/路径/工具来源/全文统计/去重键/标签） |
| | `tags` / `clipboard_item_tags` | 标签与多对多 |
| | `file_type_icons` | 文件类型图标缓存 |
| | `llm_sessions` / `llm_messages` | AI 会话与消息 |
| | `tool_invocations` | 工具调用台账（`ToolRegistry.run` 唯一写入点） |
| `statistics.sqlite` | `usage_daily_metrics` | 窄表 `(day, event_name, count)`，`ON CONFLICT` 累加 |
| | `app_meta` | 安装日期等元信息 |

连接参数：`WAL` + `foreign_keys=ON` + `journal_size_limit=1MB` + 启动 `wal_checkpoint(TRUNCATE)`。
`clipboard_items` 有 4 个二级索引（timestamp / (type,timestamp) / (is_generated_by_tool,timestamp) / is_note）+ 主键。

### 2.2 文件落盘策略

| 内容 | 位置 | 规则 |
|---|---|---|
| 长文本（>64KB） | `texts/` | 库内 `content` 只留 4,000 字符预览，全文在 `text_path` |
| 图片 | `images/` | 原图落盘，库内只存路径 |
| 缩略图 | `thumbs/` | 50pt 行缩略图 |
| 富文本 | `rich/` | RTF 副本（预览保真渲染用） |
| OCR 文本 | `ocr/` | 按 `dedupe_key` 分文件，索引 `index.json` |
| 日志 | `logs/YYYY-MM-DD.log` | 保留 3 天、单文件 4MB 截断 |
| 截图历史 | `captures/` | `CaptureHistoryStore` 自己的 sqlite |
| 归档临时 | `frset-archive-<uuid>/` | **不自动清理**（§7 P1） |

目录统一走 `AppDirectories.base` / `.sub(name)`，唯一例外是 `LogArchive` 自己硬编码
`FrsetNext/logs`（DEBUG 版会与正式版混写，§7 P1）。

### 2.3 统计口径

- 事件枚举 `AnalyticsEvent`：原版 53 个 + 重建扩展 11 个 = 64 个 case，另加 5 个裸串键；
  `trackedEventNames` 必须包含所有写入口，否则会出现"写了但统计窗不显示"的静默丢失。
- 写入：`StatisticsManager.record` → 串行队列 `com.frset.statistics.queue` → `INSERT ... ON CONFLICT`。
- 去重：7 个"操作组"事件（剪贴板捕获/截图/取色/OCR/翻译/工具/搜索）有 1.0s 去重窗口。
- 门控：`analyticsEnabled`（默认开）。
- 读取：统计窗 5 张卡走后台队列 + `autoreleasepool`；`trackedEventNames` 必须包含所有写入口，
  否则会出现"写了但统计窗不显示"的静默丢失（v116 修过一次 `ai_request_count`）。

### 2.4 日志与自诊断

`Log.write` → stderr + `LogArchive.append`。`LogArchive` 提供：
按天分文件、3 天清理、4MB 截断、**主线程卡死看门狗**（10s 预热期内不判定）、
60s 状态快照、最近 5 条面包屑（HANG 日志附带）。
排障开关：`FRSET_*` 环境变量 30+ 个（探针全部零成本路径，生产不触发）。

### 2.5 偏好

`Preferences` 是 `UserDefaults` 薄封装，`Preferences.Keys` 45 个常量（另有大量模块内散键）。
`Personalization` 管 15 个个性化键（字号/密度/圆角/强调色/打开动画/材质/缩略图…），
写入走 150ms 防抖 + `isLoading` 抑制，变更广播 `Personalization.didChangeNotification`。

## 4. 功能域地图

> 每域给：入口 → 主链路 → 关键文件 → 该域最容易踩的约束。函数级细节见对应深读报告。

### 4.1 剪贴板（`Features/Clipboard`，16 文件 / 5,957 行）

入口：`ClipboardModule.start()` → `ClipboardManager` 2s 轮询（`changeCount` 双读比对）。
链路：`ClipboardPasteboardReader` 读类型 → 自写回声抑制（token + TTL 5s）→ SHA-256 指纹去重 →
64KB 阈值分流（内联/落盘）→ `ClipboardRepository` 写库 → `items` 发布 → `NSTableView` 渲染。
约束：所有 IO 在 `com.frsetnext.clipboard.persist` 串行队列；行选中必须由
`ClipboardRowChromeView.drawSelection` 接管（否则系统蓝色实心铺满）；`maxResidentItems=800`。

### 4.2 截图与长截图（`Features/Capture`，39 文件 / 12,929 行）

入口：热键 ⌥1 / ⇧⌥W / ⇧⌥L、面板工具条、深链。
链路：`ScreenshotManager`（权限探针用 `SCShareableContent`，不用 `CGPreflight` 作硬闸门）→
`ScreenshotOverlay`（选区/窗口/元素）→ `ScreenSnapshot.cgCapture`（`CGWindowListCreateImage`
已被 macOS 15 移除，走 dlsym 兼容层）→ `CaptureActionChain`（复制/保存/钉图/标注/OCR/翻译）。
长截图：`LongScreenshotCoordinator` → ScreenCaptureKit **恒定 30fps 取帧流**（v150 放弃了早期
"事件驱动"，改为不管用户有没有滚动都按帧到位、按位移判定是否采纳）→ `LongScreenshotStitcher.append`：
跳过顶栏 13%（避免固定导航栏重复）→ 按行投影 1D NCC 粗搜 → 2D NCC 精修 → 锚点帧 + 最多 2 次全量重同步。
只追加条带，不做整图重拼。
约束：帧宽必须与画布同宽（±4px 归一，超过丢帧，否则整幅横向拉伸）；倍率用
`display.width / display.frame.width`（用 `backingScaleFactor` 会 2 倍拉伸）；采集矩形内收 3pt
且边框窗/HUD `sharingType = .none`（否则每帧顶边一条橙线）。

### 4.3 OCR 与翻译（Capture + AI）

OCR：`OCRService`（Vision）+ `PPOCROCRemote`（子进程 `OCRHelper` + onnxruntime 本地引擎）。
分级策略（v151 定型）：**锚定遍**（原生尺寸）→ 小字增强（识别 0 行 → 2×；行高中位数 <14px →
放大到行高约 18px，即 2~3×；≥14px **不放大**，v141 实测盲目放大会把"的路径"认成"时路径"）→
按锚合并（增强版只补锚没有的行）→ 可插拔 `Refiner`（系统 / 本地 PP-OCR，仅对中文行且文本不同时采纳）。
结果写 `CaptureEventBus.onTextRecognized`。
翻译：`TranslationToolSession` 三通道（LLM → 360 免 Key QNW → Apple 本机），
`⟦n⟧` 编号协议保证分段对应，失败回退逐块。
约束：OCR 复核必须在所有合并之后；Apple 翻译要求语言包已下载（`.supported` 会抛错）。

### 4.4 标注 / 钉图 / 取色

`AnnotationEditorController`（坐标恒为"图像像素、左上原点"）；`PinnedScreenshotManager`
（非激活面板，键盘靠 contentView `keyDown`）；`Eyedropper`（会话式，Esc/右键取消）。
约束：标注文本存"逻辑文本 + 换行宽度"，不能提交时硬换行（改字号不重排会溢出）。

### 4.5 监测（`Features/Monitor` + `FrsetStatsBar`）

链路：`MonitorSampler`（可见 6.5s / 静息 5s、30s 门控）→ `StatsDataProvider`（C 侧 `g_snap`
有效时覆写核心指标，保证菜单栏与面板同一时间线）→ `MonitorDetailView` / `StatsModulePanels`。
菜单栏：C 引擎 0.5s tick 自绘部件。
约束：三个可见性闸必须独立；`scheduleNext` 内部要重算门控；`statsRing` 不得在
GeometryReader 闭包注入基于 `geo.size` 的 environment（render→layout 死循环）。

### 4.6 搜索（`Features/Toolbox`）

`SearchSectionView` + `SearchEngine` + 多源（剪贴板/文件 `mdfind`/工具/网页）+ `FuzzyMatcher`。
约束：`scheduleSearch` 每个 await 后必须校验 generation；`runMdfind` 必须封顶读取 512KB。

### 4.7 AI（`Features/AI`，25 文件 / 4,475 行）

`AIModule` → `LLMService`（Anthropic / OpenAI / Gemini / Ollama 适配器 + `normalizedBase`）→
流式 `AsyncThrowingStream` → `AIChatViewModel`（每 token 更新 `@Published`）。
凭证：**刻意不用钥匙串**，AES-256-CBC + PBKDF2-SHA256（10 万轮、随机盐、随机 IV）落在
应用数据目录的加密文件（0600），因此不触发系统授权弹窗；审计日志只记 key 的 SHA-256 前 12 位。
约束：continuation 只 finish 一次；`LLMLineBuffer` 必须跨 chunk 攒行；Gemini 无终止事件只能等超时。

### 4.8 工具箱与命令面板

`ToolRegistry`（11 内置工具 + 自定义 AI 工具）→ `ToolRunnerWindow`；`CommandPalette`（⌥K）。
约束：一切执行必须走 `ToolRegistry.run`（否则漏 `tool_invocations` 与统计）；
录制快捷键时必须吞键；命令面板上下键方向在 v156 仍反（§7 P2）。

### 4.9 中转 / 投屏 / 互传（`Features/TransferDock`，17 文件 / 7,172 行）

`TransferDockService` + `LocalTransferStore`（硬链接暂存，绝不删原文件）。
**三条互相独立的通道**：① 空投（`AirDropSendEngine`，系统面板，iPhone 零安装）；
② ADB 族（`ADBExtrasEngine` / `AdbPairingService` / `ADBWirelessEngine` / `ADBFileBridge`，
无线配对 + 文件桥 + 应用窗口）；③ 自建 HTTP（`LanTransferServer` / `MCPServer` / `AndroidWebDAVServer`）。
投屏走 `ScreenCastEngine`（scrcpy 子进程，参数三处各拼一份）。
约束：主线程不得枚举目录/起 adb（v105 冻结 236s 的根因）；读管道必须在 `waitUntilExit` 之前；
`LocalTransferPaths` 必须是纯静态（单例属性会在 `dispatch_once` 里重入 SIGTRAP）。

### 4.10 归档（`Features/Archive`，14 文件 / 5,442 行）

`ArchiveCore`（7zz 封装）→ `ArchiveTaskQueue`（同包串行）→ 浏览/创建/Mini/进度四窗 +
`NSFilePromiseProvider` 拖出 + Finder 服务（`NSServices` 三条）。

`Process` 登记进队列以支持取消，`-bsp1` 只在需要进度时加（会污染 `l -slt` 与 `e -so`）。
约束：写操作串行；`7zz a` 靠 cwd 保住包内路径；提取路径安全两级判定（穿越/绝对/UNC 拦截，设备名只警告）。

### 4.11 设置 / 引导 / 说明书 / 统计

设置 11 页签：通用 / 音频 / 监测 / 剪贴板 / 截图 / 搜索 / AI / 工具 / 快捷键 / 数据 / 关于。

**两个踩过的坑（写下来免得再犯）**：

1. **点剪贴板条目后面板会被误收起**。原因：`renderClipList()` 重建了列表，
   被点的 `<li>` 已脱离 DOM，`e.target.closest(".hero-stage")` 沿**当前**父链往上找
   会漏掉 `.hero-stage`，于是「点外面就收面板」的判断误成立。
   修法是用 `e.composedPath()`——它保留事件派发那一刻的原始路径，不受重建影响。
2. **预览浮层的定位基准不能是列表**。`li.offsetTop` 是相对 `.pm-list` 的，
   直接拿来当内容区偏移会把预览顶到日历上。要用 rect 差值换算到 `.pm-body` 坐标。

**面板是固定尺寸框，内容在内部滚动（v224）**：真机的面板是**固定大小的窗口**
（默认 400×700pt，实际截图 360×630），内容超出就在窗口里滚动，窗口本身不随内容伸缩。
网页版照做：`.panel-mock` 固定 `height: 632px` + `overflow: hidden`，
`.pm-body` 负责纵向滚动（`overscroll-behavior: contain`，横向不滚）。
这样外层 `.hero-stage` 的高度也是稳定的，上下文不会因为条目增减而跳动。

**预览在面板内部向左展开（v224）**：真机的预览是独立 NSWindow 飘在面板**外面**
（`MainPanelPreviewPopoverCoordinator` + `PreviewArrowGeometrySupport.preferredNSRectEdge`
按屏幕空间选左右）。网页版没有屏幕概念，改成**收进面板内部**：
浮层回到 `.pm-body` 里，贴着条目行**向左展开**（右缘对齐行的左缘），
被 `.panel-mock` 的 `overflow: hidden` 裁住，**保证不溢出外框**；
面板窄（340px）时预览贴到内容区左缘、盖住列表左侧，这正是「向左展开」的结果。

⚠️ 两个必须记住的坑：
1. 浮层盖在列表上时，**空白区必须 `pointer-events: none`**——
   否则指针被浮层挡住 → 列表触发 `mouseleave` → 浮层收起 → 又触发 `mouseover` → 来回抖。
   浮层里的 `a / button / pre / code` 单独设 `pointer-events: auto`，照常可交互。
2. 同一行已显示预览时**不要重算位置**（真机也有 hover 抑制），否则会闪。

**网页版的预览与真机有一处刻意的差异**：真机的预览是**独立浮窗**（NSPopover，
可以飘到面板外面），网页的浮层不能出面板，所以做成「贴着那一行、上方放不下就翻上方」
的行内浮层；单击打开后会**固定**（真机是移出即关，网页里浮层会挡住指针，
固定住体验反而更像「打开了一个东西」），点列表外或切页才关。

脚本校验（编号存在 / 数字未变 / 相似度 ≥ 0.55 / 关键词未丢）→ 人工复核时把

**为什么子代理的产出必须过校验脚本**：AGy 的不同模型会不同程度地把编号与文本对错号
（gpt-oss 那轮整批错位，直接作废）。校验脚本对每条改动做四道闸：编号必须存在、

关键词丢失超过 35% 视为信息损坏——四条任一不过就丢弃这条。

## 6. 全工程不变量（合并 11 份深读 + 本次核对）

**窗口与布局**
1. 设置窗 940×620、统计窗 800×530：`contentRect` == 根视图 frame == `contentMin/MaxSize`，三者缺一即崩。
   （流传的"设置窗 800×530"是**口径漂移**，800×530 属于统计窗。）
2. `NSHostingView.sizingOptions = []`、`safeAreaRegions = []` 不可去；窗口禁用 `setFrameAutosaveName`。
3. SwiftUI 内容必须延后一个 runloop 装载（占位 `NSView()`），否则 `_postWindowNeedsUpdateConstraints` 异常。
4. 面板宽度下限 320，三处（prepare/sync/persistSize）都要钳制。
5. 缩放只发生一次：窗口负责尺寸，内容恒 1:1。
6. 非当前页不留在视图树；`NSTrackingArea` 在非激活页必须移除。

**线程与数据**
7. 剪贴板一切 SQLite/文件 IO 在 `com.frsetnext.clipboard.persist`；统计在 `com.frset.statistics.queue`。
8. `StatisticsManager` 的去重表只在队列内访问。
9. 主线程不得枚举目录、起子进程、`waitUntilExit`（v105：冻结 236s）。
10. 读管道必须在 `waitUntilExit` 之前，否则死锁。
11. `g_snap` 只允许主线程写；SMC 全量扫描必须在后台。
12. `ingestToolOutput` 目前**没走 queue**（已知偏差，§7 P1）。

**菜单栏**
13. 监控只允许 STATS 合并条一套；多实例必须退出，原版在跑只提示。
14. 状态项 `autosaveName` 必须带 `frsetnext.` 前缀；移除前备份 `Preferred Position`。
15. 双层项 = 子视图 + 空图占位 + 定长；`syncStatusItems` 必须防重入且异步再同步。
16. 连续旋转动画只能线性。

**视觉**
17. 圆角三路径统一 `.continuous`（`corner_audit.py` 0 违规）。
18. 动效只从 `Theme.Motion` 取（`motion_audit.py` 0 违规）。
19. 字号 ≥11pt；弱文字用 `Theme.tertiaryText` 不用 `.tertiary`。
20. 行选中态必须接管 `drawSelection`，hover 用中性色不用强调色。

**模块与工程**
21. 功能模块之间不引用具体类型，只走注册表/协议（既有 4 处例外见 §1.3）。
22. 本机无 SwiftUIMacros：`@State` 不可用，一律 `@Stored`。
23. 事件总线签名冻结（5 条），改签名会让 App 层接线静默失效。
24. 一切工具执行走 `ToolRegistry.run`；一切统计走 `StatisticsManager.record`（单点计数）。
25. 构建必须原子（staging → rename），否则会出现"已损坏"的瞬时半成品包。
