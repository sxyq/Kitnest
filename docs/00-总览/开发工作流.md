# FrsetNext 开发工作流（Git / 打包 / 安装测试）

> 2026-10-21 起固化的工作流。每次更改必须走完：**改代码 → 构建部署 → git 提交 →
> 重打 DMG → 本地重启 App**。本文档是完整操作手册，随时可查。

---

## 一、Git 提交规范

**每次修改后都必须提交**，commit message 写清楚「需求 + 改动文件 + 具体改动」。

格式（实际历史提交均遵循）：

```
<type>(<scope>): <一句话需求/结论>

需求（日期 用户原话）：「……」

改动文件：<路径>
- 具体改动 1（含数值：如 6pt→10pt）
- 具体改动 2

实测（验证方式）：……
```

type 取值：`fix`（缺陷）/ `feat`（能力）/ `chore`（工程）/ `docs`（文档）。

常用命令：

```bash
cd /Users/sunyiyang/Desktop/Project/frset-rebuild
git add -A apps/FrsetNext/Sources      # 或 add 具体文件
git commit -q -m "<按上面格式>"
git log --oneline -5                   # 核对提交链
git status --short                     # 每轮收尾前确认工作树干净
```

注意：
- 提交范围用 `git add -A <路径>` 按目录收，避免把 build/ 产物带进来
- 全仓库工作树收尾时必须 `git status --short` 为空

## 二、APP 构建与部署

```bash
/Users/sunyiyang/Desktop/Project/frset-rebuild/apps/FrsetNext/build.sh
# 输出过滤：grep -E "error:|✗|已部署"
```

- 构建约 3 分钟；`已部署(原子)` = 成功（产物 → /Applications/Kitnest.app）
- 构建前**不要**并行改同一文件（可能被清 build/ 打断）
- 构建后**必须重启 App** 才生效：

```bash
pkill -f "Kitnest.app/Contents/MacOS/Kitnest" 2>/dev/null; sleep 2
open -a /Applications/Kitnest.app; sleep 5
open "kitnest://panel?page=home"     # 可选：直接打开面板
```

## 三、DMG 打包（版本号固定 1.0.0）

一键脚本：`apps/FrsetNext/package_dmg.sh`

```bash
/Users/sunyiyang/Desktop/Project/frset-rebuild/apps/FrsetNext/package_dmg.sh
```

- 产出：`~/Desktop/Kitnest-1.0.0.dmg`（UDZO 压缩，约 42MB）
- 内含：`Kitnest.app` + `安装说明.txt`
- 自动挂载校验签名后卸载；版本号**固定 1.0.0 不变**（用户要求）
- **每次更改后都重新打包**（哪怕只是替换二进制）

## 四、安装测试清单（发给朋友 / 装到别的机器）

| 项 | 结论 / 操作 |
|---|---|
| 芯片 | **仅 Apple 芯片（arm64）**，Intel 机不可用；如需 Intel 版要单独构建 |
| 系统 | macOS 13+（LSMinimumSystemVersion=13.0） |
| 安装 | 打开 dmg → 拖 Kitnest 进「应用程序」 |
| 首次打开 | 未公证：**右键 → 打开 → 再点打开**；或终端 `xattr -cr /Applications/Kitnest.app` |
| 签名 | 自签 FrsetDev（TeamIdentifier 未设置），`codesign -v` 校验通过即可分发 |
| 权限 | 辅助功能（快捷键/自动粘贴）、屏幕录制（截图/录屏）、完全磁盘访问（可选）、通知——按需开，不开也能用大部分功能 |
| 卸载 | 删 App；数据在 `~/Library/Application Support/FrsetNext` |

打包后自检（脚本已含签名校验，手动复核时可再走）：

```bash
hdiutil attach ~/Desktop/Kitnest-1.0.0.dmg -nobrowse -readonly
codesign -v "/Volumes/Kitnest 1.0.0/Kitnest.app"   # 应无输出/无报错
plutil -p "/Volumes/Kitnest 1.0.0/Kitnest.app/Contents/Info.plist" | grep -E "ShortVersion|Identifier|Minimum"
hdiutil detach "/Volumes/Kitnest 1.0.0" -quiet
```

## 五、完整发布闭环（每次改动的标准动作）

1. **改代码**（Sources 下对应文件）
2. **构建部署**：build.sh → grep 确认「已部署」
3. **验证**：截图 / 探针 / 深链（见项目 skill：frset-verify）
4. **git 提交**：按第一节格式（需求 + 文件 + 改动）
5. **重打 DMG**：package_dmg.sh
6. **重启 App**：供用户随时查看效果
7. 收尾报备：改了什么文件、对应哪条需求、DMG 路径

## 六、排障速查（深链 / 探针）

> `Info.plist` 双注册 `kitnest` 与 `frsetnext`，旧链接仍可用；**本仓现行口径一律写 `kitnest://`**。
> 历史归档 / 深读报告里的 `frsetnext://` 是证据原文，不改写、不作现行示例。

```
kitnest://panel?page=home            打开面板
kitnest://settings?pane=monitor      打开设置页（monitor / monitor.widgets / about…）
kitnest://statistics                 打开使用统计
kitnest://cloudlink?url=<URL>&action=download   直驱网盘解析下载（测试用）
```

探针（defaults，用完删除）：

```bash
defaults write com.sxyq.frsetnext probe.preview -string "text"    # 启动 3s 后预览剪贴板首条
defaults write com.sxyq.frsetnext probe.openTool -string "qrcode" # 启动 3.5s 后打开工具（验证工具窗）
defaults delete com.sxyq.frsetnext probe.preview
```

窗口截图：`/usr/bin/swift /tmp/winall2.swift` 列窗 id → `screencapture -x -o -l<id>`；
玻璃/透明窗捕获发黑时改全屏 `screencapture -x` 后 sips 裁区域。

## 七、在线更新发布（v201 起）

> 端点与字段规格见 `docs/00-总览/工程全图.md` §5.7。**日常发版只需一条命令。**

### 日常发版

```bash
cd /Users/sunyiyang/Desktop/Project/frset-rebuild
bash tools/publish_update.sh $'[新增] 支持某功能\n[改进] 优化某交互\n[修复] 修掉某问题'
```

脚本依次：读当前 `CFBundleVersion` 并 +1 → 改 `Info.plist`（显示版本 1.0.0 不动）→
`build.sh` 构建部署 → 把 `/Applications/Kitnest.app` 打成 zip → 算 sha256 →
按行首 `[新增]/[改进]/[修复]` 归类生成 `latest.json` → scp 到 124 → `curl` 验证。

行首不带前缀的说明归入「改进」，并同步写进 `releaseNotes`。
也可用 `bash tools/publish_update.sh "说明" 7` 显式指定 build；
`--skip-build` **只允许** build 与当前 Info.plist 一致时使用（首版发布/仅重发清单）。

### 首次部署记录（2026-11-04 已完成，勿重复执行）

- 目标机：124 `124.222.153.108`（`calorieai.sxyq27.online` 官网与更新服务所在机）。
- 在 `/etc/nginx/conf.d/calorieai-updates.conf` 的 443 server block 内新增两段：
  `location = /kitnest/stable/latest.json`（alias 静态 + no-cache）与
  `location ^~ /kitnest/releases/`（alias 静态 + 复用 `limit_conn` zone）。
- 备份：`/etc/nginx/conf.d/calorieai-updates.conf.bak-kitnest-20261104`，按维护规范保留 ≥72h。
- 校验顺序：`sudo -n nginx -t` → `sudo -n systemctl reload nginx`（**reload，不要 restart**）→
  回归验证官网 `/`、CalorieAI 旧清单 `/android/stable/latest.json`、`/healthz` 均 200。
- 静态目录：`/srv/calorieai-updates/public/kitnest/{stable,releases}`。
- 该 conf 的源模板在另一个仓库 `~/Desktop/Project/CalorieAI/scripts/nginx/calorieai-updates.conf`；
  若那边重新部署会覆盖 124 上的配置，**需把这两段 location 同步回模板**。

### 发版后验证清单

```bash
curl -fsS https://calorieai.sxyq27.online/kitnest/stable/latest.json | python3 -m json.tool
curl -sS -o /dev/null -w '%{http_code}\n' -r 0-0 \
  "https://calorieai.sxyq27.online/kitnest/releases/<build>/Kitnest-<build>.zip"
```

客户端：重启 App → 看日志 `~/Library/Application Support/FrsetNext/logs/` 的
`清单已拉取：远端 build=… / 当前 build=…` → 状态栏「检查更新…」在有新版时变为
「发现新版本 · build N」→ 点「立即更新」验证下载、校验、备份替换与重启 →
重启后 WhatsNew 弹一次且显示清单里的分组说明。

### 回滚

- **只撤清单**：把 `stable/latest.json` 换回上一 build 的内容（客户端比较 build，自然不再提示）。
- **撤 Nginx 改动**：`sudo install -m 0644 <备份> /etc/nginx/conf.d/calorieai-updates.conf`
  → `sudo nginx -t` → `sudo systemctl reload nginx`。
- 客户端整包替换失败时，旧版留在 `/Applications/Kitnest.app.bak`（`installUpdate` 的既有保障）。

## 八、品牌官网部署（v214 起）

线上地址：**`https://calorieai.sxyq27.online/kitnest-site/`**
仓库位置：`website/`；部署脚本：`tools/deploy_site.sh`；nginx 配置：`deploy/nginx/`。

### 日常改站点

```bash
# 1) 本地预览（清单用仓库内快照）
cd website && python3 -m http.server 8788 --bind 127.0.0.1
#    浏览器打开 http://127.0.0.1:8788/

# 2) 截图脱敏（换了实机截图必做！原图含真实剪贴板内容）
python3 website/tools/sanitize_shots.py

# 3) 部署 + nginx + 验证
bash tools/deploy_site.sh
```

`deploy_site.sh` 做四件事：刷新 `website/kitnest/stable/latest.json` 快照（取线上 feed，
并把 `pageUrl` 指向官网）→ tar 传站点到 124 的 `/srv/kitnest-site`（原子换目录）→
幂等替换 nginx 片段（`<!-- kitnest-site:start -->` 标记，先备份 `calorieai-updates.conf`，
`nginx -t` 不过就不 reload）→ 验证首页 / CSS / 截图 / 清单四个地址返回 200。

### 关键约定

1. **截图必须脱敏**：`website/tools/sanitize_shots.py` 把剪贴板条目文字做模糊 + 遮罩。
   实机截图里含真实聊天消息、链接、文件名，直接上图等于公开泄露。
2. **清单同源**：nginx 把 `/kitnest-site/kitnest/` alias 到 `/srv/calorieai-updates/public/kitnest/`，
   官网展示的版本 = App 内检查到的版本，同一份文件，不会打架。
3. **下载要预检**：点「下载安装包」先发 HEAD，429 / 4xx / 超时会挡住并提示，不会给出坏链接。
4. **改 nginx 先备份**：脚本会自动 `cp` 出 `calorieai-updates.conf.bak-kitnest-<时间戳>`。

### 切到独立子域（待 DNS）

1. DNS 加 A 记录 `kitnest.sxyq27.online → 124.222.153.108`；
2. `scp deploy/nginx/kitnest-subdomain.conf sxyq27-124:/tmp/` → 装到 `/etc/nginx/conf.d/` →
   `sudo nginx -t` → `sudo systemctl reload nginx`；
3. `sudo certbot --nginx -d kitnest.sxyq27.online` 签发证书（现有证书不含通配符）；
4. 把清单的 `pageUrl` 与官网里的链接改成 `https://kitnest.sxyq27.online/`。
