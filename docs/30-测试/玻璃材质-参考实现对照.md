## 1. bring-shrubbery/dynamic-landing — `Sources/DynamicLanding/Views/IslandView.swift`

| 机制 | 原文要点 | 我们的落地 |
|---|---|---|
| 只有形状在动 | `shape.frame(height: layout.rect.height)` 单独动画；内容按**展开后的最终尺寸**一次性布局，再 `offset(y: -layout.slide)` 从顶边后面滑出 | 等价实现放在 AppKit 取样层：`IslandMaterialView` 的玻璃取样面固定在展开尺寸，逐帧只改 `CAShapeLayer` 遮罩路径 |
| 裁切按形状而非包围盒 | 注释明确：按 rect 裁会在形变时露出圆角外的新内容 | 我们用 `IslandOutline` 路径做 mask（同一几何），未用 rect 裁 |
| 单层外壳 | `shape.fill(backgroundStyle)`：黑 / 纯色 / `.ultraThinMaterial` 三选一，不叠第二层 | 岛外壳只有一层材质宿主 + 一层黑幕过渡；没有第二层模糊 |
| 阴影按需 | `islandShadow(_:)`：`.none` 时**不挂** modifier，「默认岛不为阴影付费」 | 同口径：流光只在展开且预览可见时启用 |

## 2. techuila/top-notch — `Sources/NotchCore/Style.swift` + `DECISIONS.md`

- `NotchMaterial`（Style.swift:154-243）：**一个组件**从黑过渡到玻璃/渐变/纯色，过渡属于开合动画的一部分；`DECISIONS.md:95-101` 明确记了「先做过常驻 backing + 只在展开时挂 effect view，被判为第二组件后废弃」。
  → 我们的岛也是单一材质宿主；收起态由黑幕 1→0 完成，展开态玻璃自身不再叠第二层黑。
- **玻璃模式不画自绘高光边**（Style.swift:216-233）：手绘 specular 只给 `.solid`，理由是系统玻璃自带边缘处理，「doubling it read as a fake transparent border」。
  → 我们已有同样的门控：`effectiveMaterial != .liquidGlass` 才画 0.12 发丝线。
- 阴影只在展开时（Style.swift:236-240）：`.black.opacity(isExpanded ? 0.55 : 0)`、`radius 26 / y 14`。
  → **未采用**：岛面板窗口尺寸是固定的 712×436（`position()` 按 `screen.frame.maxY - size.height` 贴顶），四周没有 26+14pt 余量；在这个窗口里加阴影会被窗口边界硬切，出现一条直边。要加必须扩窗，属于「既有窗口尺寸」禁改范围。现状以形状自身的明度台阶 + 系统玻璃边缘提供层次。
- 顶部锚定 + 上角外扩（`NotchSilhouette`，`flareRadius` 随展开从 8→15 变化）：我们的 `IslandOutline` 用 `shoulder = min(radius*0.45, h/2)` 做了同类处理，且由同一个 `radius` 插值驱动。

## 3. DevSrijit/islet — `Islet/Views/Components/BlurBackdrop.swift`

- 展开时才存在的**渐进模糊**：`NSVisualEffectView(.hudWindow, .behindWindow, state .active)` + 垂直衰减 mask（`pow(1-t, 1.7)`，24 段渐变）+ 左右 22pt 软化；mask 只在 `bounds.size` 变化时重建（`MaskedEffectView.layout` 里比对 `maskedSize`）。
- 借鉴的是**「只在需要时采样 + mask 按尺寸更新」**这条机制，不是它的视觉：我们的岛不需要在下方再铺一层渐进模糊（那会成为第二层背景采样，与「每个窗口只保留必要的背景采样层」冲突）。
- 尺寸门控我们学了一半：它的 mask 按尺寸重建（尺寸不变就不重建）；我们的遮罩每帧都随形变重算——实测 `p95 0.006–0.017ms`、`layout p50 0.005–0.009ms`，属于可接受范围，因此保留逐帧重算（否则形变会跳格）。

## 4. Apple 文档侧

- `NSGlassEffectView`：系统玻璃自带折射与边缘高光，官方不建议在外面再叠仿玻璃描边——与 top-notch 的结论一致，我们沿用「玻璃模式不画亮边」。
- `NSVisualEffectView`：`state = .inactive` 只是固定浓淡，不改变采样来源；`blendingMode = .behindWindow` 才采样窗口后方。这两点决定了「固定失焦观感」只能靠 `state`，而「是否真玻璃」只能靠类选择。
- `GlassEffectContainer`：用于多个玻璃元素合并渲染，适用于同一容器内多块玻璃；我们的结构面每窗只有一块玻璃，不适用。

## 5. 结论

三条可借鉴的机制都已落在实现里：**形状单独动画 + 内容/取样面固定**（DynamicLanding）、**单组件材质 + 玻璃不叠自绘亮边**（top-notch）、**只在需要时采样 + mask 按尺寸更新**（Islet）。唯一明确不采用的是 top-notch 的展开态阴影——窗口尺寸固定、没有绘制余量，硬加会被窗口边界切边。
