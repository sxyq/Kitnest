> 无线配对与剪贴板显式化也要单独核实；并把这些功能写成需求用例说明」

## 二、证据链（逐项）

### 2.1 窗口截图：原版有，重建版丢了，v112 补回（但交互没对齐）

**原版存在的三层证据**：

1. **反汇编还原的调用骨架**（`specs/06-规格-截图与OCR.md` §4.1）：
   ```swift
   func capture(_ mode: CaptureMode) {   // .area/.window/.full/.ocr/.pin/.long
   ```
   ← 原版 `CaptureMode` 枚举**含 `.window`**，且捕获链路与区域模式同源。

2. **能力清单结论**（`specs/20-规格-截图工具原版调用实测与复用.md` §1 末）：
   > 「即：选区截图、**窗口截图**、整屏、长截图、贴图（Pin）、截图编辑器、OCR、取色全部是原版自带的。」

3. **本次二进制反射实测**（`/Applications/Frset.app` arm64 slice，`__swift5_reflstr` 类字段）
   —— 同一属性簇中出现：
   ```
   windows | windowOrder | selectedWindowId | keyDownMonitor | isClosingWindow | id | manager
   ```
   语义：窗口集合 → 排列顺序 → 当前选中窗口 → 键盘监听 → 关闭中态。
   即原版窗口模式**不是「直接抓最前台」，而是一个窗口选择器**（方向键切换、回车/单击确认）。

**重建版历史上从未有过**（`git log --all -S` 全空）：
- `case .window` → 0 次
- `captureWindow` → 0 次
- `highlightedWindow` → 0 次

**结论**：窗口截图是**原版能力在重建版丢失**；v112 补回方向正确，但交互简化成「抓最前台窗口」，
与原版「窗口选择器」不一致 → v113 改为覆盖层窗口选择（悬停识别 + 单击截取）。

### 2.2 区域窗口吸附：没有依据，是自研发明

- `specs/06` §3「UI 规格」的 overlay 结构图：只有 **选区（拖拽）+ 放大镜 + 尺寸标签 + 工具条**，没有窗口识别/吸附描述；
- 原版二进制中与选区相关的字段是 `selectionRect / selectionScreenRect / selectionScreenRectProvider /
  selectionMoveReferencePoint / selectionCornerRadius`（选区几何与移动），**没有任何 hoveredWindow /
  snapWindow / windowUnderCursor 类字段**；
- 唯一与窗口识别相关的字段簇（见 2.1 第 3 条）全部是**窗口模式**的选择器状态。

**结论**：「区域模式悬停吸附」在原版无证据，属 v112 自研。已按用户判定移除——
区域截图回归纯手动框选（原版行为），窗口识别只在窗口模式内提供。

### 2.3 无线配对：原版没有，是真实新增

- 原版二进制（arm64，14.8MB slice）中 `adb` / `scrcpy` / `Android` / `android` 字符串 **0 处**；
- 原版是纯 macOS 工具（无手机端任何功能），`specs/20` §2.1 的快捷键表也全是本机动作；
- 重建版 v103 才有 `connectedDevices`（adb devices 探测），v112 才加 `pair/connect/mdns`。

**结论**：真实新增，来源是对标 AndroMeld（见综合对标分析报告），与“原版已有”无关。保留。

### 2.4 剪贴板双向同步：能力原本就有（scrcpy 默认），v112 只是显式化

- scrcpy 官方语义：**默认自动同步剪贴板**，`--no-clipboard-autosync` 才是关闭开关；
- 重建版 v103 的 `startMirror` 参数为 `--max-size / --video-bit-rate / --stay-awake / --no-power-on`，
  **没传 clipboard 参数 = 默认开启**；
- v112 追加 `--clipboard-autosync`（显式声明）+ Toast 文案「剪贴板双向同步开」。

**结论**：不是「半接入 → 转正」，而是「默认已在工作，v112 只是把它写进参数并告诉用户」。
保留参数（自文档化），修正文档表述。

## 四、需求用例说明

> 这一节回答「这几个功能到底是用来做什么的」——每项按 目标 / 场景 / 前置 / 主流程 / 异常 / 验收 写。

### 用例 1：窗口截图（窗口模式）

**用来做什么**：把「屏幕上某一个窗口」整块截下来——不带桌面背景、不带其他窗口的遮挡。
用于做教程配图、报 bug 截图、把某个 App 的界面发给别人。

| 项 | 内容 |
|---|---|
| 触发 | 全局热键 ⇧⌥W；或主面板截图区「窗口截图」卡片 |
| 前置 | 已授「屏幕录制」权限 |
| 主流程 | ① 覆盖层铺满所有屏幕并压暗；② 鼠标移动时，光标下的窗口**整框高亮 + 显示「App 名 · 窗口名」标签**；③ **单击** → 截取该窗口（SCK 窗口级抓取，**自动排除遮挡它的其他窗口**）；④ 进入与区域截图相同的收尾：落盘 + 动作工具条（复制/保存/贴图/识字/翻译/编辑/美化/空投） |
| 异常 | 无窗口高亮时单击无效果；Esc/右键取消；SCK 失败回退「覆盖层快照裁剪」（此时会带上遮挡窗口，属降级） |
| 验收 | 选一个被其他窗口遮住一半的窗口 → 截出来应是完整无遮挡的该窗口 |

### 用例 2：区域截图（区域模式）

**用来做什么**：自由框选屏幕上任意一块矩形区域，是最高频的截图方式。

| 项 | 内容 |
|---|---|
| 触发 | ⌥S / 面板「区域截图」/ 其他截图热键（截图并复制/贴图/OCR/翻译都走这条） |
| 主流程 | 拖拽框选 → 实时尺寸标签 + 放大镜 → 松开 → 动作工具条或默认动作 |
| 说明 | **不做窗口吸附**（原版无此行为，v113 已移除）；想截窗口请用用例 1 |
| 验收 | 拖拽全程无卡顿；选区与截图内容像素一致 |

### 用例 3：无线配对（ADB，Android）

**用来做什么**：让 Mac 和安卓手机**不插 USB 线**建立 ADB 连接，之后投屏、传文件都走无线。
适合手机放桌上/支架上、桌面不想多一根线的场景。

| 项 | 内容 |
|---|---|
| 触发 | 传输与投屏页 → 投屏区「无线连接」→「扫描局域网」或手动填 IP:端口 |
| 前置 | 手机 Android 11+，开发者选项 → 无线调试已开启；Mac 与手机同一局域网 |
| 主流程 | ①「扫描局域网」→ 列表出现设备（`_adb-tls-connect` 可直接连，`_adb-tls-pairing` 需配对）；② 首次：手机无线调试页「使用配对码配对」→ 填 IP:端口 + 6 位配对码 →「配对」；③ 用扫描到的地址点「连接」→ 状态显示 connected；④ 之后「检测设备」可见设备，可投屏/传文件 |
| 异常 | 配对码错误 → 状态栏显示 adb 原始报错；公司网隔离 mDNS → 用手动 IP:端口 |
| 验收 | 配对一次后，重启应用点「检测设备」仍能看到该无线设备并投屏 |

### 用例 4：投屏期间剪贴板双向同步

**用来做什么**：投屏窗口里操作手机时，**电脑复制的文字手机能直接粘、手机复制的文字电脑能直接粘**——
省掉「发给自己」的中间步骤。这是 scrcpy 自带能力，我们要做的是「让用户知道它在工作」。

| 项 | 内容 |
|---|---|
| 触发 | 开始投屏即生效（scrcpy 默认开启；v112 起显式传参并在启动提示中说明） |
| 主流程 | 电脑 ⌘C 一段文字 → 手机输入框长按粘贴 → 出现的是电脑复制的内容；反向同理 |
| 边界 | 图片剪贴板不保证双向（scrcpy 只同步文本）；超大文本可能被截断 |
| 验收 | 投屏中双向各粘一次文本成功 |

### 用例 5：ADB 文件互传（同批新增，一并说明）

**用来做什么**：不用数据线管理工具、不用装手机 App，把文件在 Mac 和安卓之间搬运。

| 项 | 内容 |
|---|---|
| 触发 | 传输与投屏页 →「文件互传 · Android」→ 推送/拉取 |
| 主流程 | 推送：本地暂存的文件 → 手机 `Download/FrsetNext/`（逐个报成功/失败）；拉取：该目录全部文件 → 本地暂存（自动入索引，可预览/再转发） |
| 前置 | ADB 已连接（USB 或用例 3 的无线） |
| 验收 | 推 3 个文件 → 手机文件管理器可见；手机上放 2 个文件 → 拉取后本地暂存出现且可预览 |

### 用例 6：自动更新（v112 新增，待确认去留）

**用来做什么**：装好的 App 能知道自己有新版并引导下载，而不是用户永远停在装机版本。

| 项 | 内容 |
|---|---|
| 触发 | 启动静默检查（≥24h 一次，未配置更新源则完全关闭）+ 状态栏「检查更新…」手动 |
| 前置 | 「设置 → 关于」填了更新源（GitHub `releases/latest` 或同构 JSON） |
| 主流程 | 拉取 → 语义化版本比较 → 有新版本弹窗（前往下载 / 忽略此版本 / 下次再说） |
| 说明 | 原版更新链已被补丁 C 禁用、本项目无分发渠道时该功能无实际作用 → **是否保留待定** |

## 五、待确认事项

1. **窗口模式是否还原原版的「窗口列表 + 方向键选择」**：二进制证据（`windows / windowOrder / keyDownMonitor`）
   指向一个带键盘导航的窗口选择器；当前 v113 实现是「悬停 + 单击」。若要完全对齐原版，需另做列表式选择器（约 2-3 天）。
2. **自动更新去留**：无分发渠道时建议关闭（保留代码但默认关），待确定发布方式后再启用。
3. **区域模式的按键增补**：原版窗口选择器有 keyDownMonitor（方向键），区域模式是否也需要方向键微调选区——待确认。
