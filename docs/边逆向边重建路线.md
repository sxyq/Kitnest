# 边逆向边重建路线

> 2026-10-14 制定。回答一个问题：**如何用已有的逆向档案（汇编/截图/偏好键）作为输入，
> 一边继续逆向维护原 App、一边正向重建 Mini-Frset，两条轨道并行不冲突。**

---

## 1. 双轨总图

```
軌道 A（逆向维护）—— 保障"现在就能用"
  frset/（原项目）
  ├─ 二进制补丁（20 项防呆）+ 注入工具链 + 维护脚本
  ├─ 产出：注入版 Frset（过渡主力）
  └─ 副产品：FrsetStats.framework（M1，与轨道 B 共享）★

軌道 B（正向重建）—— 收获"越用越便宜"
  frset-rebuild/（本工程）
  ├─ specs/（规格书：逆向档案 → 可开发规格）
  ├─ apps/FrsetStats（监测 framework，直接来自轨道 A 的 M1 产物）
  ├─ apps/FrsetNext（主工程：面板/剪贴板/设置…按优先级重建）
  └─ tests/（行为对照：原 App vs 新 App）

交接点：FrsetNext 覆盖日常使用 → 逐步替代原 Frset；原 App 转为备用/对账基准。
```

## 2. 转化管道（逆向产物 → 重建输入）

| 逆向产物（frset/） | 转化动作 | 重建产物（frset-rebuild/） |
|---|---|---|
| 反汇编（242 万行，otool + da.py） | 读函数逻辑 → 写"逻辑规格"（输入/输出/边界/时序） | Swift 实现 + 单元测试 |
| UI 探针截图（ui-probe/ deploy-test/ final-test/） | 逐界面写"UI 规格"（布局/组件/交互/文案） | SwiftUI 视图 |
| 偏好键与行为记录（defaults dump/报告） | 归纳数据模型 | 模型层（Codable structs） |
| 补丁点与逆向报告（报告/补丁 JSON） | 标注"原版行为边界"（哪些是修正过的行为） | 设计决策记录 |
| Stats 源码（MIT） | 直接编译 | FrsetStats.framework（零重写） |

**规格书模板**（每个模块一份，放 `specs/`）：
```
# 规格：<模块名>
## 来源  （截图引用 / 反汇编函数地址 / 偏好键）
## 行为  （功能点清单，每条：触发→行为→边界）
## UI    （布局草图 + 组件清单 + 文案）
## 数据  （模型字段 + 存储位置 + 迁移策略）
## 验收  （对照测试用例：原 App 操作 X → 期望 Y）
```

## 3. 模块优先级（蚕食顺序）

| 优先级 | 模块 | 依赖 | 说明 |
|---|---|---|---|
| **P0** | 监测 framework（FrsetStats） | 无 | M1 双轨共享产物，重建的第一个模块 |
| **P0** | 主面板框架（FloatingPanel 结构：工具栏/区域布局） | 无 | 重建的"壳"，其余模块往里挂 |
| **P0** | 剪贴板历史（监控/存储/搜索/缩略图） | 面板框架 | NSPasteboard 监听，无系统权限 |
| **P1** | 监测视图区（Stats 式卡片+popover，Frset 化） | 监测 framework + 面板框架 | UI 照探针截图 |
| **P1** | 截图 + OCR（Helper 管线） | 屏幕录制授权 | 逻辑照逆向报告，OCR 可换系统 Vision |
| **P2** | 设置窗口（通用/搜索/工具/快捷键/关于 5 页） | 面板框架 | UI 照截图；监测设置页新增 |
| **P2** | 菜单栏图标体系（主图标+监测项） | 监测 framework | Stats SWidget 体系 |
| **P3** | 工具/日历/笔记/快捷键/AI 服务商 | P2 | 低频，可最后搬甚至不搬 |

## 4. 里程碑

| 里程碑 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **M0**（本周） | 本工程骨架 + 首批规格书（监测区/主面板/剪贴板） | specs/ 3 份规格评审通过 | 1-2 天 |
| **M1** | FrsetStats framework（含 Stats 采集层 + 两轨共享） | 独立宿主验证：10 模块数据与 Stats 对账 | 2-3 天 |
| **M2** | FrsetNext 主工程：面板框架 + 剪贴板 + 监测视图 | 日常可用性测试（剪贴板/面板/监测三项替代原 App） | 3-5 天 |
| **M3** | 整合：截图OCR + 设置窗口 + 菜单栏体系 | 全日常路径覆盖；与原 App 行为对照通过 | 3-5 天 |
| **M4** | 切换评估：日常主力换成 FrsetNext | 双轨并用一周无回归 → 原 App 转备用 | 持续 |

> 轨道 A 的 M1-M4（Stats 注入集成）不停止：其产出（framework）正是轨道 B 的第一块砖。
> 两轨共享一套采集层，**没有重复劳动**。

## 5. 行为对照机制（重建的质量保证）

- `tests/` 维护一张**对照测试表**：每行 = 场景（如"复制文本→面板出现条目"），
  两列 = 原 App 行为 / 新 App 行为，逐项打勾；
- 关键场景优先：剪贴板捕获时序（含图片/富文本）、面板展开收起、监测数值误差（<2%）、
  权限请求时机；
- 任何不一致：先判定"原 App 行为是否正确"（原版可能有 bug/我们修正过的行为），再决定新实现。

## 6. 技术决策记录（ADR 速记）

| 决策 | 选择 | 理由 |
|---|---|---|
| 语言/框架 | Swift + SwiftUI（面板/设置） + AppKit（菜单栏/窗口管理） | 与原 App 同栈，规格迁移损耗最低 |
| 监测采集层 | 直接编译 Stats 源码（MIT） | 零重写、数据能力 100% 对齐 |
| bundle ID | 待定（沿用 com.maoux.frset 共享偏好 vs 新 ID 独立） | M2 前决策；新 ID 需重授屏幕录制 |
| OCR 引擎 | 优先系统 Vision（若能满足） | 免 Helper 管线复杂度 |
| 数据存储 | 独立 store（SQLite/JSON），不与原 App 混写 | 双轨并行期互不污染 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 重建烂尾 | 按 P0→P3 蚕食，任一点停下都不影响已覆盖的功能；轨道 A 始终可用 |
| 行为漂移 | 对照测试表 + 关键路径 100% 覆盖才切换 |
| 工作量大 | 低频功能不搬；UI 照截图重画（不逆向 UI 代码） |
| 双轨数据冲突 | 独立存储；迁移工具晚做 |
