## 二、存储占用实测（460 MB）

| 目录/文件 | 大小 | 说明 |
|---|---|---|
| `Application Support/FrsetNext/images/` | **440 MB**（89 个文件） | 剪贴板图片原图，单文件均值约 5 MB（Retina 截图直接入库未压缩） |
| `rich_texts/` | 7.7 MB（116 个） | 富文本（RTF）落盘 |
| `texts/` | 1.9 MB | 超长文本（>64KB inline 上限）落盘 |
| `thumbnails/` | 1.9 MB | 列表缩略图 |
| `screenshots/` | 1.0 MB | 截图原图 |
| `ocr/` | 336 KB | OCR 文本索引 |
| `clipboard.sqlite` + WAL | 1.9 MB + 1.6 MB | 剪贴板索引库（WAL 偏大） |
| `statistics.sqlite` + WAL | **4 KB + 2.1 MB** | 统计库——主库几乎空、WAL 滞留全部数据（未 checkpoint） |
| `app.log` | 110 KB（滚动 200 KB） | 日志；RenderProbe 每 5s 一行是主要增长源 |
| `Caches/com.sxyq.frsetnext` | 7.7 MB | 应用图标/预览缓存 |

**清理机制（设计内）**：保留 30 天 + 容量上限 2048 MB（10 分钟巡检，超限删最旧至 90% 水位）。
**结论**：440 MB 图片在 2 GB 上限内，属设计内积累；若要压降，建议图片入库前压缩（JPEG/HEIC 重编码，预计降 60–80%）或把上限调到 512 MB。

## 三、CPU / 内存 / IO 发现（按调用链）

97 条调用链画像（`调用链资源画像.csv`）：

- **CPU 高（11 条）**：截图链路 3 条（`startRegionCapture` / `longScreenshotTapped` / `showOnMain`——CGImage 合成+编码）、状态栏 4 条（`mainItemClicked` / `startTimers` / `toggleMonitor*`）、`sampleOnce`（监控采样）、`registerAppLevelTools`（启动注册）。
- **内存高（3 条）**：截图/长截图/美化（CGImage 全尺寸位图峰值最高；长截图拼接是最大单次内存峰值点）。
- **常驻高频信号 TOP**：`installMainItem`（timer+fileIO+sortFilter 7 个信号）、`MainPanelPreviewPopoverCoordinator` 鼠标事件链（mouseMoved/hover 4 个信号）、剪贴板表格 hover 链。
- **日志 IO**：`Log.write` 每次 open→seek→write→close（无缓冲句柄），高频 info 点会放大 syscall；已把 RenderProbe 从常驻路径移除，其余高频点建议降 `.debug`。

## 四、本轮修复清单（v73 第二轮）

1. `MonitorSampler.scheduleNext`：隐藏态采样门控（1s → ≥5s）。
2. `RenderProbe.isEnabled`：默认关闭，排障显式开启。
3. `Database.init`：WAL 上限 1 MB + 启动 TRUNCATE checkpoint。
4. 主面板三项：宽度单一来源（选中值）、锚点展开（图标正下方）、三角指示器 + 长出来动画（上一轮已交付）。

## 五、复看建议（按性价比排序）

1. **剪贴板图片压缩**（存储 −60~80%，改动集中在 `ClipboardImageStorage.write`）。
2. **日志异步化**：`Log.write` 改用常驻 FileHandle + 后台串行队列（去掉每行 open/close）。
3. **双层部件位图缓存**：`refreshTitles` 增加「文本未变即复用」判断（省 CPU/渲染）。
4. **长截图内存峰值**：分帧直接写盘（AVAssetWriter/临时文件）而非全量驻留内存。
5. **死代码清理**：25 个 `dead_suspect`（C 静态函数为主）删除前先跑一轮回归。
