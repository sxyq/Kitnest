## 1. OCR 模型（只讨论）

### 1.1 现在用的是什么

| 项 | 值 |
|---|---|
| 模型 | **Apple Vision** `VNRecognizeTextRequest`（系统内置，无第三方依赖） |
| 档位 | `.accurate`（准确模式，非 fast） |
| 版本 | `VNRecognizeTextRequestRevision3`（macOS 12+，中英混排最优档） |
| 语言纠错 | `usesLanguageCorrection = true` |
| 语言 | 「自动检测语言」开（默认，revision 3 的按行语种识别）→ 识别更稳；关则用 `ocrLanguages`（zh-Hans + en-US） |
| 位置 | `Features/Capture/OCR/OCRService.swift`（含 `ScreenshotOCRDirectImageStore` 解码缓存） |

### 1.2 调用链（AST/CodeGraph 实测 6 个消费方）

1. `App/AppBootstrap.swift` —— 图片进剪贴板后自动 OCR，落 `ocr/<dedupeKey>.txt`
2. `Features/Capture/Screenshot/ScreenshotManager.swift` —— 截图后 OCR（可弹结果窗）
3. `Features/Capture/OCR/ScreenshotOCRWindow.swift` —— OCR 结果窗手动重识
4. `Features/Capture/Pin/PinWindow.swift` —— 贴图窗口取词
5. `Features/Capture/OCR/ScreenTranslator.swift` —— 取词/划词翻译前的文本提取（走 `recognizeObservations` 拿坐标）
6. 预览弹窗「识别文本」（`PreviewPopoverDataBridge.recognizeImageProvider` → `OCRService.recognizeText`）

### 1.3 「效果不太行」的根因与已做修复

不是模型识别错，而是**输出被拼错**：

| 问题 | 修复（已上线） |
|---|---|
| Vision 返回的 observations 是**检测顺序**，拼起来整段乱序 | `readingOrder()` 按 boundingBox 自上而下、行内从左到右重排 |
| 段落感丢失 | `assemble()` 行间距 > 0.85 行高处插空行 |
| 中文里插空格（「文 字 录 入」） | `cleanLine()` 去掉 CJK 之间空白，英文空格保留 |
| 固定语言列表在混排上吃亏 | 「自动检测语言」开关（默认开，`automaticallyDetectsLanguage`） |

### 1.4 换模型的三条路（讨论，不动手）

| 方案 | 准确率 | 代价 | 结论 |
|---|---|---|---|
| A. Vision + 参数调优 | 中上 | 0 | **已做**，先观察效果 |
| B. 捆绑本地第三方模型（PaddleOCR / RapidOCR / ONNX Runtime） | 高（小字/密集排版明显更好） | 二进制 +20~60MB、签名/公证链路、模型更新维护 | 若 A 仍不够，**优先这条**（真正「换模型」） |
| C. 联网/本地大模型视觉转写 | 最高 | 图片出网（本地 Ollama 除外）、延迟、费用 | **本轮明确不做**（已撤销）；将来若做，接在 `LLMProviderAdapting` 的视觉扩展层最省 |

## 2. 本地 AI 线：已有实现（功能清单）

### 2.1 分层架构（协议 + 门面 + 适配器）

| 层 | 实现 | 说明 |
|---|---|---|
| 协议 | `LLMProtocols.swift`：`LLMRequestBuilding` / `LLMResponseParsing` / `LLMCredentialStoring` / `LLMProviderAdapting` | 适配器只写「构造 + 解析」两个切面，`send/complete` 由协议扩展给模板方法 |
| 门面 | `LLMService`（12 个调用方） | `send` 流式 / `complete` 一次性 / `buildMessages` / `withSystemIfNeeded`；同时实现 `LLMServiceProtocol` 经 `ServiceLocator.llmService` 跨模块注入 |
| 路由 | `LLMResolver` + `AIProviderModelDiscoveryCache` | 厂商切换、`effectiveModel`（用户选择 > 厂商默认）、模型列表拉取 + 缓存失效 |
| 传输 | `LLMTransport`：`streamBytes` / `LLMLineBuffer` / `LLMJSON` | SSE（OpenAI/Anthropic/Gemini）与 NDJSON（Ollama）两种流式；含 `[DONE]`/`message_stop` 终止识别 |
| 厂商适配 | `OpenAICompatibleService`（OpenAI/DeepSeek/豆包/Kimi/智谱/Groq…）、`AnthropicService`、`GeminiService`、`OllamaService`（**本地**） | 各自的端点规范化、鉴权头、模型列表过滤 |

### 2.2 凭证与安全

- `CredentialStore`（18 函数）：AES 信封加密落 `ai-credentials.bin`（0600），主密钥由钥匙串派生（`masterSecret`/`derivedKey`）；`InMemoryCredentialStore` 供测试
- `AICredentialJournalStore` + `AICredentialCommitCoordinator`：凭证增删改留痕（有数据、**无 UI 入口**）
- `LegacyGeminiMigrator`：旧 Gemini 键一次性迁移 + 迁移台账

### 2.3 功能面（用户可感知的）

| 功能 | 入口 | 实现 |
|---|---|---|
| AI 对话 | 设置/AI 或命令面板 | `AIChatView` + `AIChatViewModel`：多会话（`LLMSessionStore`，自动标题/摘要）、流式渲染、停止、新建会话、模型切换、错误横幅 |
| 摘要 / 润色 / 翻译 | 剪贴板右键/预览 | `AISummaryView` + `AISummaryAction`（summarize/polish/translate）+ 默认动作持久化；`ClipboardSummaryExecutionCoordinator` 执行 |
| 自定义提示词工具 | 设置 → AI → 自定义工具 | `CustomAIToolStore`（`ai.customTools`）：`name + systemPrompt + promptTemplate`，`AISummaryViewModel.runCustom` 消费 |
| 截图翻译 / 划词翻译 | 截图工具条 | `TranslationToolSession`（3 调用方）+ `ScreenTranslator`（OCR 取词 → LLM）+ `AppBootstrap.beginScreenshotTranslate/runTranslateSelection` |
| 贴图窗口内 AI | 贴图窗口 | `PinWindow` 直接发起（复用 AISummary 通道） |
| 厂商管理/连通性 | 设置 → 搜索与 AI | `AISettingsPane`（11 函数）+ `AIProviderConnectionService.test`（连通性测试、BaseURL 回滚） |
| 事件广播 | — | `AIEventBus.emitResult` |

### 2.4 模型/参数偏好

`AISettings`：厂商（anthropic/gemini/openAICompatible/ollama）、模型（空 = 默认）、BaseURL（每厂商独立键 + 共享回落）、温度、maxTokens、系统提示词、默认动作。

## 3. 插件/工具体系（Toolbox）

### 3.1 注册表与插件模型

- `ToolRegistry`（4 个调用方）：`register`（同 id 覆盖）/ `all` / `tool(id:)` / 启用禁用（`toolbox.tool.<id>.enabled`）/ `grouped()` 分类 / 执行 + 埋点
- `ToolDescriptor` + `ToolOption`：带参数（选项/默认值）的工具描述
- `ToolKind` 14 种：`timestampConverter, ipAddress, varNameConverter, base64, urlEncode, jsonFormat, codePreview, imageCompress, colorPicker, translation, hashGenerator, uuid, summary, qrCode`
- **插件 = 内置注册工具 + 用户自定义提示词工具**；没有外部脚本/MCP 插件加载器（MCP 属宿主连接器，不在 App 内）

| uuid | uuid | 否 | UUID 生成 |

## 5. 缺口与建议（按优先级）

1. **零测试**：AI/工具链 3 跳内没有任何测试。建议先给纯函数补单测：`LLMJSON`（SSE/JSON 解析）、`LLMLineBuffer`（流拆包）、`CustomAIToolStore`（编解码）、`ToolConverters`（转换正确性）。
2. **死代码清理**：删 `LanTransferServer.invalidateTokenCache`；ObjC 调试探针按需保留（它们本就是探针）。
3. **`ToolKind.colorPicker` 悬空**：枚举有、无注册无实现。要么注册（Capture 里已有取色器 `Eyedropper` 可包装成工具），要么删枚举值——二选一，别留半截。
4. **凭证审计无 UI**：`AICredentialJournalStore` 数据已落盘，但设置页没有查看入口，出安全争议时无从举证。
5. **OCR**：先观察本轮质量修复的效果；若小字/密集排版仍不行，走 §1.4 的方案 B（真正换模型 = 捆本地第三方），方案 C（AI 引擎）本轮已按要求撤掉。
6. **Ollama 本地线**：适配器齐（`/api/chat`、`/api/tags`、NDJSON 流），但设置页对「本地模型须支持的上下文/视觉」无校验提示——纯文本模型被拿去跑翻译/摘要没问题，将来若恢复视觉能力需要提示。
