## 2. 重复请求的真实链路

```
① 持续触发（最严重）
   FSStatsTick（0.5s，frset_stats_tick.m）
     → FSBarSystemTick（0.5s，frset_barwidgets.m:2605）
       → FSBarProbeMenuBarDarkAsync（2s 节流，:360）
         → FSBarSampleMenuBarDarkNow（:326）
           → CGDisplayCreateImageForRect（:335）   ← 屏幕录制 TCC API
   结果：App 运行期间每 2 秒触碰一次录屏权限。TCC 记录与当前 code identity
   一旦有偏差（自签名 / 重启 / 替换二进制），系统就会再次弹授权。

② 启动触发
   ScreenshotManager.init（:122）
     → probePermission（:195）
       → SCShareableContent.excludingDesktopWindows（:212）  ← 录屏 TCC API
   结果：每次启动 app 都可能弹一次。

③ 每次截图失败重复弹
   ensureScreenRecordingPermission（:229）
     → probePermission（可能失败）
       → CGRequestScreenCaptureAccess（:233） + NSAlert
   结果：未授权成功时，用户每点一次截图就弹一次，形成“反复请求、无法授权”。

④ 打开设置页也触发
   CaptureSectionView.onAppear（:38）→ refreshPermission（:174）
     → probePermission → SCShareableContent
```

## 3. 已修复（v77）

1. **删除 `CGDisplayCreateImageForRect` 及其 dlsym/后台采样**：
   菜单栏明暗改为「视图绘制上下文外观」（与 Stats 原生 `isDarkMode` 同源），
   `FSBarProbeMenuBarDarkAsync` 不再截图。C 侧唯一的周期性 TCC 触发点被移除。
2. **启动不再用 SCK 探测**：`ScreenshotManager.init` 只做 `CGPreflightScreenCaptureAccess()`
   （纯查询）；权威探测推迟到用户真正截图/取色时。
3. **`refreshPermission()` 只做 preflight**：打开设置页不再触发系统弹窗。
4. **`CGRequestScreenCaptureAccess()` 每次启动最多一次**，说明弹窗也最多一次；
   后续失败只显示 Toast（去系统设置），不再反复弹。
5. 录屏/截图的 `SCShareableContent`、`SCStream`、`SCScreenshotManager` 全部保留——
   它们是**用户主动操作**时才调用，不属于重复请求。
