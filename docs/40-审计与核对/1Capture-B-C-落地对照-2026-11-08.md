## 二、B 组逐项

### 9. 固定比例（可增删多组）

**1Capture 证据**：设置里的固定比例是一组可增删的条目，框选时锁死宽高比。做素材图、封面、头像时纯靠鼠标拖不出精确 16:9。

**实现**

- `CaptureAspectRatio`：`width:height` 两个整数（不存浮点，避免 1.7778 反复比较时抖动）。
  预置 6 组：1:1 / 4:3 / 3:2 / 16:9 / 3:4 / 9:16。
- 用户输入 `16:9`、`16x9`、`1600×900` 都能解析，自动约分；同比例已存在则复用，不重复入表。
- `CaptureRatioStore.constrain(from:to:ratio:bounds:)`：**起点是锚点**，按拖拽方向（四个象限）生长，
  以投影更长的一边为准，另一边按比例推；推过屏幕边缘时整体收缩（比例不破）。
- 框选时按住 ⇧ = 临时正方形；比例优先于 ⇧。
- 尺寸气泡会显示 `2560 × 1440 · 16:9`。
- 设置页：`CaptureExtraSettings.CaptureRatioSettingsView`，可选「自由框选」、增删自定义。

**实测**：`16:9`，起点 (100,100)、拖到 (500,200) → 终点 (500,325)，实际比例 **1.778**。

### 10. 窗口截图多选

**1Capture 证据**：窗口模式可多选（`windows` / `selectedWindowId` 字段）。

**实现**

- 窗口模式下 **⌘ 单击** = 勾选/取消勾选（不立即截），选中窗口画强调色边框 + 序号徽章；
  **回车**或再单击 = 一次截完；Esc 取消。
- 每个窗口用 `SCShareableContent` + `desktopIndependentWindow` 单独抓（自动排除遮挡窗口）；
  SCK 失败才回退到覆盖层快照裁剪。
- 多张图纵向拼成一张：16pt 间隔、24pt 留白，背景跟随深浅色（浅 0.96 / 深 0.13）。
- 内存闸门：总像素 > 120MP 时等比缩（十张 6K 竖拼会到 300MP）。

**限制**：混选不同屏幕的窗口时，若 SCK 失败会退回「提交窗口所在屏幕」的快照坐标，
跨屏窗口可能错位——SCK 正常时不受影响。

### 11. 拖成文件的轻量角标

**1Capture 证据**：`HangingShelfImageDragWriter` + `DDShelfPreviewControl`，截图后就在手边，直接拖进别的 App。

**实现**（`CaptureDragBadgeController`）

- 88pt 缩略图 + 文件名，出现在鼠标所在屏幕右下角（`visibleFrame` 已扣 Dock 与菜单栏）。
- 拖出 → `NSDraggingItem` 写文件 URL（`public.file-url`），Finder / Slack / 编辑器都能接；
  拖拽期间**暂停倒计时**（拖到一半消失很难受）。
- 单击 = 复制到剪贴板；双击 = 在访达中显示。
- 停留 2–15 秒可配（默认 6 秒），窗口 `level = 4`、`nonactivatingPanel`，不抢焦点。
- 只在「保存 / 复制」这两种「我要拿去用」的动作后出现；区域截图走动作条时也出现。

**限制**：只保留最新一张（新截图替换旧角标），不做队列。

### 12. 文件名模板

**1Capture 证据**：命名是一整个小系统（时间戳 / 随机 / 序号 / 前后缀，57 条文案）。

**实现**（`CaptureFileName`）

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{yyyy} {MM} {dd} {HH} {mm} {ss}` | 时间片段 | 2026 / 11 / 08 / 13 / 27 / 07 |
| `{date} {time}` | 组合 | 2026-11-08 / 132707 |
| `{timestamp}` | Unix 秒 | 1794106027 |
| `{seq}` `{seq:4}` | 当日序号（每天重置，可补零） | 001 |
| `{random}` `{random:3}` | 随机数字串 | 775 |
| `{w} {h}` | 出图像素 | 2560 / 1440 |
| `{mode}` | 截图模式 | area / window / long / annotate |
| `{app}` | 当时前台 App | Xcode |

- 默认模板 `Screenshot-{yyyy}-{MM}-{dd}-{HH}{mm}{ss}-{random:3}`，**与 v263 的输出格式一致**，老用户不会被改名规则吓到。
- 清洗 macOS 非法字符（`:`→`.`、`/`→`-`），去掉开头的点（否则 Finder 里是隐藏文件），长度上限 180。
- 设置页有实时预览；占位符做成 chip，点一下追加到模板。
- `{w}{h}` 在截图、标注保存、美化、长截图、屏幕翻译、staging 深链六条链路都传了真实像素。

**第一版的 bug（已修，留档）**：`replacePattern` 按 `"{seq}"` 去找，而 `{seq:3}` 的冒号在**花括号里面**，
永远匹配不到；随后 `sanitize` 把冒号换成点，文件名里就留下了字面量 `{random.3}`。
现在按 `"{seq"` 前缀匹配，再解析可选的 `:N}` 或 `}`。修复前后的探针输出见 §四。

### 13. 静默识别 + 提示时长

**1Capture 证据**：`OCR_NOTIFICATION_DURATION`，识别完只弹通知、不弹窗。

**实现**（`CaptureOCRNotify` + `OCRNotePanel`）

- 识别完成 → 文本自动写剪贴板 → 顶部一条不抢焦点的小面板（图标 + 单行预览 + 「已复制到剪贴板」），
  2–12 秒（默认 4 秒）后淡出。
- 静默模式只影响「识别后」这一条路径；「复制并识别 / 复制并翻译」仍走完整结果窗（用户明确要看）。
- 文本仍进剪贴板历史（`onTextRecognized` 不变），历史检索不受影响。

**为什么不用系统通知中心**：`UNNotification` 的展示时长由用户「横幅样式」决定，App 改不了；
要「可配时长」只能自绘面板。

### 14. 钉图补三块

| 子项 | 状态 | 说明 |
|---|---|---|
| 工具条独立窗 | ⛔ | 工具条仍嵌在内容视图里 |
| 失焦不变灰 | ✅ | 钉图窗口本来就是自绘 chrome（`.borderless` + 自绘按钮），没有系统标题栏，不存在 1Capture 那个 `_hasActiveAppearance` 问题 |
| 池化 | ◐ | 窗口对象不复用（关闭即销毁）；有 `hideAll / showAll / closeAll`，v264 补了 `repinLast()`（⌃⌥P「重新钉住上一张」） |

**为什么不硬做独立工具条窗**：现有 `isSmallMode`（宽度小于阈值时隐藏工具条、只留关闭钮）已经解决了
「缩到 80pt 工具条被裁」这个真实问题；把工具条搬到独立窗口要同步位置、层级、气泡锚点、点击穿透，
收益是「小图也能看到工具条」，成本和回归风险不成比例。如果以后要做，入口在
`PinToolbarView` + `PinnedScreenshotContentView.layoutChrome`。

### 15. 图帘悬停顶边唤出

**1Capture 证据**：`HangingShelfRevealController`；
`SETTINGS_DDSHELF_HANGING_REVEAL_ON_HOVER = 鼠标悬停屏幕顶边时显示：`，
`..._DESCRIPTION = 离开后自动收起，保留暂存内容。`

**实现**（`CurtainRevealController`）

- 每块屏一条 **5pt 高**的透明热区，位置是 `visibleFrame.maxY` 往下 5pt —— 即菜单栏**下方**，
  不抢状态栏点击（v261 当时就是因此没做）。
- 鼠标进入 → `ImageCurtainController.show()`；随后 0.2s 轮询「鼠标是否还在热区或帘子窗口内」，
  离开 **0.8 秒**后才收起（避免从热区移进帘子的那一下被判定为离开）。
- 只在「图帘总开关 + 悬停唤出」同时开着时建窗口；关掉立刻销毁；屏幕布局变化自动重建。
- 安装幂等：按屏幕几何签名去重，启动时不会装两遍（第一版会，已修）。
- 默认**关**：它会在屏幕最上方多一条 5pt 的「鼠标陷阱」，必须是用户主动选的。

**限制**：那 5pt 内的点击会被热区吃掉（高度只有 5pt，正常点菜单栏不受影响）。

### 16. 马赛克「仅文本」

**1Capture 证据**：`ANNOTATE_MOSAIC_TEXT_ONLY`。

**实现**（`MosaicTextOnly` + `AnnotationCanvasView.mouseUp`）

- 开启后，马赛克笔触只用来**指定范围**：提交时取「与笔触相交的文本行矩形」，
  每行生成一条横向马赛克（直径 = 行高 + 6），行间空白与图标完全不受影响。
- Vision `VNRecognizeTextRequest`（accurate、关闭语言纠正、`minimumTextHeight 0.004`），
  按底图缓存（`textLineCache`），同一次编辑里反复刷不重跑。
- 笔触没碰到任何文本行 → 退回普通马赛克（不让用户以为工具坏了）。
- 底图被抹除工具替换时缓存与马赛克缓存一起失效。

**实测**：对一张 1645×559 的截图识别 **4 行文本 / 219ms**（含 Vision 初始化）。

**限制**：首笔会有约 0.2 秒的识别停顿；手写体、艺术字、极低对比度文字可能漏识别。

## 三、C 组逐项

### 17. 摄像头画中画

- `AVCaptureSession` + `AVCaptureVideoDataOutput`（BGRA），最新一帧存在 `latestCamera`（加锁）。
- 每帧用 Core Image 合成：按角（四角可选）与宽度比例（10–35%，默认 18%）算矩形，4:3 竖版，
  右下角为默认位。
- 权限：`NSCameraUsageDescription`（Info.plist 已加），未授权时**静默跳过**，录制照常。
- 只在「开启画中画」时才走合成路径；关闭时原始帧直通，零额外开销。

**未做**：圆角/描边遮罩、镜像、背景虚化。
**未实测**：本机有 MacBook Air 摄像头，但授权会弹系统对话框，没在无人值守时点。

### 18. 显示按键

- `CGEventTap`（`.cgSessionEventTap`，`.listenOnly`）跑在独立线程 + 独立 run loop；
  只监听 `keyDown` / 左右 `mouseDown`。
- 键名：修饰键拼 `⌃⌥⇧⌘`，特殊键映射 `↩ ⇥ Space ⌫ Esc ⌦ ← → ↑ ↓`，其余取
  `NSEvent.charactersIgnoringModifiers` 大写。
- 键帽条：最多 4 个，底部居中，1.6 秒 TTL；画布只有 720×110（×pixelScale），
  不做全画布绘制。
- 无辅助功能/输入监控权限时：`AXIsProcessTrusted()` 直接返回 false，**不弹窗、不申请**，
  只写一条日志，录制不受影响。

**实测**：合成帧里能看到 `⌘` `⇧` `K` 三个键帽（见 §四）。

### 19. 忽略 App 录制

- `SCContentFilter(display:excludingApplications:exceptingWindows:)`，
  按 bundle id 匹配 `SCShareableContent.applications`。
- 设置页「忽略的 App」：`NSOpenPanel` 选 `.app`，读 `Bundle.bundleIdentifier`，列表可增删，
  存 `recording.excludedApps`。
- 启动时日志打印 `排除 App=N`，可核对。

**限制**：App 级排除，不做到窗口级（1Capture 也是 App 级黑白名单）。

### 20. 点击动画

- 与按键共用事件源；点击记录全局坐标 + 时间 + 左右键。
- 每帧对 0.65 秒内的点击画两圈扩散环（主环 + 慢 0.14 的尾环），左键橙 `(1,0.42,0.28)`，
  右键蓝 `(0.28,0.62,1)`；画布 160×160，按点击位置平移合成。
- 只画按下，不画拖动轨迹（1Capture 的「圆环三段：按下/保持/抬起」也只覆盖按下）。

### 21. 录屏后期编辑器（STUDIO）

**做到哪**：`AVPlayerLayer` 预览 + 入点/出点两条滑块（不允许交叉）+ 导出时静音 +
`AVAssetExportSession`（HighestQuality，mp4，`shouldOptimizeForNetworkUse`）+ 导出后自动在访达定位。

**没做**：多段拼接、时间轴缩放、转场、字幕轨、光标美化、加速/倒放。
1Capture 的 STUDIO 有 207 条文案，是半个独立 App；残缺版不如直接用 QuickTime 剪。

### 22. 自定义工作流 + GitHub/Linear

**模型**（`CaptureWorkflow` / `WorkflowStep`）：一张有序步骤表，步骤类型 7 种：

| 步骤 | 参数 | 行为 |
|---|---|---|
| 保存到文件夹 | 路径 | 复制截图到该目录 |
| 复制到剪贴板 | — | PNG 写入剪贴板 |
| 识别文字 | — | OCR，结果进入上下文 `{text}` |
| 钉在屏幕上 | — | 调钉图管理器 |
| 上传图片 | 上传地址 / 字段名 | multipart POST，从响应里取 `url` / `data.url` / `data[0].url` |
| 新建 GitHub Issue | owner/repo / Token | `POST /repos/{repo}/issues` |
| 新建 Linear Issue | Team ID / API Key | GraphQL `issueCreate` |

- 上下文传递：`{name}` 文件名、`{text}` OCR 全文、`{url}` 上传得到的图片链接、`{date}` 时间。
- 某一步失败**只记日志并继续**——工作流不该因为图床挂了就不保存截图。
- 存储：`~/Library/Application Support/Kitnest/workflows/workflows.json`，权限 **0600**
  （含 Token，不写 UserDefaults 明文 plist）。
- 默认只有一条**禁用**的示例（保存 + 识别 + 复制），用户不开就没有任何开销：
  `imageCaptured` 里先 `filter { $0.enabled }`，空数组直接 return。
- 触发点：`AppBootstrap.wireEventBuses` 的 `onImageCaptured`（与剪贴板入库、图帘同一处）。

**限制**：没有重试/断点续跑；上传端点必须返回 JSON 且含 `url` 字段；
GitHub 不能直接附图（需要先配图床拿 URL，issue 正文里引用）。
