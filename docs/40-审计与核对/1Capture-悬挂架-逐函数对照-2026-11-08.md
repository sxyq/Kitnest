## 〇、方法说明

### 静态

- 全量反汇编：`objdump -d --macho --no-show-raw-insn thin_arm64 > oc_full.txt`（117 MB，约 190 万行）
- 字符串地址换算：`vmaddr = 0x100000000 + file_offset`（用 `HangoCapture/HangingShelfWindow.swift`
  的 0xe8d810 ↔ 0x100e8d810 校验过）
- 常量还原：解析 `mov/movk` 拼 64 位立即数 + `fmov dN, xN`，还原成 double
- 局限：Swift 内部类型（`HangingShelfPresenter` / `Flight` / `Fall` / `Capacity` 等）的符号已被
  strip，只有源码路径字符串残留，**拿不到函数名**，只能靠调用图与字段名推断

### 动态（部分受阻）

- ✅ 拿到：主窗口 `700×500 @ (548,182)`、全部 UserDefaults 键名
- ❌ 受阻：1Capture 启动后弹出「设备控制和数据访问」授权（含「拖放架快速预览」），
  本机没给辅助功能权限，**无法点击 UI 把拖放架切到「悬挂」**，因此没能观察到运行中的货架
- 已写入偏好但未生效：`ddshelfStyle=3`、`ddshelfHangingRevealOnHover=1` 等，
  推断还缺一次「内容存在」的前置条件

## 二、已还原的常量（按类）

### 2.1 `HangingShelfRopeView`

见 `1Capture-交互特色与缺失清单-2026-11-08.md` 第六节，此处摘要：

```
y   = height - 12
sag = min(width * 0.018, 28)
curve(to: (w, y), cp1: (w/3, y-sag), cp2: (2w/3, y-sag))   // 三次贝塞尔
shadow: 黑 28%, offset (0,-1), blur 2
CLASSIC: white 0.62 @0.9 宽 2.0 + white 0.62 @0.5 宽 0.45
CANDY_CANE: white 0.997 宽 3.0 + red(0.86,0.03,0.16) 虚线
```

### 2.2 `HangingShelfCard.initWithFrame`（0x1006c89a4，实码在 0x1006c9100-0x1006c9e80）

**图层结构**（从 `addSublayer` 调用逆推）：

```
主 layer (偏移 0x840)
└── 图片层 (0x848)            ← 阴影挂在这一层
    ├── 内层 (0x850)          ← resizeAspectFill / 圆角25 / masksToBounds
    │   └── 0x858
    ├── 内容层 (0x860)        ← 圆角25 / continuous
    └── 渐变层 (0x868)        ← CAGradientLayer
```

**阴影**（0x1006c9830-0x1006c9858）：
```
shadowOpacity = 0x3E6B851F ≈ 0.23      (fmov s0, w8)
shadowRadius  = 9.0                    (fmov d0, #9.0)
shadowOffset  = (0, -5)                (movi.2d v0,#0 ; fmov d1,#-5.0)
```

**圆角**（0x1006c97a4 / 0x1006c9880 / 0x1006c98e4）：
```
cornerRadius = 25.0   ×3 处（主层 / 内层 / 内容层）
cornerCurve  = kCACornerCurveContinuous
masksToBounds = true
```

**渐变层**（0x1006c9910-0x1006c9c54）：
```
colors    = [white 0.62, white 0.94, white 0.80, white 0.61]   四色，alpha 均 1.0
locations = [0, 0.36, 0.68, 1]
startPoint = (0, 0.5) → endPoint = (1, 0.5)                   水平方向
cornerRadius = 3.0
borderWidth  = 0.5
```

> 四个颜色 alpha 都是 1，所以它不可能是「叠在截图上的高光」——那样会完全遮住图。
> 从层级看它挂在图片层下、并且在内容层之后添加，最合理的解释是**占位底色**
> （没有截图/缩略图未就绪时显示），或者是给文字卡片用的底。
> 我们据此把它复现成「缩略图未解码时的占位渐变」。

**控件**（`layout` 0x1006c1f50-0x1006c1ffc）：
```
关闭按钮  9 × 26  @ (midX - 4.5, maxY - 10)
工具条    22 × 22 @ y = maxY - 2
边框宽度  0.5 / contentsScale
```

**关闭按钮**（0x1006c9d70-0x1006c9e38）：
```
accessibilityLabel = NSLocalizedString("Close shelf item")
target/action      = dismiss
borderWidth        = 0
```

**其他字段**：卡片里有一个 `UUID`（0x1006c95cc `UUID.init()`），是 item 的唯一标识。

### 2.3 `HangingShelfMotionView` / `SurfaceView` / `DecorationsView`

三个都是**极薄的 NSView 子类**，只做一件事：
- `MotionView.makeBackingLayer`（0x1006c8bec）：只调 super，用来拿到自己的 layer 做摆动
- `SurfaceView.updateTrackingAreas`（0x100723ebc）：跟踪鼠标（悬停/跟随）
- `DecorationsView.hitTest`（0x100724120）：返回 nil，装饰层不接收点击

**结论**：这三层是为了「互不干扰」拆开的——装饰层不能挡住卡片点击，摆动层独立于内容层。
我们目前把绳子装饰画在 rope view 的 draw 里，点击本来就不冲突，但**摆动和内容在同一层**，
将来如果要「摆动不影响命中区域」会有麻烦。

### 2.4 `HangingShelfScrollView` / `ClipView`

两个类都只有 4–6 个方法，且都是 thunk，真实逻辑在私有函数里。
重写的方法说明它的滚动是**自己实现**的：

```
HangingShelfScrollView:  scrollWheel:
HangingShelfClipView:    bounds / setBounds: / setBoundsOrigin: / constrainBoundsRect:
```

即：滚轮事件被接管（横向滚动），`constrainBoundsRect` 限制回弹边界。
我们在 v262 里做了「宽度自适应 + 超宽裁切」，没有滚动。

### 2.5 `HangingShelfWindow`

```
styleMask = 0x80                     → 只有 nonactivatingPanel
canBecomeKeyWindow  = false
canBecomeMainWindow = false
sendEvent:           重写
willStartLiveScroll / didScroll / didEndLiveScroll  重写
constrainFrameRect:toScreen:        重写（可拖到边缘外）
```

**`didScroll`（0x100722ac8）** 就是「滚动时暂停摆动」的开关：
`isNativeScrollActive` / `isScrollInteracting` / `lastScrollOffset` / `scrollEndTask`。

### 2.6 `HangingShelfFlight` / `HangingShelfFall`（只有字段，没有方法）

```
HangingShelfFlight: from, to, imageLayer, window, completionTask
HangingShelfFall:   imageLayer, window
```

字段形态说明它们是 **fire-and-forget 对象**：`init` 里把动画跑完，用 `completionTask` 收尾。
两个类都持有 `window` 和 `imageLayer`，意味着**各自开一个独立窗口**做位移——
这就是为什么飞入/掉落能飞出主窗口范围而不被裁切。

反汇编里搜不到这两个类名（符号被剥离，类引用走 `__objc_classrefs` 的间接指针），
**具体时长与缓动曲线未能还原**。不做猜测。

## 四、我们缺什么（按性价比排序）

### A. 已有绘制层，补细节（半天）

1. **卡片内标注**（`HangingShelfAnnotationSession`）：在货架卡片上直接进标注编辑器，
   不用先钉图。我们的 `onPin` 已经能拿到图，接标注编辑器即可。
2. **工具条跟随鼠标**（`HangingShelfHoverFollow`）：卡片很宽时工具条跟着指针走，
   不用每次移到固定角落。
3. **位置可选**（`ddshelfPosition` 四角）：我们固定顶边居中。

### B. 要新窗口/新状态机（2–3 天）

4. **飞入动画**（`HangingShelfFlight`）：从截图选区飞到货架。需要 `CaptureEventBus`
   多传一个 `rect`。
5. **掉落动画**（`HangingShelfFall`）：移除卡片时向下掉出屏幕。
6. **顶边悬停唤出 + 离开自动收起**（`HangingShelfRevealController`）：
   热区在屏幕最上沿，需要处理与菜单栏的点击冲突。
7. **会话暂存**（`HangingShelfSessionStore`）：收起后保留每张卡的**剩余时长**，
   重新唤出接着算。我们现在收起后重新唤出会重置。
8. **横向滚动 + 回弹**（`HangingShelfScrollView`）：卡片超过一屏时横向滚动，
   而不是被窗口裁掉。

### C. 独立立项

9. **拖放架四态**（无/迷你/预览/悬挂）：它这是一整套「截图往哪放」的产品设计，
   悬挂只是其中一态。
10. **「拖动截图到顶边 + 空格预览」**：需要辅助功能权限。
