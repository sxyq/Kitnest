## 二、交互特色 Top 8（按用户感知强度排，不按成本）

### 1. 拖成文件：截图后留一个可拖的载体

- **1Capture 做法**：`HangingShelfImageDragWriter` 实现 `writableTypesForPasteboard:`，
  `DDShelfPreviewControl` 提供拖拽起点。截图不是「存到某处再去拿」，而是「就在手边，直接拖进 Slack/编辑器」。
- **解决什么**：省掉「打开文件夹 → 找文件 → 拖」三步。
- **我们**：v261 的图帘卡片已支持拖出（`beginDraggingSession`），但只在悬挂架开启时才有。
- **缺口**：v264 曾补「截图后右下角拖拽角标」（`CaptureDragBadge`），不依赖图帘；
  **v267 已按用户要求整套移除**（用户从未要求加这个预览窗）。现在截完只剩动作工具条与可选的图帘。

### 2. 到期自动收起，但内容不删

- **1Capture 做法**：`HangingShelfItem` 有 `deadline` / `configuredDuration` / `remainingDuration` / `dismissTask`；
  设置文案 `SETTINGS_DDSHELF_HANGING_DISPLAY_DURATION_DESCRIPTION = 到期后自动收起，暂存内容不会删除。`
- **解决什么**：既不会一直挡着屏幕，也不会因为「忘了处理」而丢东西。
- **我们**：v261 已实现同等语义（`displayDuration` + `orderOut` 不清 items）。

### 3. 悬停屏幕顶边唤出，离开自动收起

- **1Capture 做法**：`HangingShelfRevealController`；
  `SETTINGS_DDSHELF_HANGING_REVEAL_ON_HOVER = 鼠标悬停屏幕顶边时显示：`，
  `..._DESCRIPTION = 离开后自动收起，保留暂存内容。`
- **解决什么**：常驻的东西不占视觉，需要时一个鼠标移动就到。
- **我们**：v264 已做，热区放在菜单栏下方 5pt 窄条（`CurtainRevealController`），默认关闭。

### 4. 截图浮层的「微操三件套」

- **1Capture 做法**：`CAPTURE_NOTE_CAPTURE_RATIO_SQUARE`（按住截正方形）、
  方向键 + ⇧⌘⌥ 微调选区、空格拖动整体移动选区。这三条都在截图浮层上，不弹任何面板。
- **解决什么**：要精确 200×200 的图标截图时，纯靠鼠标几乎不可能对齐。
- **我们**：**都没有**。`ScreenshotOverlay` 只处理拖拽起止。

### 5. 双击左键动作可配

- **1Capture 做法**：截图完成后双击缩略图/浮层执行用户预设动作（拷贝/保存/钉图…），设置里可选。
- **解决什么**：把手最顺的那个动作变成默认，不用去点工具栏。
- **我们**：**没有**。我们的双击只用于「双击修饰键唤起」（`AppBootstrap` 的 2× 快捷键）。

### 6. 一张钉图 = 三个窗口

- **1Capture 做法**：`SnipPinWindowController` + `SnipPinToolbarWC` + `SnipPinAnnotateWindowController`；
  `Snip.PinWindow` 的 `_hasActiveAppearance` 返回 true（钉图失焦不变灰）、`canBecomeMainWindow` 返回 false。
- **解决什么**：图片缩到 80pt 宽时工具条不会被裁；钉图在别的 App 前也不会变灰。
- **我们**：`PinnedScreenshotWindow` 把工具条嵌在内容视图里，且没覆盖 `_hasActiveAppearance`。
- **缺口**：工具条独立窗口 + 不变灰 + 池化（隐藏全部/上次钉图）。

### 7. OCR 直接产出「变量名」

- **1Capture 做法**：5 种格式 `varName` / `var_name` / `VarName` / `VAR_NAME` / `var-name`，
  识别完一键转成代码里能直接用的标识符。
- **解决什么**：写代码时抄一个长变量名/常量名，这是真实高频场景。
- **我们**：**没有**。纯函数改造，成本极低，收益高。

### 8. 静默识别

- **1Capture 做法**：`OCR_NOTIFICATION_DURATION`（通知时长可配）；识别完只弹通知、不弹窗。
- **解决什么**：连续识别多张时不被窗口打断。
- **我们**：v264 已做（设置 → 截图与钉图 → 截完即用 → 静默识别），只弹 2–12 秒的小提示，文字自动进剪贴板。

## 六、图帘帘线的实测参数（反汇编还原，v262）

用户说「我们的 UI 形式和动效可能不合理」，于是把 1Capture 的
`HangingShelfRopeView` / `HangingShelfCard` 反汇编了一遍（类名是 1Capture 的原始符号）。以下都是
从指令里读出来的常量，不是猜的。

### 绳子几何（`drawRect` @0x100716a2c，path 构建 @0x100714a18）

```
y   = height - 12                    // 绳端距视图顶 12pt
sag = min(width * 0.018, 28)         // 下垂量按**宽度**算，与挂几张无关
curve(to: (w, y), cp1: (w/3, y-sag), cp2: (2w/3, y-sag))
```

- 是**三次贝塞尔**，不是二次。控制点落在 1/3 与 2/3 ⇒ `x(t) = w·t` 精确线性，
  所以「按 x 反解 t」不需要解三次方程（`ShelfRopeGeometry` 就靠这个）。
- 二次贝塞尔在中间会顶出一个尖、两端很陡；三次贝塞尔是两端平、中间垂，
  这才是真绳的形状。

### 描边（`stroke` 辅助 @0x100716920，每种样式各调一次）

辅助函数内部每次都新建 `NSShadow`：**黑 28%、offset (0,-1)、blur 2**，
然后设色 → 设线宽 → stroke。也就是说：

> 1Capture 靠**阴影**勾轮廓，而不是双色描边。

实测印证：我们原来用「深色底线 + 浅色高光」两层，浅色桌面上看起来是
两条平行线；改成阴影之后才是一根绳。

四种样式（对应 `HangingShelfRopeStyle`）：

| 样式 | 画法 |
|---|---|
| CLASSIC 原版 | 白 `calibratedWhite 0.62` @alpha 0.9，宽 2.0；再叠一道同色 @alpha 0.5、宽 **0.45** 的细芯 |
| CANDY_CANE 拐杖糖 | 白 0.997 宽 3.0 打底，再叠红色 `(0.86, 0.03, 0.16)` 宽 3.0 **虚线** |
| CHRISTMAS_LIGHTS 圣诞彩灯 | 细绳 + `CAEmitterLayer`（`emitterShape = line`，position `(midX, h+6)`，`birthRate = max(width/70, 4)`） |
| SNOW 积雪 | 绳 + 白色堆积（两个辅助绘制函数 @0x100714b14 / 0x10071509c） |

### 卡片

- `CGPathCreateWithRoundedRect(rect, 25, 25, nil)` —— **圆角 25pt**（写死）
- 描边 0.25pt
- 底部工具条 22×22，位置 `y = maxY - 2`
- `atan2` + `rotationAnchorPoint` / `rotationBounds` ⇒ **卡片沿绳线切线旋转**，
  不是一律垂直挂着

### 动效

- 每张卡有 `swayMotion` + `isInteracting` + `animationsActive`：
  常驻钟摆，交互时暂停
- 用十几处 `CAKeyframeAnimation`（`transform.rotation.z`），不是定时器重绘
- 进出场是两段独立窗口动画：`HangingShelfFlight`（新图飞入）/ `HangingShelfFall`（移除掉落）

### 我们据此改了什么（v262）

| 项 | 原来 | 现在 |
|---|---|---|
| 曲线 | 二次贝塞尔，单控制点 | 三次贝塞尔，控制点 1/3 与 2/3 |
| 下垂依据 | 卡片数量（`3 + n×1.2`，上限 10） | 宽度（`w×0.018`，上限 28） |
| 绳端位置 | `midY - 5` | 距顶 12pt |
| 可见性 | 深色底线 + 浅色高光两层 | 阴影（黑 46%，offset 1，blur 2.5）+ 白 0.72 主绳 + 0.85 细芯 |
| 卡片圆角 | 写死 7 | 宽度×0.09，钳 8…18 |
| 卡片姿态 | 一律垂直 | 按绳线切线倾斜（钳 ±4°） |
| 动效 | 落入摆一次就静止 | 落入回弹 → 常驻 ±0.7° 微摆，悬停/拖拽时暂停 |
| 两端 | 直接被窗口裁断 | 各留 5pt 画绳结 |

**为什么敢做常驻动画**：微摆只改 `transform`，不重绘内容，跑在
render server 上；实测两帧对比只有卡片区域像素变化（98,879 字节差异），
纯背景区域 0 差异，主线程零成本。用户「任何负载下不掉帧」的要求成立。
