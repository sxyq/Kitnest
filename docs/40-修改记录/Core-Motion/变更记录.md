### 2026-11-06 面板开合改成 Dock「神灯」漏斗——展开和收起同一套（d39e0309，v237）
- 需求/原因：用户「但是展开和收起都需要同样的呀，请你去实现一下尝试」。参照 raphaelsalaja/the-genie-effect（作者从 Dock 二进制反汇编出 Apple 网格函数），按同一公式用 Swift 重写，不引入原项目代码。
- 涉及文件与关键函数：Core/Motion/GenieMesh.swift（axis/timing/subdivide/build 四函数逐条对应；两段时序各由 log 距离决定 trunc(ln(d/2+1))×50ms；acos 解出「窗口前沿抵达图标」时刻）；GenieWarp.swift（抓窗口快照 dlsym CGWindowListCreateImage→隐藏真窗→全屏覆盖窗逐行重绘→放回真窗；快照按窗口圆角裁透明四角；每四边形拆两个三角形仿射贴图；Timer 60fps）；PanelController.show()/performHide() 先试神灯，抓不到快照自动退回缩放动画。
- 修改后行为：展开/收起统一神灯漏斗；收起回到本次图标格子（presentation.anchorRect）；无锚点路径兜 22pt 插槽。
- 已确认结果 / 未确认事项：实测修掉四个问题（快照 nil 重试、覆盖窗抢 key 致面板 992ms 后自关、flipped 视图 clip 整块裁没、漏斗顶盖住菜单栏图标）；实测展开 p 从 1.00 走到落位、面板正常可交互。未确认事项：无。时长三档 0.18/0.22/0.28 映射为 0.40/0.46/0.56（Dock 自身 500ms）。

### 2026-11-06 先逐帧渲染再逐帧播放，不再主线程现画掉帧（4d020e76，v238）
- 需求/原因：用户「整个动画非常闪退，没有做到一帧一帧地渲染，是一帧一帧闪现的」。实测：收起时主线程被 SwiftUI 重排占着，24 帧掉到 12 帧。
- 涉及文件与关键函数：GenieWarp.play()——一次性渲染整条动画成 N 张 CGImage，交给 Core Animation contents 关键帧（calculationMode=.discrete）播放；帧数 round(时长×60) 上限 30；像素倍率按 64MB 内存预算（实测 372×676@1.2x）。
- 修改后行为：播放跑在渲染服务器上，主线程再忙也不掉帧；28 帧时一帧一个刷新周期。
- 已确认结果 / 未确认事项：预渲染 28 帧 @1.2x 从 108ms 降到 73ms（整张先降采样）；probe.genieDuration=3 连拍三帧证明逐帧播放；抓不到快照/帧渲染失败自动回落缩放动画。未确认事项：无。

### 2026-11-06 收纳动画「重复播放+闪回」两处时序修复（8480f73e，v240）
- 需求/原因：用户「最新添加的一个收纳动画是有问题的……和之前动画重复播放，同时有闪回的现象」。两处独立成因：① finish() 先 alpha=1 再 orderOut，中间亮回来一帧；② hide() 的 0.6s 兜底二次进入 performHide（两个 guard 都放行）重播收纳动画，且第二次抓到透明窗。
- 涉及文件与关键函数：GenieWarp.finish()（收起直接 orderOut、alpha 留 0，下次 show 前统一重置）；hide() 兜底闭包捕获 hideGeneration 不一致即跳过；finish 提前返回时也清 isHiding（否则面板再也收不起来）。
- 修改后行为：收起无闪回、无重复播放。
- 已确认结果 / 未确认事项：三轮连续开合日志每轮展开 1 次/收起 1 次、无重复、无快照失败，预渲染稳定 28 帧/68–94ms。未确认事项：无。

### 2026-11-07 掉头改成时间反演——同一动画 speed=-1（30c75c4e，v248）
- 需求/原因：用户「随点随停，可以打断」「还是非常僵硬」「从哪来回到哪去」。原实现掉头=反转帧数组+重挂第二段 CAKeyframeAnimation，新腿从第 0 帧重新计时、速度曲线从头再来，物理上速度不连续。
- 涉及文件与关键函数：GenieWarp——帧序列固定不动、动画本体只挂一次；掉头时 legSpeed 取反、timeOffset 设到当前位置、beginTime 重置，同一条曲线从当前位置原速倒回。
- 修改后行为：位置/速度/曲线连续；连点 N 下就是 N 次原速反演，不累积误差。
- 已确认结果 / 未确认事项：build.sh EXIT=0；日志「genie 掉头 → 展开/收起：位置 X/Y ms，原速反演」。未确认事项：无。

### 2026-11-07 收缩抽搐真根因：CALayer 隐式淡变 + 索引差一帧 + 贴边假成功（6cb74c69，v257）
- 需求/原因：用户「它连续点击之后，收缩的时候还是会抽搐」。前几轮（v244/v248/v252/v254）都在改「动画怎么挂」，方向对但不完整。三处根因：① frameLayer 是手动 CALayer，contents 默认隐式 0.25s crossfade，与显式关键帧动画叠加（主因）；② 模型值索引用 t·(n-1) 与 keyTimes 的 floor(t·n) 差一帧；③ switchDirection 在 pos≈0 时 guard 返回 true 但什么都不做（贴边掉头假装成功），面板 alpha 停在 0、状态与画面脱节。
- 涉及文件与关键函数：GenieWarp——frameLayer.actions=["contents": NSNull()] + CATransaction.setDisableActions(true) 双保险；模型值统一 floor(t·n) 并 clamp 到 n-1；pos≈0 时按新方向 finish()。
- 修改后行为：收缩不再抽搐；贴边掉头真实结束。
- 已确认结果 / 未确认事项：build.sh EXIT=0；func_table 2,836 函数；docs/90-历史归档 已补三处根因与修法。未确认事项：无。
