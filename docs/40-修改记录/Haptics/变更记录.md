### 2026-11-23 补齐两项遗留验证：外接板选择逻辑、符号缺失回落（本次）
- 需求/原因：上一轮交付如实标注「外接 Magic Trackpad 实际震动未验证」「系统移除 MTActuator 符号时是否真回落公开接口未实测」，用户要求「继续完成」。本机无外接板可用，因此把两件事拆成「可验证的代码事实」与「必须硬件的体感」：前者现在做，后者如实留白。
- 涉及文件与关键函数：`Features/Haptics/TrackpadActuator.swift`——①设备选择抽成纯函数 `selectDeviceID(from:)`（`actuationDeviceID` 只负责枚举 IOKit 再交给它），行为不变、可脱离硬件验证；②`loadSymbols(at:)` + `frameworkPath`，支持 `--haptic-framework=<path>` 验证钩子（默认永远走系统真实路径，业务不传该参数）；③`openLocked` 四个失败分支统一记一行「马达直连不可用：<原因>，回落公开接口」——原来只在成功时记「马达直连就绪」，失败无声，用户排查时看不到原因。
- 修改后行为：设置页「仅向系统接口请求」的文案现在在日志里有同源证据；其余行为不变（同一套四符号、同一套 3/4/6 波形、失败仍只重开一次）。
- 已确认结果 / 未确认事项：用 `swiftc` 把上述源码 + `HapticDriver`/`HapticService`/`HapticConfiguration`/`HapticEvent` 与一个 `Log` 打印替身编成独立可执行文件（跑同一份源码，不重启主 App、不动前台焦点），两条路径各跑一遍：真实路径 `ready(0x7000000000000e7)` + `actuate` true + `privateActuated` + 文案「触控板马达已就绪…」；`--haptic-framework=<自建 dylib，仅含无关符号>` 时 `frameworkUnavailable` + `actuate` false 不崩 + `publicRequested` + 文案「系统不再提供马达私有接口…」。设备选择 6 例合成字典全过（内建优先/外接兜底/不支持排除/缺 ID 排除/空列表）。安装版已重建原子部署、签名通过、二进制含新钩子；运行中的旧实例未打断，**下次启动生效**。未确认事项：外接 Magic Trackpad 的物理震动仍需一块实体板（本机蓝牙列表无该设备，IORegistry 仅内建板）；「手离开触控板仍能感到」属主观体感，日志只能证明调用成功。

### 2026-11-23 触觉系统按功能模块重构：事件/配置/驱动/业务分离（4c62dd75）
- 需求/原因：用户「对现有触觉反馈系统进行一次完整的、以功能模块为边界的重构，解决此前多次修改后仍存在的触觉不生效、场景配置与真实行为不一致、设备兼容不足和代码职责混乱」「本次要重构真实实现，不是只调整触觉强度、增加日志或重新设计设置页面」。
- 涉及文件与关键函数：新增 Features/Haptics/{HapticEvent,HapticConfiguration,HapticDriver,TrackpadActuator,HapticService,HapticSettingsPane}.swift；删除 Core/Haptics/{HapticFeedback,TrackpadActuator}.swift 与 Features/Settings/Panes/HapticSettingsPane.swift；16 个业务文件调用点改 HapticService.shared.perform(...)。HapticEvent：18 类事件（rawValue 不变）+四类节奏；HapticConfiguration：解码无副作用、迁移挪出 init(from:)、HapticSettingsStore 内存快照；HapticService：总开关/场景/强度判断、按类型去重（边界 90ms/完成 250ms/里程碑失败 400ms）、跨事件 45ms 错峰延迟而非丢弃、专用串行队列；HapticDriver：私有 MTActuator 优先、失败回落一次 NSHapticFeedbackManager，设备状态区分就绪/仅公开接口/不可用；TrackpadActuator：隔离 MultitouchSupport 私有调用、init 不做 IO、dlopen 只一次、失败「关掉→重发现→重开一次」、唤醒后 invalidate 重建。
- 修改后行为：业务事件不再每帧 JSON 解码（旧实现网格拖拽每帧解码一次）；旧 60ms 全局节流改为延迟错峰（拖网格不再吃掉截图完成反馈）；试听按所选场景真实节奏演示并 Toast 明确「试听≠已接线」；无可用设备时禁用试听并如实说明。业务接线核查 85 处：18 类事件均至少一个真实触发点；Island 翻页误标 gridMove 两处已移除；搜索触觉改到显式提交才触发。
- 已确认结果 / 未确认事项：真机冷启动通过；马达直连就绪 id=0x7000000000000e7；probe.haptic 真实业务路径触发「网格吸附 类型=边界 强度=medium 结果=privateActuated」。未确认事项：振动是否真被感知未做人工体感确认，待用户实机。

### 2026-11-22 场景触觉改马达直连，设置页去说明并分组（92ba878a）
- 需求/原因：用户「这些场景的自动震动都没生效；右侧使用说明全部去掉；按钮要和顶部排列整齐；场景要分组」。根因：NSHapticFeedbackManager 只在手指贴着触控板时才响，而复制、截图、传输完成时手大多不在触控板上——「日志有请求、手上没感觉」。

- 修改后行为：手离开触控板也能产生触感；设置页分组与右缘对齐统一。
- 已确认结果 / 未确认事项：安装版探针日志「马达直连就绪 id=0x7000000000000e7」「触觉 网格吸附 强度=medium 波形=4 直连=ok」；麦克风录音 +3.48s 出现敲击瞬态（RMS 266，背景 65–107），手未接触触控板；设置页 940×1180 截图核对分组与对齐；reconcile 全绿。未确认事项：无。

### 2026-11-22 force-activate 三连发与激活诊断（c0677b37）
- 需求/原因：用户「是一点感觉没有的，你现在好像没有正确的触发」。根因：NSHapticFeedbackManager 只在 App 前台激活时真正产生触感，后台请求被系统静默丢弃；Kitnest 是菜单栏工具，大量交互发生在不激活 App 的浮动面板上。此前日志只有请求行，无法区分「被系统吞掉」还是「硬件无感」。
- 涉及文件与关键函数：HapticFeedback.emit 诊断日志记录 app=active/inactive 与 frontmost 应用名；simulate 先 NSApp.activate(ignoringOtherApps:) 再连发 3 次（间隔 0.18s）；新增 fireProbeIfRequested()（probe.haptic 触发启动后 2.5s 自动模拟，用完删键）；设置页状态行写明前台要求、三连发与硬件不支持判定口径。
- 修改后行为：模拟路径保证前台并三连发；日志可区分「被吞」与「硬件无感」。
- 已确认结果 / 未确认事项：探针实锤三连发 levelChange #1/#2/#3（间隔 0.18s）、app=active front=Kitnest；探针键已删；reconcile 全绿（4,268 函数）。未确认事项：若三连发仍无触感即硬件不支持 Force Touch（系统 API 无投递确认，无法程序化判定），设置页已写明口径。
