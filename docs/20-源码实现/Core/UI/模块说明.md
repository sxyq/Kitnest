## 模块职责

- **Support.swift**：`Log`（唯一日志出口）、`AppModule`/`ModuleRegistry`、`ServiceLocator`、`Theme` 个性化动态令牌、`Date/String/Data` 扩展（sha256）、`AppDirectories`。
- **ThemeTokens.swift**：无服务依赖的排版/圆角/间距/动效令牌（正式界面与独立展示包共用）。
- **LiquidGlassMaterial.swift / LiquidGlass.swift**：玻璃材质唯一工厂 + SwiftUI 玻璃背景族（结构面玻璃 / 卡片玻璃 / 按压悬停样式）。
- **AppearanceTheme.swift**：外观模式、Midnight 覆盖层、`frsetThemeChrome()` 统一主题入口。
- **Toast.swift**：屏幕中线下方的胶囊通知卡（菜单栏通知条，spec 13）。
- **官方 chrome 与手绘件**：`OfficialWindowChrome`（官方灰底窗口 chrome + 红绿灯策略）、`RoundCloseButton`、`ContinuousCorner`、`FlowLayout`、`PointingHandCursor`。

## 玻璃系统（2026-11-24 v293 重构）

职责四层，代码里也只有这四处：

| 层 | 位置 | 说明 |
|---|---|---|
| 参数解析 | `LiquidGlass.resolve(_:appearance:)` | 纯函数：solid/降透明 → `windowBackground + withinWindow + active`；系统动态玻璃仅在 `focus == .systemDynamic` 且 `uiUseSystemGlass` 允许时成立；其余 `visualEffect + .inactive`。输出 `Resolved`（后端/材质/混合/状态/圆角/着色/外观）与 `signature` |
| 实际后端 | `GlassHost` + `makeBackend` | 只有这里 new `NSGlassEffectView` / `NSVisualEffectView`。**后端真变才替换对象**；着色/圆角/普通透明度变化复用现有对象 |
| 着色与内容 | `GlassTintLayerView` / `GlassTintOverlayView` / `GlassSurface` | 毛玻璃后端用独立着色层消费 tint（与系统玻璃的 `tintColor` 语义对齐）；`GlassTintOverlayView` 是「通透度 + 磨砂」预合成的另一层（读 `Theme.glassTint`），不要和 tint 叠成两层黑幕/白雾 |
| 几何与生命周期 | `GlassHost.layout` / `UnifiedGlassBackingView` / `installUnifiedGlassBackground` | frame/圆角无变化就不赋值（AppKit 对 material/blending/state/frame 的重复赋值都会作废整窗采样） |

材质角色（`Role`）：`window → .underWindowBackground`、`panel → .popover`、`menu → .menu`、
`hud/island → .hudWindow`。旧实现所有结构面统一 `.hudWindow`，浅色外观下再压乳白着色膜
就是用户说的「灰雾 / 脏灰」；HUD 材质现在只留给真正的深色 HUD 与刘海外壳。

签名口径（`LiquidGlassBackground.signature`）：只含**真正影响底层材质**的输入
（解析后签名 + 外观 + 是否预览）。`glassOpacity / glassBlur` 只作用于着色膜，已从签名移除
——旧签名含这两项，拖一次「通透度」滑块就重套一次材质 = 整窗重采样。

已知边界：`NSGlassEffectView` 没有公开的焦点锁定口子。稳定档一律
`NSVisualEffectView.state = .inactive`（不虚构、不用私有接口）；系统玻璃是显式可选模式，
会随 key/inactive 变化。`uiUseSystemGlass` 是全局开关，不写 = 关。

## 入口与主要调用链

- **主题注入**：三个根视图（`PanelRootView` / `SettingsRootView` / `FloatingClipboardWindow`）各挂一次 `frsetThemeChrome()` = `.tint(Theme.accent)` + Midnight 注入；**漏挂 = 个性化/主题不生效**。
- **玻璃**：窗口/面板/浮层创建处 → `LiquidGlass.makeView` 或 `applyOfficialChrome(glassBacking:)`；SwiftUI sheet/自定义面板 → `LiquidGlassBackground`（`makeNSView` 异步把宿主窗置透明，否则 sheet 玻璃采样到白底）；卡片 → `WhiteGlassCard`/`GlassCard`（白渐变 + 斜向高光，不叠真玻璃）。
- **Toast**：`Toast.show(msg, icon, isWarning)` → 非主线程转发主线程 → `present`（代际 +1 → ensureWindow → 每次重新量尺寸定位 → spring 显形 → `toastDuration`（默认 3s）后 `hideAnimated` → 0.4s 后 `orderOut`）。
- **日志**：全工程 `Log.info/warn/error/debug/breadcrumb` → 同步写 stderr + `LogArchive`（见 [Core/Runtime](../Runtime/模块说明.md)）。

## 数据流与状态变化

1. **个性化 → 视觉**：`Personalization.shared` 的 19 个 `@Published` → `Theme` computed property 即时读取；`ThemeChromeModifier` 观察两个单例触发整棵子树重算（v193：玻璃通透度/磨砂/卡片亮度/描边四个滑块直接改表面令牌）。注意 `Theme.*` 是 computed property，**自身不触发重绘**，必须挂 `frsetThemeChrome()`。
2. **明暗**：`LiquidGlassBackground.syncAppearance` 读 `AppleInterfaceStyle`；卡片/文本用动态 NSColor（`Color.primary.opacity` 等）自动跟随；菜单栏部件侧明暗判定独立（见 [FrsetStatsBar](../../FrsetStatsBar/模块说明.md)）。
3. **Midnight**：不是自定义 NSAppearance，是 DarkAqua 之上的 SwiftUI 覆盖层（4 个 Environment 键），真正的 NSAppearance 应用在 Features/Settings/Panes（跨模块，不在此）。
4. **Toast 定位**：目标屏 = 面板窗所在屏 → 鼠标所在屏 → `mainScreen`；默认屏幕中线偏下 6%（2026-10-20 需求变更，弃原版 18.3% 底部公式）；`toastFollowPanel` 时贴面板下 8pt。

## 异常和取消处理

- **Toast 代际（`animationGeneration`）**：连续 `show` 时旧的 hide 回调作废，防"新通知被旧定时器关掉"。
- **玻璃不支持 / 降低透明度**：`makeView` 退化不透明 `windowBackground`；`material == .solid` 只影响**内容卡片**（2026-11-23 修正：不再拖累结构面）。
- **`Data.sha256Hex`**：统一 CommonCrypto（`CC_SHA256`）——历史手写 SHA-256 曾在 32KB 输入崩溃（`FrsetNext-2026-10-15-111300.ips`）；**改哈希实现必须用 `shasum -a 256` 对照空串/abc/1MB 三组向量**。
- **`RoundCloseButton.init(coder:)` 为 `fatalError`**（无 nib，安全但脆）。

## 性能边界（实测数字，来源标注）

- **玻璃重采样**（v282 注释，2026-11）：`reapplyStyle` 会作废整窗采样；数据刷新每秒触发 `updateNSView` 时无防抖 = 每秒重采样一次玻璃，是高负载"面板顿一下"的主要来源之一 → `LiquidGlassBackground.Coordinator.signature` 签名不变不碰材质。
- **玻璃图层数**（2026-11-24 实测）：结构面从「模糊 + 底衬 fill + 霜感 fill」三层降到「模糊 + 单层预合成着色」两层（`Theme.glassTint`，AppKit 侧同一层换成单个 CALayer）；预合成按 `A=a1+a2(1-a1)` 离线算，运行期零计算，按 通透度×磨砂×midnight 缓存。岛外壳另测：玻璃重建 12–16 次/次开合 → 2/0 次（见 Features/Island 模块说明）。
- **字号/对比度审计**（v153/v155 注释，2026-10 测绘）：曾查出 297 处 <11pt 字号、132 处 `.tertiary` 实测 3.2:1 不达 AA、圆角 9 种；`TextSize.caption=11` 是 HIG 下限；**连续循环动画只能线性**（旋转接缝速度不连续会"转一下顿一下"）。
- **`Date.relativeFormatter`**（v101/v260 注释）：DateFormatter 每次新建 0.5–2ms → 静态复用；v260 修"复用后仍每次改 dateFormat"的滚动掉帧。
- **`FlowHStack`/`ContinuousCorner`**：轻量纯函数，无缓存需求。
- **Toast**：单窗口复用不销毁；每次 show 重新 `fittingSize` 量尺寸（文案长度不同）。

## 已知限制 / 历史坑

1. **`.continuous` 圆角三路径统一**（v156）：SwiftUI `style: .continuous` / CALayer `cornerCurve = .continuous` / AppKit 手绘走 `NSBezierPath.continuousRoundedRect`——漏一个就是肉眼可见的圆角不一致。
2. **Toast 层级不能用 `.utilityWindow`**：必须 `CGWindowLevelKey(rawValue: 14)`（实测 2147483631；Swift 符号桥接成 19 会被普通窗盖住）。
3. **Toast/覆盖窗必须 `sharingType = .none`**（长截图曾把它截进去）；注释补充：ScreenCaptureKit 侧另按窗口 ID 排除提示卡。
4. **`attachOfficialRoundCloseButton` 三坑**：NSHostingView 不参与子视图约束求解（Auto Layout frame 恒 0）→ 手工 frame + 三次 `place`（挂载时 bounds 未布局）→ `isFlipped` 判定（判错挂左下角）。
5. **`toastFollowPanel` 的 clamp 退化**：面板贴屏幕上沿时 Toast 被 clamp 到屏幕底部（视觉"跳走"）。
6. **`reapplyStyle` 对 NSVisualEffectView 硬编码 `.hudWindow`**：丢调用方自定义 material（仅非 solid 分支，视觉可接受、语义不一致）。
7. **「背景材质 solid/vibrancy」曾是空转开关**（2026-11-24 修）：窗口玻璃恒定采样后没有分支消费它；现在它只决定**内容卡片**实/透（`GlassCard` → `readingBase` / `cardFill`），默认改为 `vibrancy`，旧默认值由 `ui.materialLookVersion` 一次性迁移，用户显式选择保留。
7. **`AppearanceState` 非严格单例**（public init，允许测试实例）：多实例会导致 `frsetThemeChrome()` 观察不到被写的那个。
