## 模块职责

- `FrsetNextApp`（`@main`）+ `AppDelegate`：进程入口。菜单栏常驻形态（`LSUIElement=1`，无 Dock 图标）、单实例护栏、`kitnest://` 深链分发、退出前 flush/确认、Dock 存在感维护。
- `InstanceLock`（v282 起）：对 `~/Library/Application Support/FrsetNext/instance.lock` 持 `flock` 的**唯一实例权威判据**，带心跳与"接管废实例"逻辑。
- `AppBootstrap`：唯一装配点——模块注册/启动、事件总线接线、默认热键、探针门、欢迎窗/WhatsNew/更新检查时序。

## 数据流与状态变化

1. **单实例判定**：`instance.lock`（flock + 写入 holder pid + buildStamp）→ `instance.heartbeat`（2s 一跳，mtime 即存活证据）。新实例抢不到锁时三判据决定是否接管：持锁者不是活的同 bundle 实例 / 构建戳更旧 / 心跳 >12s 未更新；接管前要求锁文件年龄 >3s（防双击误杀）；杀不掉则 `runningWithoutLock = true` 无锁启动（宁可偶发双菜单栏，不能"打不开"）。
2. **退出链**：`applicationShouldTerminate` → `ArchiveTaskQueue.confirmQuitIfNeeded()`（未完成归档任务可取消退出）→ `AppUpdateChecker.prepareToTerminate`（整包更新待装时批准退出）；`applicationWillTerminate` → `Personalization.flushPendingPersist()` → `LogArchive.stop()` → `AppBootstrap.stop()`（仅打日志，不摘热键/监听）。
3. **事件总线接线**（`wireEventBuses`）：`CaptureEventBus.onImageCaptured` → 剪贴板插图 + `bumpStat("screenshot_count")` + 图帘/自定义工作流；`onTextRecognized` → 插文本 + `ocr_count` + **消费截图翻译挂起标志**；`onColorPicked` → 插 HEX + `colorPickSuccess`；`AIEventBus`/`ToolboxEventBus.onResultProduced` → `ingestToolOutput`（AI 计数在 `LLMService.send`、工具计数在 `ToolRegistry.run`，均不重复 bump）。
4. **截屏翻译会话**：`beginScreenshotTranslate()` 置挂起标志 → `captureAndOCR()` → OCR 回调里 `takeScreenshotTranslatePending()` 一次性消费 → `translateAndIngest` 译文回流剪贴板。

## 依赖关系

- **上游**：系统（NSApplication / Apple Event / NSServices / flock / proc_pidinfo）。
- **下游**：全部 Features 模块（App 层是唯一允许同时引用所有 Features 具体类型的地方）；Core/Runtime（`LogArchive`、`AppUpdateChecker`、`Personalization`、`ModuleRegistry`、`Preferences`）；Core/UI（`Toast`、`Log`）；Features/Haptics（`HapticService.start()`）。
- 跨模块协作只在本层接线（CONTRACT §1.3）：Clipboard/Capture/AI/Toolbox 之间不互相引用。

## 异常和取消处理

- **第二实例**：拿不到锁且持锁者健康 → 激活旧实例后 `NSApp.terminate`，`AppBootstrap.start()` 不执行（防止第二套 STATS 合并条）。
- **僵尸进程**：`isZombie` 用 `proc_pidinfo` 的 `pbi_status == 5` 识别（`NSRunningApplication` 与 `kill(pid,0)` 都会被僵尸骗过），不激活、不等待。
- **锁 fd 必须 `O_CLOEXEC`**（v283）：否则被 OCR helper / screencapture 等子进程继承，父进程退出后锁永不释放 → 下次启动永远抢不到。
- **深链**：全部窗口创建延迟到下一 runloop；未知 host 静默忽略。
- **退出**：归档任务未完成时 `terminateCancel`；`AppBootstrap.stop()` 无实际清理（有意保留，进程即将结束）。

## 性能边界

- `AppBootstrap.start()` 主线程同步跑完（模块启动期间 runloop 不 tick；`LogArchive` 的 10s 卡死预热期就是为它准备的）。
- 启动期延时链避免拥塞区（v111 实测启动 ~0.9s 拥塞）：欢迎窗 1.5s、WhatsNew 2.2s、面板预热 3s（v279：首开卡顿治理，离屏预布局一次，`probe.warmup=NO` 可关）。
- v143 取消 OCR 启动预热：预热会常驻 +54MB RSS（43MB ORT 运行时 + 10MB 模型，`dlclose` 不归还），改懒加载——**不要"优化"回去**。
- `ProcessInfo.disableAutomaticTermination`：LSUIElement 应用无窗口时会被系统回收（实测录屏收尾阶段进程消失）。

## 已知限制 / 历史坑

1. **Apple Event 上下文不能建窗口**——`application(_:open:)` 必须整体 async，否则 `_postWindowNeedsUpdateConstraints` 异常（最小视图也复现）。
2. **transient 面板打开前必须 `NSApp.activate`**——否则"打开即关"。
3. **`Settings` scene 只能是 `EmptyView()`**（v85）：SwiftUI Settings 空窗与自管窗同时布局 → `NSHostingView.layout → GeometryReader → layout` 主线程死循环。⌘, 必须走 `commands` 转发。
4. **菜单栏监控只允许 STATS 合并条一套**（v43 不变量）：同 bundle 多实例必须退出；原版 `com.maoux.frset` 在跑只能提示，进程内无法阻止。
5. **InstanceLock 的 fd 泄漏路径**（v283 复盘）：不带 `O_CLOEXEC` 时子进程继承 fd，表现为"App 打不开、重装也没用"。
6. `AppBootstrap.stop()` 只打日志（不摘热键/监听/flush），与 `start()` 严重不对称——进程结束兜底，非通用 teardown。
7. `setShortcut` 失败时不写 defaults（冲突组合键不被记住），用户会觉得"点了没反应"，需要 UI 提示（未做）。
