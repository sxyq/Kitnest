# FrsetStatsBar（feature_id: STATSBAR）

> 菜单栏监控的唯一实现（STATS 引擎）：C/ObjC 部件绘制与合并条布局、0.5s 采样 tick、录屏、PP-OCR 的 ONNX 封装、传感器名表与小猫帧资源。对应源码：apps/FrsetNext/Sources/FrsetStatsBar/（14 个文件 / 9,054 行，6 头 + 5 `.m` + 3 `.c`，无 SwiftUI）

## 模块职责

对标原版 Stats 注入引擎的重建（原样移植 + 适配）：

- **部件引擎**（`frset_barwidgets.m`）：16 种部件形态绘制、合并条/独立条双模式布局、状态项保邻与位置校准、`widgets.plist` 配置存储（与官方 Stats 域互通）、奔跑小猫主图标覆盖层。
- **采样**（`frset_stats_tick.m` + `frset_stats_data.c`）：0.5s 主循环填 `g_snap`（CPU/内存/网络/磁盘/电池/GPU/温度/负载/功耗），SMC 直连、ICMP 连通性、nettop 分进程流量、NVMe SMART、IOReport 能耗。
- **录屏**（`frset_recorder.m`）：ScreenCaptureKit + AVAssetWriter（H.264/AAC、GIF 转码、区域框选、计时窗、完成面板）。
- **OCR 桥**（`frset_ocr_onnx.m`）：ONNX Runtime 的 dlopen 封装（PP-OCR 逐行识别），供跨进程 OCRHelper 复用。
- **数据**：`frset_sensor_names.c`（212 项传感器名表）、`frset_runcat_frames.c`（小猫 5 帧 × 黑白 PNG 字节数组）。

## 入口与主要调用链

**构建**（`build.sh`）：`*.c|*.m` 先 `clang -c` 成 `.o`，再与 Swift 一起 `swiftc` 链接，桥接头 `FrsetStatsBar.h` 唯一 `-import-objc-header`；`MemoryHelper/main.swift`、`OCRHelper/main.swift` 排除出主 App 文件集，单独编译签名（**必须在主 App 签名之前**）。

**0.5s 采样主循环**

```
NSTimer 0.5s（mainRunLoop, .commonModes）                 [frset_stats_tick.m:FSStatsTickStart]
 └ @autoreleasepool
    ├ statsTick()
    │   ├ CPU/内存/loadavg（每拍）；net/disk/battery（隔拍=1s）
    │   ├ statfs 磁盘容量（每 60 拍=30s）
    │   ├ dispatch_async(UTILITY) frset_smc_scan（每 12 拍=6s，~150ms）
    │   │    └ atomic_store(s_sensorCountA) release ← 跨线程发布点
    │   ├ frset_power_sample（IOReport，功耗模块用）
    │   └ 写 g_snap（温度类过滤 + 最热回退）
    ├ FSBarSystemTick()（barwidgets.m:2737）
    │   ├ FSBarResolveNativeItems → FSBarReconcile（幂等重建，合并/独立双模式）
    │   └ FSBarRefreshValues（按模块 interval 调 refreshWithSnap）
    └ FSBarKeepAdjacentTick → 必要时主队列 setFrameOrigin（保邻）
```

**点击 → 打开监测面板**：`FSBarManager.openMerged:`（CGWindowList 取真实窗口 x，减 `kStatusItemFrameDX=32` 系统偏差，命中模块）或 `openItem:` → `FSBarOpenMonitor(idx)`（stats_tick.m）→ Swift 注册的 C 函数指针（`FSStatsSetOpenMonitorHandler`）。

**配置改动闭环**：设置页（Swift `Features/Settings/Panes/MonitorWidgetsPane.swift`，读 `FSBarSensorKeysList`）→ `FSBarCfgSet/FSBarGlobalSet`（`g_cfgGen++` + 全量写 `widgets.plist`）→ `FSBarReloadFromStore` → `FSBarReconcile` → `FSBarMergedLayout` → 系统重排 → 0.5s 后 `FSBarKeepAdjacentToMain`。

**录屏**：`FSScreenRecBeginFromSettings` →（区域模式）`FSRegionOverlayShow` → `FSRecEngine.start`（SCShareableContent → filter/config → 3 路 output）→ 首帧视频建 writer（H.264 + ≤2 条独立 AAC）→ 逐帧 append → `FSScreenRecStop` → finishWriting →（GIF）后台转码 → 完成面板。

**OCR（跨进程）**：主 App Vision 定位文本行 → 写 `FOCR1` raw + boxes.json → 起 `Contents/Helpers/FrsetOCRHelper` → 逐框 `PPOCROCR.recognize` → `FSPPOCRRun`（dlopen ORT）→ stdout JSON → 进程退出（ORT 内存整块回收）。

**内存优化（跨进程 + root）**：主 App → Unix socket `/var/run/com.sxyq.frsetnext.memory.sock` → MemoryHelper（`getpeereid` 校 UID）→ `kern.memorypressure_manual_trigger = 6<<16|4` → sleep 3 → **defer 复位 normal** → `/usr/sbin/purge`。

## 数据流与状态变化

1. **`g_snap`**：全局非原子结构体，主线程 tick 写 / 主线程 drawRect 读；后台 SMC 扫描结果经 `_Atomic s_sensorCountA` + `release/acquire` 发布（**配对不能拆**，否则读到半个数组）。
2. **配置**：`widgets.plist`（`~/Library/Application Support/FrsetStats/`）单文件存部件/录屏/位置锚（`NSPos_*`）/小猫开关；`FSBarCfgSet` 每次整表原子重写；`g_cfgGen` 递增是 `FSBarEnabledForms` 缓存失效的唯一机制（绕过 `FSBarCfgSet` 直改 `g_cfg` 必须手动 `g_cfgGen++`）。
3. **布局**：合并条 `FSBarMergedLayout`（spacing + 1pt 分隔线 + 各部件 `preferredWidth + 2*pad`）→ `mergedItem.length` 变化 → 系统重排 → **保邻两级**（屏幕口径 gap 目标 16pt ±6 → 窗口口径回退；连续 6 次无效升级完整校准：8 候选扫描 + 帧稳定闸门，60s 冷却、每会话 3 次上限）。
4. **宽度迟滞**：`stabilizeWidth` 变宽立即、变窄需 <稳定宽-4 且连续 4 次才收（迟滞带必须 4pt，v135 实测 6pt 时网络块锁死在峰值宽度）。
5. **小猫**：`FSRunCatTick`（10Hz，CPU EMA 7 档倍速，每 tick 最多 2 帧）→ `FSRunCatIconView` 覆盖主图标（隐藏原子视图 + 清 `button.image`）。

## 异常和取消处理

- **SMC/IOKit 失败**：`parse_value` 未知类型返 -9999、`plausible` 值域过滤、电池三条回退链（容量：AppleRawMax→BatteryData→MaxCapacity；温度：根→BatteryData→SMC TB1T/TB2T；功率：PPBR→电压×电流）。
- **录屏**：`stream:didStopWithError:` 系统停流回调 → `finishWithError` 收尾；`FSScreenRecStop` 带超时兜底；音频首帧 `CFRetain` 缓冲（SCK 音频比首帧视频晚到），session 开始后按时间戳补写。
- **OCR 名字所有权**：`FSPPOCRRun` 的 `inOwned/outOwned` 标志决定能否 `AllocatorFree`（给字面量名字 Free 会堆损坏，实测概率性崩溃）；新增 early-return 必须带齐三处释放。
- **MemoryHelper**：`defer { set(normal) }` 必须保留（不复位会**永久禁用内核真实压力处理**）；socket 单线程 accept + 60s 收发超时 + 白名单命令（`version`/`optimize-memory`，参数数校验防注入）。
- **位置校准**：`s_calibrating` 互斥 + `g_posCalibrating` 抑制位置恢复；全失败恢复 500。

## 性能边界（实测数字，来源标注）

- **0.5s 主循环**（A2 测绘 + v49 注释）：SMC 全量扫描 ~150ms/次必须后台（移回主线程立刻复现"菜单栏周期尖峰卡顿"）；nettop 每 5s 一次子进程（采样 ~1s）；ICMP 1 包/秒；`frset_proc_top` 进程表上限 512（`FRSET_PROC_CAP`，省 ~1MB 静态堆，超限按枚举序截断）+ 200ms 扫描缓存。
- **绘制**：SF Symbol 必须走 `FSBarSymbolImage` 静态缓存（每 `drawRect` 重建触发 CoreSVG 解码 ≈ 3.8MB 堆，v129）；文本坐标 `floor` 防半像素发虚。
- **配置写盘**：每次 `CfgSet` 整表 `writeToFile:atomically:`（当前 ~60 键可接受，禁止在这条路径加高频调用）。
- **`FSBarRenderFormPreview`**：逐像素扫 alpha 裁剪（w×h×4 次 getPixel），设置页每形态各跑一遍。
- **`FSBarLog`**：同步写盘 + 200KB 截断（`removeItemAtPath`），只允许 ≥5s 节流路径。
- **能耗采集**（v178 起）：IOReport 采样（CPU/GPU/ANE/DRAM/DCS/Package Energy 按 domain 聚合）+ 分进程 `Δnj/Δt` 功率（`frset_energy_pid_t.watts`）。

## 已知限制 / 历史坑

1. **自建状态项必须 `sendActionOn(MouseDown|RightMouseDown)`**（v14 根因）：默认 mouseUp 派发会被空内容按钮的状态栏跟踪取消 → 真机点击毫无反应。
2. **合并条命中测试常量是实测值**：AppKit 状态项窗口坐标偏 24pt、macOS 26 `NSWindow.frame` 再偏 32pt（`kStatusItemFrameDX`）——"若未来系统修正该偏差，把常量改 0"。
3. **`Preferred Position` 增益约 13:1**（ΔP 501 ↔ Δx 38）：按 gap 等量微调永远追不上，必须候选扫描 + 帧稳定性闸门；0.6s 早读会拿到系统"暂放位"误判成功。
4. **音频两源不能共轨**（`-12737`）；音频轨必须在 `startWriting` 前 addInput；`cfg.width/height` 有 480×320 下限。
5. **`proc_pidpath` 缓冲区必须 ≥4096**（512 时恒定返回 0，图标/归类全失效）。
6. **`ORT_DISABLE_TELEMETRY` 必须在 `dlopen` 前 `setenv`**（之后关不掉已建的 1DS 通道）。
7. **宽度迟滞带 = 4pt**：改大（6pt）实测数值变窄时永不收缩（"305 KB/s"→"29 KB/s" 落带内），网络块锁死历史峰值宽度。
8. **小猫覆盖层 `hidden=YES` 掉主图标全部其他子视图并清 `button.image`**：关闭时 `FSRunCatIconSetEnabled(false)` 不恢复 `button.image`（依赖 Swift 侧重建图标）。
9. **探针常量硬编码系统版本行为**（`kStatusItemFrameDX=32`）：macOS 27 若不再偏移会整体错位一个部件宽度。
10. **死代码/实验段**：`FSBarDebugClickProbe`（T1–T6 点击链路实验，触发即冻结 UI >20s）、`FSBarDebugPosProbe`（两处 `sleep(1.5)`）、`FSBarProbeMenuBarDarkAsync`（v77 起空实现但每 0.5s 仍调）——均仅探针触发，勿在生产路径复用。
11. **MemoryHelper socket 无并发**：`optimize-memory` 期间（≥3s + purge）整条 socket 阻塞，不是通用 IPC。
