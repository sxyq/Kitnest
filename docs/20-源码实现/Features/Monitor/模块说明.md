## 2. 核心类型说明

### 2.1 `MonitorModule`（`Sampling/MonitorModule.swift:6`）

`start()`：采样器 → `NetworkFlowTracker.shared.applyKeepAlivePreference()`（v191 分流常驻）→ 注册设置页（id "monitor"）→ `StatsBarEngine.start()` → `probe.batteryPage` 探针（3.5s 后开电池页）→ 独立窗预热。v42 起不注册官方 4 个独立状态项（菜单栏只用 STATS 合并条）。

### 2.2 `MonitorSampler`（`Sampling/MonitorSampler.swift:10`）

- 每 tick：`StatsDataProvider.refresh(uiActive:)` → `g_snap` 判有效 → `MonitorReader.readResult(needFull:)` → g_snap 覆写 5 组核心指标（v76 修「两套时间」）→ lock 内 append 7 环形缓冲 + scratch 双缓冲 → `MonitorExtra.update` → 主线程发 `sample/history/tick`。
- **四可见性闸**（合并即回归「两套时间」）：`setIslandActive`（新增，刘海岛）/ `setPanelActive`（独立窗）/ `setHomePanelActive`（主面板，由 `PanelController` 开合配对调用）/ `setSettingsActive`。UI 不可见间隔 `max(base, 5.0)`；`scheduleNext` WorkItem 内部必须重算门控（v73）。
- v128：`stop()` 连带 `frset_conn_set_active(0)`/`frset_net_top_set_active(0)` 关 C 层后台线程。v168：netIn/netOut 累计用 `&+=` 回绕加法。
- 遗留坑（仍有效）：`perCore` 硬编码 32 核上限；隐藏期累计流量按 `netBps × refreshInterval` 估算会偏小（M2）。

### 2.3 `MonitorReader` / `MonitorExtra`（`Sampling/MonitorReader.swift`）

系统直采（CPU 差分/host_statistics64/getifaddrs/IOBlockStorageDriver/AppleSMC 150ms 单飞/IOPSCopyPowerSources/PowerTelemetryData）。`readResult(needFull:)`：`needFull=false` 仍读内存（压力/交换/压缩不在 g_snap）。`MonitorExtra`：NSLock 旁路快照（峰值/累计/压缩/负载），每读取一属性取一次锁（M1）。`delta` 回绕返回 0。

### 2.4 `StatsDataProvider`（`Sampling/StatsDataProvider.swift`）

四档节流：每帧（内存构成/连通性）、`heavyDue`（GPU/集群/电池）、`slowDue`（磁盘容量/SMART/网络 Top/本地 IP）、`scanInterval`（`frset_smc_scan(600)` 传感器全量）、`procInterval`（3s/15s 进程排行）。`readProcList` 静态 512 项 `frset_proc_t` 缓冲（v129）+ `lastOrders` 稳定排序（同桶沿用上轮名次）。不变量：`refresh` 只允许采样队列调用；`category` 必须用扫描层 `raw.category`（官方名表 `type` 口径不同，曾致「BDAT 显示 5388°」）。

### 2.5 `NetworkFlowTracker`（`Sampling/NetworkFlowTracker.swift:37`，v191 新增）

- 10 分钟滑动窗口（`windowSeconds = 600`）：nettop 差分速率**按时间积分成字节**，按 App 累计；`NetworkFlowEntry`（down/upBytes + live 速率）。
- 数据源：分应用 `procNet`（diskRead=下行/diskWrite=上行）；整机后台节拍读 C 引擎速率。单值上限 10Gbps 防脏数据。
- `applyKeepAlivePreference()`：常驻开则不依赖监测页可见性（用户：「一直放在那，只是会变化显示的 App」）；覆盖不足 10 分钟时 UI 显示已统计时长。
- 消费方：`MonitorDetailView.networkFlowNodes`（v181 流带，Top N + 「其他 N 个」聚合，512 B/s 噪声阈值）。

### 2.6 `MonitorDetailView` 家族（`Views/MonitorDetailView.swift`）

- `MonitorDetailSelection`（`:7`）：`@Published module`，独立窗与主面板共用实例（`MonitorCenterPresenter.shared.monitorSelection`）。
- `MonitorPerformanceContent` / `LiveMonitorPerformanceContent` / `MonitorPresentation` 环境（`:13`，预览值注入——设置窗预览用）。
- `MonitorDetailContent`（`:128`）：模块切换（`FlowHStack`）+ 功耗/CPU/内存/网络/磁盘/温度/电池/GPU 八区 + v181 可视化数据整形 + footer。**不变量**：主面板性能页与独立窗除 `topInset` 外必须一致。
- 陷阱（仍有效）：`modulePicker` 不得包进 `ScrollView`（v82 点击被吞）；选中胶囊不得用 `matchedGeometryEffect` 放 `.background`。

### 2.7 `MonitorPopoutWindowController`（`Window/MonitorPopoutWindow.swift:30`）

- borderless 玻璃窗 380×640；内容高度驱动 resize（clamp 200…min(880, 屏高-40)，**顶边固定**）。
- 开合动画 v 新版走 `GenieWarp`（`playIn/playOut` 0.42s，失败退 CA 层动画）；预热与主面板同款「停屏外 + token 防串」（`warmupOnScreen`/`warmupToken`，3s 错峰）。
- `isVisible` 排除预热态（`!warmupOnScreen`）；`appearToken` + `isDismissing` 双机制；`dismissPopout` 200ms 硬兜底（CATransaction completion 不执行的历史 bug）；`resetToken` 滚顶；`MonitorPopoutPanel.canBecomeKey = true`。
- `windowDidResignKey`：`NSApp.isActive` 时不关（本 app 换 key）；`FRSET_PANEL_PIN` 放行；否则 `TransientWindowCenter.requestDismiss`。

### 2.8 `StatsBarEngine`（`StatusBar/StatsBarEngine.swift`）

C 引擎桥：`start()` 幂等（v126 observer 注册顺序防重复 Toast）→ `FSStatsTickStart` → 0.5s 空隙探针（静息降频 2s）→ `syncMainItem`（0.2s×10 重试）。`openMonitor(index:)` 判定树：已开同模块=关（v63）、异模块=`showModule`；未开且 `wasJustDismissed` 同模块=保持关闭。`FRSET_STATSBAR_PROBE` 六种排障探针长期保留。

### 2.9 Memory/*

- `MemoryHelperClient`：socket `/var/run/com.sxyq.frsetnext.memory.sock`；`send` 校验 `getpeereid` UID==0；`install` 12 条命令 AppleScript 管理员串联 + 30×200ms 轮询。坑：`client.json` 写死 uid 从不更新（换用户需重装）。
- `MemoryOptimizer`：`@MainActor` 串联基线→optimize→1s→复测→报告；`MemoryOptimizationReport` ≥32MB 才「可感知」。
- `MemoryBreakdown` / `ProcessMemoryInspector` / `MemoryOptimizeSection`：口径与 UI 见深读笔记 §2.17（语义未变）。

### 2.10 其它

- `MonitorPreferences`/`MonitorModuleID`：8 模块（memory/network/disk 默认开）；`refreshInterval` 钳 `[0.5,10]`。
- `MonitorCharts`：`MonitorTrendChart`（NSViewRepresentable AppKit 绘制）+ Sparkline/Ring/StackedBar/语义色。`StatsRing`（StatusBar 侧）与 `MonitorRing` 双实现并存。
- `BatteryEnergy` / `DiskVolumes` / `MonitorFlow` / `MonitorCPUViews` / `MonitorNetworkViews`：能耗口径、卷列表、流带/热区/磁盘空间可视化、CPU 硬件信息与核/集群图、吞吐卡片。

## 3. 关键数据流

### 3.1 采样主链（每 tick）

```
DispatchWorkItem（com.frset.monitor.sampler, interval = uiActive ? base : max(base,5)）
  → MonitorSampler.sampleOnce()
      ├─ StatsDataProvider.refresh(uiActive:)   [C 层四档节流 + conn/nettop active 置位]
      ├─ g_snap 有效？→ readResult(needFull:false) : readResult(needFull:true)
      ├─ g_snap 覆写 CPU/内存/网络/磁盘/电池（菜单栏与面板同一时刻同一组值）
      ├─ lock: buffers×7 + scratch 回填 → MonitorExtra.update
      └─ main: sample/history/tick → 全部 @ObservedObject 视图
```

### 3.2 菜单栏部件 → 独立窗（神灯）

```
C 部件点击 → statsBarOpenMonitorTrampoline → StatsBarEngine.openMonitor(index:)
  ├─ 已开：同模块 dismissPopout / 异模块 showModule
  └─ open(module:anchor:) → GenieWarp.playIn(slot=部件格)
        + TransientWindowCenter.register + setPanelActive(true)
收起：GenieWarp.playOut + finishDismiss（token 幂等）+ setPanelActive(false)
```

### 3.3 网络分流（v191）

```
nettop 差分（procNet）/ C 引擎速率 → NetworkFlowTracker 滑动窗口积分（10min）
  → Snapshot.entries（按累计字节排序）
  → MonitorDetailView.networkFlowNodes（Top N + 聚合 + 512B/s 噪声阈值）→ MonitorFlow 流带
```

## 5. 不变量与陷阱（现行）

1. 四可见性闸（island/panel/homePanel/settings）必须独立；`homePanelActive` 由 `PanelController.show/performHide` 配对置位。
2. `scheduleNext` WorkItem 内必须重算门控（v73）；`stop()` 必须关 C 层 conn/nettop（v128）。
3. `g_snap` 有效必须覆写核心指标（v76「两套时间」）；`needFull:false` 仍读内存。
4. SMC 单飞 + 150ms 超时；`StatsRing` inset + GeometryReader 内禁注入 environment（v84/v85 死循环）。
5. `modulePicker` 禁 ScrollView 包裹 / matchedGeometryEffect 进 `.background`（v82）。
6. 独立窗：`isDismissing`+`appearToken` 双机制、200ms dismiss 兜底、`canBecomeKey`、`resetToken` 滚顶均不可去；神灯路径 `warmupToken` 防「预热收尾把刚打开的窗藏掉」。
7. `readProcList.ChildRec.idx` 依赖 `procBufferLock` + 仅采样队列调用；传感器 `category` 用 `raw.category`。
8. `MemoryHelperClient.send` 的 `getpeereid(uid==0)` 不能删（防同机伪造）；`StatsProcTable.expandedIDs` 用 `groupKey` 非 pid；`StatsAppIcon` 只缓存成功结果（v86）。

## 6. 重复实现 / 死代码 / 风险（现行）
