# Capture/Workflow —— 截图工作流模块说明（feature_id: CAPTURE）

> 截图后自动执行步骤链（保存→OCR→上传→GitHub/Linear Issue），对标 1Capture 的自动化。对应源码：`apps/FrsetNext/Sources/Features/Capture/Workflow/`（**2** 个 `.swift` / **719** 行，2026-11-23 实测）。
> 源笔记：无（v264 新增，深读笔记未覆盖）。本说明读当前源码撰写。

## 模块职责

提供"截图后自动执行一串动作"的能力。不做可视化编排器，而是一张有序步骤表——90% 的真实需求是：保存到某处 → 识别文字 → 上传图床拿 URL → 建一个 GitHub / Linear issue。步骤之间用**上下文**传递产物（文件 → 文本 → 图片 URL），后面的步骤能引用前面的结果。

## 目录与主要类型

| 文件 | 关键类型 | 职责 |
|---|---|---|
| `CaptureWorkflow.swift` (527) | `WorkflowStep`（Codable, Identifiable）、`WorkflowStep.Kind`（enum: save/copy/ocr/pin/upload/github/linear）、`CaptureWorkflow`（enum 引擎）、`WorkflowContext` | 步骤定义 + 执行引擎 + 上下文 |
| `WorkflowSettingsPane.swift` (192) | `WorkflowSettingsPane`、`WorkflowSettingsModel` | 设置页（步骤编辑/排序/启停） |

### WorkflowStep.Kind 七种步骤

| Kind | 职责 | 产物 |
|---|---|---|
| `save` | 保存到文件夹 | 文件路径 |
| `copy` | 复制到剪贴板 | — |
| `ocr` | 识别文字 | 识别文本 |
| `pin` | 钉在屏幕上 | — |
| `upload` | 上传图片（自建/图床） | 图片 URL |
| `github` | 新建 GitHub Issue | Issue URL |
| `linear` | 新建 Linear Issue | Issue URL |

### 模板占位符

`{name}`（文件名）、`{text}`（OCR 文本）、`{url}`（上传 URL）、`{date}`（日期）——写在 GitHub/Linear 的标题/正文里。

## 入口与主要调用链

```
截图完成（handle() 收尾阶段）
  → 若已配置工作流 → CaptureWorkflow.run(image:url:context:)
  → 逐步执行 WorkflowStep
      ├─ save   → ScreenshotManager.savePNG（到指定目录）
      ├─ copy   → ScreenshotManager.copyToPasteboard
      ├─ ocr    → OCRService.recognizeText（thorough）
      ├─ pin    → PinnedScreenshotManager.show
      ├─ upload → HTTP 上传（自建/图床）→ 取 URL
      ├─ github → GitHub API（Keychain 凭证）→ 建 Issue
      └─ linear → Linear API（Keychain 凭证）→ 建 Issue
  → 上下文传递：前一步产物写入 WorkflowContext，后续步骤的模板可引用
```

## 数据流与状态变化

```
WorkflowContext（var）
  ├─ fileURL: URL?      （save 步骤产出）
  ├─ recognizedText: String?  （ocr 步骤产出）
  └─ imageURL: String?  （upload 步骤产出）
每步执行完 → 写入 context → 下一步的模板渲染时替换占位符
```

工作流配置存 `UserDefaults`（JSON 序列化的 `[WorkflowStep]` 数组），不含凭证。GitHub/Linear 凭证由 **Keychain** 保存（不落 JSON）。

## 异常和取消处理

| 场景 | 处理 |
|---|---|
| 单步失败 | 中断链并记录日志（不回滚已完成步骤） |
| 网络超时 | GitHub/Linear/upload 步骤使用标准 URLSession 超时 |
| 凭证缺失 | github/linear 步骤直接失败，提示去设置页配置 |
| 模板占位符无对应产物 | 渲染为空串（不报错） |

## 性能边界

| 项目 | 数字 | 来源 |
|---|---|---|
| OCR 步骤 | 几百 ms–1s | OCRService 标准耗时 |
| GitHub/Linear API | 网络延迟主导（百 ms 级） | 一般 REST 调用 |
| 工作流配置读取 | UserDefaults JSON 解析，微秒级 | — |

## 已知限制 / 历史坑

1. **步骤失败不回滚**：已执行的步骤（如已保存的文件、已建的 Issue）不撤回。
2. **凭证存 Keychain**：与 `CredentialStore`（AI 模块的加密文件）不同体系，各自独立。
3. **`upload` 步骤的图床协议**：依赖用户配置的上传端点，无内置图床。
4. **工作流配置无上限**：步骤数量不限，但实际建议 ≤10 步（串行执行）。
5. **v264 新增，未经深读笔记覆盖**：函数级细表需读源码。
