## 2. 入口与主要调用链

### 2.1 区域截图（最主链路）

```
⌥S / 面板按钮 / 菜单栏 / 深链 region
  → CaptureModule.capture(.area)                 [埋点]
  → ScreenshotManager.captureRegion()
  → ensureScreenRecordingPermission()
  → beginRegionCapture()                         [@MainActor]
      ├─ ScreenSnapshot.streamScreenSnapshots()  [并发度 2，光标屏优先]
      │    └─ NativeRegionCapture.captureScreen  [screencapture -x BMP → 内存裁剪]
      │    └─ CaptureEpochCounter 代次校验        [连按取消旧任务]
      ├─ ScreenshotOverlayWindow × N（增量铺层，先冻结先铺）
      └─ 用户拖拽 → onCommit(rect)
  → commitRegion()
      ├─ ImageProcessor.crop（双轴倍率）
      ├─ savePNG → registerCaptured
      ├─ autoDetectQR（后台 Vision）
      └─ CaptureActionChain.present → 12 个工具之一
```

### 2.2 长截图（滚动）

```
动作条「长截图」/ CaptureMode.long / 深链
  → LongScreenshotCoordinator.beginSelection()
  → commitSelection → startSession()
      ├─ LongScreenshotSession（串行队列）
      ├─ LongScreenshotFrameStream（SCK 30fps）
      ├─ 定时采样 60–200ms → stitcher.append（NCC 对齐）
      └─ HUD + 边框窗
完成 → 复制 + LongScreenshotPreviewController.show
```

2026-11-27：结果编辑器的「保存」「复制」先在同一串行后台队列执行原PNG编码，再回主线程保存登记或写入剪贴板；按点击顺序提交结果，关闭窗口后已提交动作继续完成。现有2745×1365图编码21.80–22.82ms，输出字节与原方法相同；大长图和按钮交互待实测。

拼接器的完整画布、实时预览和灰度签名使用数组指针时，位图上下文的创建、绘制或makeImage均留在withUnsafeMutableBytes作用域内。真实2745×1365图三轮完整画布14987700字节、底部2745×500预览5490000字节及512×255签名与原方法相同。实时预览链已为画布尾部至多500行→卡片按槽位再裁底部，尺寸标签仍显示完整画布；滚动采集动态待实测。

`append` 在宽度归一化与原灰度签名判定之后才转换整帧RGBA：同一实际图像三组各12次静帧调用均返回unchanged，画布与状态相同，原均值0.79–6.18ms、新均值0.26–0.44ms，每次命中跳过14987700字节缓冲构造。Session的过期流帧跳过、NCC对齐、追加阈值和预览发布规则保持；会话CPU及峰值内存待实测。

`LongScreenshotFrameStream.start` 在创建Task前锁内固定启动代次；startCapture完成后同锁比较代次并发布stream/连接状态。stop在该锁内递增代次并清引用，先停止的旧启动走原stopCapture收流分支，connected跨队列读取也经该锁；30fps、选区倍率及排除窗口配置保持。快速取消及录制指示灯回落待独占时段实测。

## 4. 异常和取消处理

| 场景 | 处理 |
|---|---|
| 权限缺失 | `ensureScreenRecordingPermission`：preflight → SCK 权威探测 → 每启动仅一次 TCC 请求；后续只 Toast |
| 权限假阴性 | `CGPreflightScreenCaptureAccess` 可能假阴性（重签名/csreq 不一致）→ 改用 `SCShareableContent` 能否枚举 display 作权威判据 |
| 连按快捷键 | `CaptureEpochCounter` 终止上一轮 `screencapture` 进程 |
| 长截图失败 | 连续 3 次 `captureFailures` 判 failed；`streamStale`（静画面无帧）**不算失败** |
| OCR 空结果 | Toast 提示；`CaptureOCRNotify` 静默模式下只弹通知 |
| 延时截图取消 | Esc/Delete/右键（local monitor，仅本 App 前台时有效） |
| 标注未保存 | `windowWillClose` 把快照写回历史库 |
| 钉图 Esc | `PinnedScreenshotManager` local monitor `closeAll()`（已知副作用：不区分 key window） |
| 工作流步骤失败 | `WorkflowStep` 链式执行，单步失败中断并记录 |

## 6. 已知限制 / 历史坑

2026-11-27：`PinMenuView.setEntries` 沿原行模型准备12.5pt regular符号及两种固定灰度，图标随当前菜单行替换；`draw`直接复用，14×14位置、文字、勾选、箭头和原动画保留。原15种符号两色1x/2x离屏像素一致，同轮24次图标绘制49.98–58.41ms→2.35–2.92ms；首次符号初始化准备151.34ms，正式定向类型编译通过，窗口交互待独占时段。

1. **两条长截图实现并存**：`Stitcher`（多图手选拼接）vs `LongScreenshotSession`（滚动采捕）。`CaptureSectionView` 的「长截图」按钮走前者，`CaptureModule.capture(.long)` 走后者——同一个 `CaptureMode.long` 两个入口语义不同。
2. **`CaptureHistoryStore.init` 打不开 DB 直接 `fatalError`**：磁盘满/权限异常启动即崩。
3. **`PinnedScreenshotManager` Esc 全局 `closeAll()`**：标注编辑器里按 Esc 会先关掉所有贴图（monitor 不区分 key window）。
4. **主线程同步抓屏已缓解但未根除**：并发度 2 + 增量铺层改善了多屏体验，但 `NativeRegionCapture` 仍是同步 `Process` 调用（208ms）。
5. **`ObjectRemovalEngine.inpaint` 在 mouseUp 同步执行**：大笔刷连续涂抹累积卡顿。
6. **马赛克两套缓存**：`AnnotationCompositor.composite` 内部 `mosaicCache` + `AnnotationCanvasView.mosaicPixelCache`，不共享。
7. **`DelayedCountdownWindow` `ignoresMouseEvents = true`**：右键取消仅 local monitor 有效（本 App 前台时）。
8. **`AnnotationCanvasView` 撤销栈无上限**：`imageSnapshot` 持有整图，反复抹除 4K 图吃内存。
9. **`Eyedropper.pendingPick` 登记顺序**（先 `finish` 再登记）决定 continuation 是否悬挂——不可乱序。
10. **OCR 复核必须在所有合并之后**：先复核会被锚的原始文本覆盖。
