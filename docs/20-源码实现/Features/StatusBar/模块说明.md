# Features/StatusBar（feature_id: STATUSBAR）

> 菜单栏主图标总控（左键开面板 / 右键菜单 / 图标样式 / 拖放转入 / 暂停徽标）+ 统计窗（800×530 用量图表）。菜单栏**监测**组件不在本模块——唯一归属是 STATS 合并条（[FrsetStatsBar](../../FrsetStatsBar/模块说明.md)）。对应源码：apps/FrsetNext/Sources/Features/StatusBar/（7 个文件 / 2,044 行）

## 模块职责

- **StatusBarController**：主图标（`frsetnext.main`）安装与交互、位置持久化、暂停徽标、菜单动作分发。**v210 起动态状态项管线（StatusItemRegistry/溢出菜单/5s 同步）已整体删除**。
- **StatusBarMenuBuilder**：右键主菜单（v128 两段式缓存：结构按 revealed 分版本、勾选态每次现读）。
- **MenuBarIconStyle**：四种主图标样式（logo/fan/date/custom）+ `RotatingLayerView` 匀速旋转 + CPU 负载采样 + 样式应用器。
- **StatisticsRootView / StatisticsWindowController**：统计窗（5 指标卡 + 总览 + 30 天柱图 + 60×7 热力图）。
- **StatusItemDropProxy**：主图标上的拖放投放区（v250，文件拖入 → 转入）。
- **StatusBarModule**：`AppModule.start()` 装配入口。

## 入口与主要调用链

```
StatusBarModule.start → StatusBarController.install（主线程兜底、幂等）
 ├ installMainItem：variableLength 项 + 模板图 + 拖放层/暂停徽标
 │    └ StatsBarEngine.syncMainItem()（STATS 保邻参照物）
 ├ observePreferences：UserDefaults.didChangeNotification → 250ms 合并 → 样式/徽标刷新
 └ 交互：
     左键 → ServiceLocator.panel?.toggle(atAnchor: button.window?.frame)   （锚点展开）
     右键 → StatusBarMenuBuilder.mainMenu → popUp
     拖文件 → StatusItemDropProxy → 转入（云端/本地）
     暂停徽标 ← ClipboardManager.recordingPausedDidChangeNotification
     统计窗 ← 通知 frset.openStatistics → StatisticsWindowController.openStatistics
```

**统计窗**：`openStatistics` → 重建内容视图（数据/入场动画重放）→ 埋点 `statistics_open` → `StatisticsChartsView.onAppear → loadData`（后台 `autoreleasepool` 内跑 `StatisticsManager` Q1/Q2/Q3/Q4/Q5 + `clipboard_items COUNT(*)` → 主线程赋 7 个 `@Stored` + 一次性入场动画）。

**图标样式**：`MenuBarIconStyleApplier.start` 观察 `UserDefaults.didChangeNotification`（全量偏好通知，高频）→ `apply()`（`appliedStyle/appliedCustomSymbol` 守卫未变跳过）→ 按样式设图/标题/长度/定时器（date 60s / fan 2s CPU 采样 + `RotatingLayerView` 0.8–4.0s/圈 7 档变速）。

## 数据流与状态变化

1. **主图标状态机**：`installMainItem` **先清 `NSStatusItem Preferred Position`**（v71：钉死 322 会把整组挤出屏幕右缘）→ 系统自动排布；`autosaveName = frsetnext.main`（前缀隔离原版 Frset.app，同名会 frame=(0,0,w,0) 不显示）。
2. **暂停徽标**：`ClipboardManager.isRecordingPaused` → 右上角 7×7 `pause.fill` + tooltip 切换。
3. **统计数据**：每次 `openStatistics` 重建 → 5 条 SQL 全量重查（后台 + autoreleasepool）；`activityTotals` 用 `Dictionary(uniqueKeysWithValues:)`（**Q4 返回重复 day 会崩**，SQL `GROUP BY day` 保证）。
4. **热力图几何**：60 列 × 7 行、格 8pt、间距 3pt → 内容宽 60*8+59*3=657（咬合在 660 内容宽里，改任一常量都会溢出）。

- **下游/协作**：`StatsBarEngine`（FrsetStatsBar 的 Swift 封装：主图标参照物同步、合并条点击开监测窗）；`ClipboardManager`（暂停状态、拖放转入）；`StatisticsManager`/`DatabaseManager`（Storage）；`WelcomeWindowController`/`QuickTutorialController`/`IslandController`/`FavoritesWindowController`/`FloatingClipboardWindowController`/`ArchiveProgressWindowController`/`MonitorPopoutWindowController`（菜单动作目标，全部走公开入口或通知）。

## 异常和取消处理

- **菜单缓存**：`revealed` 变化会增删菜单项，缓存**按 revealed 分版本**；勾选态不缓存（每次读 Preferences），防串态。
- **fan 样式渲染**：必须 `button.image = NSImage()` 空图占位 + `setMainItemLength(30)`，否则旋转视图不渲染/被裁成「<<」（2026-10-16 实证）。
- **统计窗约束异常**：内容必须延后一个 runloop 装载 + 尺寸钉死（min==max），否则 `_postWindowNeedsUpdateConstraints`。
- **`StatusItemDropProxy.init(coder:)` 为 `fatalError`**（无 nib）。

## 性能边界（实测数字，来源标注）

- **主菜单两段式缓存**（v128）：改回"每次全建"会重新引入右键首帧卡顿。
- **样式应用器**（A3 缺陷记录仍部分成立）：监听**全量** `UserDefaults.didChangeNotification`，守卫前先做 4 次 defaults 读；窗口拖拽尺寸等高频写 defaults 场景会反复触发 `apply()`（有守卫但仍耗读取）。
- **统计查询**：5 条 SQL 在 `DispatchQueue.global(.userInitiated)` + `autoreleasepool`（v128：临时 NSNumber/NSString 池不排空会拖到 runloop 回收）。
- **旋转**：`RotatingLayerView` 走 CA 渲染线程（v49：弃 60fps Timer 逐帧写 transform，实测每帧触发 NSViewBackingLayer 重排）；变速时读 `presentation()` 当前角度续接（防跳相位）。
- **入场动画**：统计窗每次打开重建内容 → 全量重查 + 全量重绘（P3 级，见限制）。

## 已知限制 / 历史坑

1. **状态项同步递归环**（2026-10-16 EXC_BAD_ACCESS 实证）：`refreshTitles` 里改 `isVisible` → 系统写 defaults → `didChangeNotification` → 同步 → rebuild → …… 栈溢出。动态状态项虽已删（v210），但**任何在 defaults 观察回调里再写 defaults 的路径都要 `isSyncing` 防重入 + 异步出口**。
2. **双层项三件套**（STATS 实证）：长度 = 视图宽（否则裁成「<<」）+ `button.image = NSImage()` 占位 + 不设 title；位置键必须**创建前**写回（系统 removeStatusItem 时会删键）。
3. **`SystemCPULoad` 与 C 侧 `frset_cpu_sample` 是两套采样**（2s vs 0.5s，口径不同：Swift 只算 user+system / total）——fan 变速用 Swift 侧，勿与面板数字对账。
4. **`MenuBarIconStyleApplier` 的 `UserDefaults.didChangeNotification` 全量监听**（见性能）。
5. **每次打开统计窗全量重查**（`onAppear` 5 条 SQL，P3）。
6. **两个 popover 宽度不一致**（A3 记录）：STATS 部件 popover 用 `Theme.panelWidth` 最小宽、主面板 popover 340——同一位置两种宽度。
7. **`MenuBarTwoLineView.widthHandler` 从未赋值**（死字段，双层标题管线随 v210 删除后仅存于历史）。
