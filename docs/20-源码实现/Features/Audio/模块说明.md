## 模块职责

两块正交能力，同属「音频」功能域：

1. **`AudioMixerController` / `AudioMixerPane`**（`AudioMixer.swift`）——设置「音频」页与刘海媒体页的系统音频面板：系统输出音量/静音、输出设备切换、**实时有声 App 列表**（谁在出声）、本 App 音频 bypass（自管豁免）。核心能力边界由公开 CoreAudio 决定（2026-10-19 探针实测）：进程枚举 `'prs#'`、活动判断 `'piro'`、本进程 bypass `'pmut'` 可用；**其他进程的音量/静音选择器全部返回 `'what'`**——每 App 独立音量走私有 HAL，公开 API 无法实现，故以只读活动列表 + 能力说明呈现。
2. **`NowPlayingController`**（`NowPlayingController.swift`）——系统 Now Playing（MediaRemote）读取与播放控制：曲目元数据/封面/进度/播放状态，播放/暂停/上下曲/seek 命令。15.4 起读取要求 Apple 平台进程，故经系统 `osascript`（JXA）桥接，不直接链接私有框架、不发 Apple Events。

## 入口与主要调用链

- **设置「音频」工具**：`AppBootstrap` 注册 `ToolRegistry` 工具 `audioMixer` → `AudioMixerPane`；`onAppear`→`startRefreshing()`（2s 定时刷有声 App + CoreAudio 属性监听）、`onDisappear`→`stopRefreshing()`。
- **刘海媒体页 / 悬浮球媒体窗**：`IslandMediaContent`、`FloatingBallModuleView`（`.media`/`.volume` 分支）→ `NowPlayingController.shared.setVisible(true, consumer:)`（1s 轮询）；`.volume` 直接复用 `AudioMixerPane`。
- **音量链路**：UI Slider → `outputVolume.didSet` → `setSystemVolume`（按设备能力选 `voll`/`volm`/立体声双声道逐声道写）→ `refreshOutputState` 回读；到 0/1 边界触发 `HapticService.volumeBoundary`。
- **有声 App 链路**：`refreshPlayingApps` 遍历 `'prs#'` 进程对象 → `'piro'`==1 者取 `'ppid'` → `NSRunningApplication` 解析名称/图标（pid 级图标缓存）→ 发布 `playingApps`（顺序不变不发布）。
- **Now Playing 链路**：`request(action:)` → `osascript -l JavaScript`（内嵌脚本加载 `MediaRemote.framework`）→ JSON → `Snapshot` 解码 → 发布 `snapshot`/`artwork`；控制命令 `send(0/1/2/24)`（play/pause/…/seek）→ `MRMediaRemoteSendCommand`。

## 数据流与状态变化

```
音频设置页可见 / 刘海媒体页可见
  ├─ AudioMixer：addOutputListeners（系统对象 dOut/dev# + 当前输出设备音量/静音属性）
  │    属性回调 → refreshOutputState（readingOutput 防回环）→ @Published 回写 UI
  │    2s Timer → refreshPlayingApps（仅设置页持有；刘海只消费系统输出）
  └─ NowPlaying：1s Timer → refresh → osascript → Snapshot
       ├─ 暂停时保留旧 timestamp（防静止卡片因系统新时间戳重绘）
       ├─ 封面：artworkData(base64) 直解 / artworkURL 异步拉取（Task 可取消）
       └─ 消费者清零 → 停 Timer/杀 osascript/取消封面 Task（保留过渡正文用的当前曲目）
```

- `AudioMixerController.readingOutput` 标志防止「回读写回」循环；`selectedDevice.didSet` 只在非回读且值变化时切默认设备。
- `NowPlayingController.position` 由 `elapsed + (now - timestamp) × rate` 推算（播放中持续推进，暂停冻结）。

## 异常和取消处理

- **能力缺失降级**：`volumeReadable`/`muteReadable` 按设备属性探测；设备不提供音量 → `outputError`「输出设备不提供系统音量，请使用设备音量旋钮」，不抛错。读写失败的 OSStatus 均进 `outputError` 字符串供 UI 显示。
- **监听失败**：`AudioObjectAddPropertyListenerBlock` 非 noErr → 记 `outputError`，其余监听继续。
- **osascript 失败**：`run()` 失败 → `feedback`「无法读取正在播放：…」；非零退出 → 解 stderr 为错误描述，`snapshot` 清空、封面 Task 取消。
- **命令未接受**：`commandAccepted == false` → `feedback`「播放器未接受该操作」；接受且为 play/pause 类命令 → `mediaPlayPause` 触觉。
- **取消纪律**：`setVisible(false)` 清空消费者即停 Timer、`process?.terminate()` 杀在途 osascript、`artworkTask?.cancel()`；封面 Task 内 `Task.isCancelled` 检查后才落 `artwork`；隐藏再显示时若封面缺失会重新拉取同一 URL。

## 性能边界

- 有声 App 轮询 2s（设置页可见期间）；Now Playing 轮询 1s（消费者存在期间）；两者的 Timer 都随可见性成对启停，**无常驻成本**（v128 注释明确）。
- 进程图标按 pid 缓存（v128：原先每 2s 重取 `NSRunningApplication.icon`，开窗半小时数千次重复查找）。
- `playingApps` 仅在 pid 顺序变化时发布（避免每 2s 重绘）；`refreshOutputState(refreshDevices:)` 仅设备变化/显式要求时重读设备列表（`80494c67`）。
- osascript 每次读取起一个进程（约数十毫秒级，未实测）；1s 轮询下该开销可感知但被消费者可见性门控。

## 已知限制 / 历史坑

1. **每 App 独立音量做不了**：公开 CoreAudio 的 `pmut/volm/vmul` 对其他进程一律 `'what'`（探针 `/tmp/audioprobe2.swift` status=2003332927）；系统设置里的每 App 音量走私有 HAL。UI 已明示能力边界，勿再尝试补写。
2. **本 App bypass 只能管自己**：`kAudioHardwarePropertyProcessIsAudible('pmut')` 仅对本进程可写——「音频 bypass 豁免」开关的语义仅限自管音频静默。
3. **音量属性三选一**：`voll`（虚拟主音量）→ `volm`（标量）→ 立体声首选双声道逐声道——设备能力不同，写入需遍历全部命中的属性（`volumeProperties`）。
4. **Now Playing 走 osascript 桥**（15.4 起读取要求 Apple 平台进程）：不发 Apple Events、不改自动化/辅助功能权限；脚本内私有类 `MRNowPlayingRequest` 依赖系统私有框架签名，系统大版本变动是已知风险（未确认未来兼容性）。
5. **暂停不换时间锚**（`request` 解码处）：系统每次读取生成新 timestamp，暂停时沿用旧值，否则静止卡片每秒重绘。
6. **状态清理历史**（`8616e919`）：曾移除「有声进程模型」三项无消费者状态——新增 @Published 前先确认有读者。
