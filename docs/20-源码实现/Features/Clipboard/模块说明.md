## 2. 核心类型说明

### 2.1 `ClipboardManager`（`Store/ClipboardManager.swift`）★核心

- 职责与线程模型同深读笔记 §2.1（`queue = com.frsetnext.clipboard.persist` 承担一切 SQLite/文件 IO；主线程只做 NSPasteboard 读取与 `@Published` 发布）。
- 不变量全部仍有效：changeCount 双读比对、自写回声 token+TTL 5s、`inlineTextByteLimit = 64KB`（超限落 `texts/`、内存留 4000 字符）、`maxResidentItems = 800`（v128 注释：翻页是从头拉 `pageSize×(page+1)` 的累积模型，到顶不再翻页）、暂停只同步 changeCount 不 ingest、reload 走 `autoreleasepool`（v128 三处包埋）。
- 轮询：`idlePollingInterval = 2.0`（v101 从 1s 降）、突发 0.5s（`burstUntil`）。
- 现行扩展点：收藏（`FavoritesStore` 联动独立列出收藏条目）、备份恢复入口、`ClipboardOutputFormat` 文本转换、`filesCapturedNotification`（文件中转自动暂存跨模块通知）。

### 2.2 `ClipboardPasteboardReader` / `ClipboardRepository` / `ClipboardFileStorages` / `TagStore` / `ClipboardPruneSchedulers`

与深读笔记 §2.3/§3.4–3.9/§3.11–3.12 语义一致，要点：
- Repository：`@unchecked Sendable`（FULLMUTEX）、24 列、`LIKE ... ESCAPE '\'` 逐字符转义。
- 文件存储：`images/ thumbnails/ texts/ rich_texts/ ocr/` 相对路径 + 内存索引 + 用量统计（`storage_bytes` 口径 = 落盘产物 + 内联内容）。
- TagStore：`attachTags` 持锁就地查表（v126）；assign/unassign 增量索引。
- PruneSchedulers：Retention 1h / Storage 10min；历史坑仍在（主线程批量删、retention 理论死循环、storage 注释与实现相反）——详见深读笔记 §3.11。

### 2.3 `ClipboardTableHostView` 家族（`UI/ClipboardTableHostView.swift`）★表交互核心

同深读笔记 §2.4：`ClipboardTableScrollProxy` / `ClipboardRowHoverSuppressionController` / `ClipboardListTopScrollTracker`（迟滞 40/24）/ `ClipboardRowChromeView`（接管 drawSelection）/ `RowHostingView`（注意：被 `Panel/Preview` 协调器的点外监听命中链识别）/ `ClipboardTableView`（列宽钉剪辑宽）/ `Coordinator` 全交互仲裁 / `ClipboardNativeMenuPresenter`。
七条不变量（tracking area 必须随 isActive 移除、行视图双动作选中、列宽口径、选中绘制接管、rowViewsByRow 裁剪不清空、hovered 双清、isKeyboardNavigating 兜底复位）全部仍有效，逐条有历史事故背书，见深读笔记 §2.4。

## 3. 关键数据流

### 3.1 捕获 → 入库 → 列表（主链，与深读笔记 §4.1 一致）

```
NSPasteboard 变化 → pollTick（0.5s 突发 / 2.0s 闲置）
  → poll(): changeCount 双读 → 暂停/自写回声抑制 → ingest()
      → PasteboardReader.read（图>文件>富文本>文本>URL，指纹 SHA256）
      → persist → queue → writeToDatabase（去重 touch / 落盘 64KB 阈值 / insert）
            ├─ image → scheduleOCR → ocr/<key>.txt
            └─ file → scheduleAutoStage → filesCapturedNotification（中转自动暂存）
      → scheduleReloadCoalesced → items(≤800) → itemsDidChangeNotification
            → CloudLinkPromptController / FloatingClipDeskStore / CloudLinkBar
```

### 3.2 预览（v206 后单窗形态）

```
行 hover/空格 → ServiceLocator.panelPreview（Panel/Preview 协调器）
  → ClipboardPreviewWindowController.show（identifier frset.clipboardPreview）
  → 关闭链：hoverOut/Esc/点外/… → closeAnimated → handlePreviewWindowDidClose
```

### 3.3 悬浮工作台（v191）

```
双击 ⌘（DoubleTapCommandMonitor，0.4s）/ 菜单 / 快捷键
  → FloatingClipboardWindowController.showNearMouse()
  → FloatingClipboardDeskView（FloatingClipDeskStore 查询/预览/键盘闭环）
```

## 5. 不变量与陷阱（现行）

1. 一切 SQLite/文件 IO 必须在 `queue` 上（例外：`ingestToolOutput` 的同步 repository 访问是已知隐患）。
2. 自写回声 token + 5s TTL + 同步 `lastChangeCount`，缺一则复制即重复入库。
3. `maxResidentItems = 800` / `inlineTextByteLimit = 64KB` 口径不得单改一处。
4. NSTableView 七条交互不变量（见 §2.3 / 深读笔记 §2.4）逐条有效。
5. hover 预览窗圆角不得用 `layer.masksToBounds`（v71 阴影）；identifier `frset.clipboardPreview` 是面板不收起的白名单依据，不得改名。
6. `ClipboardPreviewWindowController` 只 close 不销毁（`isReleasedWhenClosed = false`），清理唯一入口 `handlePreviewWindowDidClose`。
7. 编辑窗 `saveTapped` 双写库无事务——保存后立即退出 app 可能只落一半。
8. Prune 主线程批量删的卡顿与 retention 理论死循环仍在（见深读 §3.11）。
