## 模块职责

- **事件层**（`HapticEvent`）：18 类真实业务事件（网格吸附/复制/截图/传输完成/失败…）→ 4 种节奏类（boundary/success/milestone/failure）。只描述"发生了什么"，不碰设备。
- **配置层**（`HapticConfiguration` + `HapticSettingsStore`）：总开关/强度/事件停用集，JSON 持久化（defaults 键 `haptic.configuration`）+ 内存快照 + 版本迁移。
- **业务层**（`HapticService`）：唯一执行入口——开关判断 → 节奏编排 → 每事件类节流 + 跨事件错峰 → 线程调度 → 驱动回落；设置页试听。
- **驱动层**（`HapticDriver` + `TrackpadActuator`）：`HapticDriverRouter` 私有优先/公开回落；`TrackpadActuator` 直连 MTActuator（手离触控板也有效）。
- **设置页**（`HapticSettingsPane`）：草稿式编辑（未保存不影响业务）、逐事件开关、试听、设备能力如实说明。

## 入口与主要调用链

```
业务模块完成点（网格吸附/复制/截图/传输…）
 └ HapticService.shared.perform(.xxx)                 [HapticService.swift:63]
    ├ store.current 一次加锁读（内存快照，不碰磁盘/JSON）
    ├ configuration.isEnabled(event)：总开关 ∧ 强度≠off ∧ 事件未停用
    └ schedule(event:intensity:respectCooldown: true)
       ├ queue.async（com.kitnest.haptics，userInitiated）
       ├ 每事件类节流：now - lastFiredAt[event] ≥ event.cooldown，否则直接丢弃
       ├ 全局槽位错峰：slot = max(now, lastSlotAt + 45ms) → asyncAfter 延迟排期（**延而不丢**）
       └ emit：HapticPattern.steps 按节奏类展开
          ├ boundary：单击，强度封顶「中」
          ├ success：单击
          ├ milestone：双击（0 + 90ms）
          └ failure：双击（0 + 60ms），强度强制 ≥「中」
             └ router.deliver(HapticPulse)                [HapticDriver.swift:133]
                ├ PrivateHapticDriver（actuator.actuate(3/4/6)）→ .privateActuated / .failed
                └ 回落 PublicHapticDriver（NSHapticFeedbackManager，主线程）→ .publicRequested
                   └ record：Log.info + 主线程更新 lastDelivery/availability
```

**设置页**：`HapticSettingsDraft`（草稿）→ 改动即时 `preview` 试听（用草稿强度、不落盘）→ 保存时 `HapticService.apply` → `HapticSettingsStore.save`（**写盘成功才替换内存快照**）。

**生命周期**：`AppDelegate.applicationDidFinishLaunching` 先行 `HapticService.shared.start()`——订阅 `NSWorkspace.didWakeNotification`（唤醒后 `invalidate()` + 0.5s 后重建句柄）+ 启动 0.8s 后才碰私有框架（避开"点图标到出现界面"的启动关键路径）。

## 数据流与状态变化

1. **配置三态**：defaults JSON（`haptic.configuration`）→ `HapticSettingsStore.snapshot`（内存真源）→ 设置页草稿（未保存不影响业务）。`Equatable` 不比较 `schemaVersion`（迁移只补版本，不能显示"有未保存修改"）。
2. **迁移**（schema < 2：`light`→`medium`；< 3：补版本号）：解码纯函数 + `migrated()` 显式返回（旧实现把迁移写进 `init(from:)` 顺手 persist——读一次配置写一次盘，且在任意解码线程改持久数据）。
3. **驱动状态机**：`TrackpadActuator.State`（unprepared → ready(deviceID) 或 noDevice/frameworkUnavailable/openFailed）；`HapticService.availability`（`@Published`）按 router 状态发布给设置页；`lastDelivery`/`lastEvent` 只读诊断（不发布，避免每事件刷新 UI）。
4. **节流状态**：`lastFiredAt: [HapticEvent: TimeInterval]`（每事件类窗口）+ `lastSlotAt`（全局 45ms 槽位），均只在串行队列访问。

## 依赖关系

- **上游**：IOKit（`AppleMultitouchDevice` 枚举）、`/System/Library/PrivateFrameworks/MultitouchSupport.framework`（dlopen，仅 4 个符号）、AppKit `NSHapticFeedbackManager`、`Core/UI`（`Toast`、`Log`、`@Stored`、Settings 组件族）。
- **下游（业务接线点，各模块在完成点调 `perform`）**：Features/Panel（gridMove/gridResize/layoutSaved）、Clipboard（copy）、Capture（screenshot/ocr）、TransferDock/Recording/AI/Search（transferCompleted/downloadCompleted/transferFailed/recordingSaved/aiCompleted/searchCompleted）、设备事件、媒体键。
- **AppDelegate**：启动接线（`HapticService.shared.start()`）。
- **不依赖**：任何设备 SDK；无常驻硬件轮询。

## 异常和取消处理

- **调用失败只做「关掉 → 重新发现 → 重开一次」**，不无限重试；仍失败返回 `false` → router 回落公开接口 → 业务无感（`perform` 立即返回，不抛错）。
- **句柄失效**（睡眠唤醒后）：`actuate` 失败自动 close+reopen 一次；`didWakeNotification` 时 `invalidate()` 全释放，下次 `prepare` 重建；重发现限频 20s（`rediscoveryInterval`，防每个事件都枚举 IOKit）。
- **设备能力不可用**：`HapticDelivery.unavailable`/`.failed` 如实记录；设置页按 `HapticAvailability` 如实说明（"试听 ≠ 场景已接线"，不拿试听成功冒充真实触感）。
- **配置损坏**：`JSONDecoder` 失败 → `Log.warn` + 回默认配置（不崩、不丢用户——下次保存覆盖）。
- **`init` 零 I/O**：dlopen/设备枚举/开句柄全在后台串行队列（`com.kitnest.haptics.actuator`），主线程调用立即返回。

## 性能边界（实测数字，来源标注）

- **每事件类节流**（`HapticEvent.cooldown`，2026-11 重构）：boundary **0.09s** / success **0.25s** / milestone 与 failure **0.40s**。拖网格等高频场景连续吸附允许更快，完成/失败类慢一些。
- **跨事件间隔 45ms**（`minimumSpacing`）：**延迟排期而不丢弃**——旧实现共用一个 60ms 窗口，两个真实事件互相抑制（拖网格把截图成功的反馈吃掉）。
- **读路径**：`perform` 只做一次 `NSLock` 读内存快照。旧实现每个触觉事件 `UserDefaults.data` + `JSONDecoder.decode` 一次——网格拖拽时每帧一次 JSON 解码（重构动机之一）。
- **启动**：设备预热推迟 0.8s（避开启动关键路径）；唤醒后重建在后台队列。
- **内存**：无常驻图像/帧缓冲；`TrackpadActuator` 只持 4 个函数指针 + 1 个设备句柄。

## 验证（2026-11-23，本机）

硬件：MacBook 内建 Force Touch 触控板（IORegistry `ActuationSupported=Yes`、`MT Built-In=Yes`、`Multitouch ID=0x7000000000000e7`）；**无外接 Magic Trackpad**。

做法：把 `TrackpadActuator.swift` + `HapticDriver.swift`（以及含业务层的 `HapticService`/`HapticConfiguration`/`HapticEvent`）与一个 `main.swift` 直接用 `swiftc` 编成独立可执行文件，**跑的是仓储里的同一份源码**，不重启主 App、不动前台焦点；`Log` 用一个打印替身。

| 用例 | 结果 |
|---|---|
| 真实路径：`prepare` → `actuate(id: 4)` | `ready(deviceID: 0x7000000000000e7)`，返回 true，`router.deliver` = `privateActuated` |
| 符号缺失：`--haptic-framework=<自建 dylib，无 MTActuator 符号>` | `frameworkUnavailable`，`actuate` 返回 false 不崩，`availability = publicOnly(.frameworkUnavailable)`，`deliver` = `publicRequested` |
| 业务层（含配置/节流）：`HapticService.start()` + `perform(.gridMove)` | 正常路径 `lastDelivery=privateActuated`、文案「触控板马达已就绪…」；符号缺失路径 `lastDelivery=publicRequested`、文案「系统不再提供马达私有接口…」 |
| 设备选择纯函数（6 例合成字典） | 内建优先、外接兜底、`ActuationSupported=No`/缺 ID/空列表均排除，全过 |

未覆盖：外接 Magic Trackpad 的物理震动（无硬件）；「手指离开触控板也能感到」属于主观感受，仍只能由人确认（日志只能证明调用成功）。

## 已知限制 / 历史坑

1. **`HapticEvent.rawValue` 入用户配置（`disabledEvents`）——改名等于丢配置，只能新增不能重命名**。
2. **硬件只有三档波形（3 轻 / 4 中 / 6 重）**：不做"18 事件 18 种波形"（做不到且手感不可预期）；强弱差异靠节奏类（单/双击、间隔、强度上下限）表达。
3. **公开接口只在手指贴着触控板时有效**：`NSHapticFeedbackManager` 无返回值，只能如实返回 `publicRequested`（"已请求"≠"已产生触感"）；Mac mini / 无 Force Touch 机型只有这条路。
4. **外接 Magic Trackpad**（2026-11-23 复核）：`actuationDeviceID` 已放宽到 `ActuationSupported + Multitouch ID`（旧实现只认 `MT Built-In` 排除外接）。**本机没有外接板**（蓝牙列表无 Magic Trackpad；IORegistry 只有 1 个 `AppleMultitouchDevice`，`Product = Apple Internal Keyboard / Trackpad`），因此物理外接板的震动仍**未实测**。已验的是选择逻辑：抽成纯函数 `selectDeviceID(from:)` 后，用合成字典跑「仅内建→内建 / 内建+外接→内建优先 / 仅外接→外接 / ActuationSupported=No→排除 / 缺 Multitouch ID→排除 / 空列表→nil」6 例全过；本机真实枚举仍得到 `id=0x7000000000000e7`（内建）。**剩余风险**：外接板是否暴露 `AppleMultitouchDevice + ActuationSupported`、`MTActuatorOpen` 对外接设备 ID 是否同样成功——需接一块实体 Magic Trackpad 才能确认。
5. **私有 API 边界**：只封装 MTActuator 四符号，不新增私有函数、不硬编码新波形；系统改动/未来版本移除 → `frameworkUnavailable` → 静默回落公开接口。**这条回落路径已实测**（2026-11-23）：把 `--haptic-framework=` 指向一个只有无关符号的自建 dylib，`TrackpadActuator` 状态为 `frameworkUnavailable`、`actuate` 返回 false 不崩；`HapticService.perform(.gridMove)` 仍投递，`lastDelivery = publicRequested`，设置页文案变成「系统不再提供马达私有接口：仅向系统接口请求…」。同一次运行去掉参数则回到 `ready` + `privateActuated`。排障钩子默认不生效，业务路径永不带该参数。
6. **`probe.haptic` 一次性探针**（用后自删）：不删会让每次启动都敲一下（`72cccd20` 修复）。
7. **试听语义**：`preview` 用草稿强度、绕过节流（`respectCooldown: false`），只证明"设备能给出什么反馈"，不证明场景已接线——设置页 Toast 文案明确区分。
