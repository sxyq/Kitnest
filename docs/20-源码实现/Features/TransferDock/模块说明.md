## 2. 三条传输通道（关键架构）

| 通道 | 实现 | 对端要求 | 数据路径 |
|---|---|---|---|
| **隔空投送** | `AirDropSendEngine`（`NSSharingService`）+ `AirDropReceiveWatcher` | iPhone 零安装 | 系统级 P2P（AWDL） |
| **扫码直传** | `LanTransferServer`（NWListener + 自写 HTTP） | 手机浏览器（零安装） | 局域网 HTTP，4 位 token |
| **ADB 直传** | `ADBFileBridge` + `AndroidWebDAVServer` | Android + 开发者选项 | USB / 无线 adb |
| （云端） | `TransferDockService`（`python3 frset_bridge.py`） | OPPO 中转站账号 | 公网 |

## 3. 入口与主要调用链

### 3.1 拖文件进中转 → 空投

```
拖入 → LocalTransferStore.add(urls:)
  ├─ stage(from:to:)：hardlink / symlink / copy
  ├─ items.insert + persist(index.json)
  └─ post .localTransfer.didChange
勾选 → AirDropSendEngine.send → NSApp.activate → NSSharingService.perform
```

### 3.2 手机扫码接收（定向）

```
勾选 → showPickQR()
  ├─ LanTransferServer.startIfEnabled → attemptBind（端口顺延 9 次）
  └─ shareURL + "?pick=ids" → 二维码
手机扫码 → GET /s/<token>/ → api/list → dl/<id>
POST api/upload → MultipartParser → addUploads
```

### 3.3 云端（OPPO 中转）

```
进「云端」→ TransferDockService.refresh()
  → runBridge(["status"]) + runBridge(["list","1","200"])
未登录 → TransferDockLoginView（WKWebView cookie 轮询）
上传 → runBridge(["upload", path])
```

### 3.4 扫码直连投屏（v264 新增）

```
投屏页 → AdbQrPairing
  ├─ Mac 生成 S/P → 二维码（WIFI:T:ADB; 前缀）
  ├─ 手机系统相机扫码 → 自动跳无线调试 → enablePairingByQrCode
  ├─ adbd 广播 _adb-tls-pairing._tcp → mDNS 发现
  └─ adb pair + adb connect
免扫码重连：AdbCastMemory 记忆设备 → 自动 reconnect
```

## 4. 数据流与状态变化

- `LocalTransferStore.items`（`@Published`）→ index.json 持久化 → `.localTransferDidChange` 通知
- `LanTransferServer`：`running/port/shareURL/statusText`（`@Published private(set)`）→ 串行队列 `frset.transfer.lan`
- `TransferDockService`：`loggedIn/leftSpace/totalSpace/files`（`@Published`）→ 30s liveSync + 300s keepAlive
- `AdbQrPairing`：Phase 状态机（发现→配对→连接）

## 6. 异常和取消处理

| 场景 | 处理 |
|---|---|
| 主线程冻死（v105 实锤） | 目录枚举/Process/waitUntilExit 全部后台化（236s 冻结根因） |
| 读管道死锁 | `readDataToEndOfFile` 必须在 `waitUntilExit` 之前 |
| `LocalTransferPaths` 单例重入 | 抽成纯静态 enum（`dispatch_once` 重入 SIGTRAP 修复） |
| 端口占用 | `attemptBind` 顺延 9 次 |
| adb 永久挂起 | `ADBExtrasEngine.run` 自己轮询 `task.isRunning` 每 60ms + 超时 terminate |
| scrcpy 非激活面板 | `NSApp.activate` + 0.12s 后 `perform` |
| 上传 multipart | body 落临时文件 → mapped 解析（不整段进内存） |
| 云端桥接 | 读管道先于 waitUntilExit + 10 分钟兜底 terminate |

## 8. 已知限制 / 历史坑

1. **`MCPServer` `adb_shell` + CORS 全开 + 无 token**（高）：默认关闭，但开了后任意本机网页可执行 `adb shell`。
2. **HTTP 服务未显式绑定 127.0.0.1**（高）：NWListener 默认监听所有接口，注释写"只绑本机"但无 `requiredLocalEndpoint`。
3. **`AndroidWebDAVServer.download` 全量入内存**（高）：大文件 OOM。
4. **`TransferDockPath.root` 硬编码开发者本机路径**（中，发布风险）。
5. **lan token 4 位**（中）：约 100 万组合，同网段穷举成本低。
6. **`LocalTransferStore.add` 主线程做 linkItem/copyItem**（中）：大批跨卷拷贝卡 UI。
7. **`LanTransferServer.onMain` 用 `main.sync`**（中）：主线程卡住时所有 HTTP 连接一起阻塞。
8. **四份 adb 执行器并存**（架构性）：`ADBExtrasEngine.run` / `ADBWirelessEngine.runADB` / `ADBFileBridge.runADB` / `AdbPairingService.runADB`，超时策略不一致。
9. **`findScrcpy()` 每次起 `which` 子进程**（中）：无缓存。
10. **`refreshCloudLogin` 用 `waitUntilExit` 无超时**（中）：Edge cookie 脚本卡住占线程。
11. **`ADBFileBridge.pushOne` 每 0.7s 起一个 `adb shell stat`**（中）：大文件 push 起几十上百个进程。
12. **`LocalTransferItem.mode == .upload` 时 `originalPath` 语义错误**（低-中）：指向已删除的临时文件。
