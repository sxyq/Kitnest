## 模块职责

给「一段代码字符串」提供从识别到呈现再到导出的完整链路：语言自动识别（扩展名 > 内容特征）→ 词法着色（注释/字符串/关键字/类型/函数/属性/数字/标点/attribute）→ 屏幕渲染（NSTextView + 行号标尺 + 工具条内联调参）→ 复制导出（HTML+RTF 富文本 / 纯文本 / HTML 源码 / 卡片图）。屏幕渲染与复制导出用**同一份** attributed 结果（「看到什么就复制到什么」）。交互参照 highlightcode.com：所有开关都在同一个框的工具条里，改完立刻重排。

## 入口与主要调用链

**两个正式消费者**（模块是纯渲染库，无窗口/注册逻辑）：

1. **面板预览 hover 内联**（`Features/Panel/Preview/PreviewPopoverContentView.swift:627`）：`CodePreviewView(code: model.inlineText, fileName:)`——文件预览为代码时整块替换为代码预览框。
2. **工具箱「代码预览」工具**（`Features/Toolbox/Tools/BuiltinTools.swift:256` `registerCodePreviewTool`）：粘贴代码 → `CodeCardImage.render` 出卡片图 + `CodeHighlighter.statistics` 统计；主题沿用 `CodePreviewPreferences.themeID`。

渲染主链路：

```
CodePreviewView(code, fileName)
  ├─ resolvedLanguage：languageID=="auto" ? CodeLanguageCatalog.detect : 显式 id
  ├─ renderKey = themeID|fontSize|languageID 变化 → .task(id:) rebuild：
  │    Task.detached { CodeHighlighter.attributed(normalize(code), options) }
  │    → cached NSAttributedString（cachedKey 防切换期间呈现旧配色）
  └─ CodeTextViewRepresentable(cached)：NSTextView + CodeLineNumberRuler + WindowThemeSync
复制链路（同一份 options，同源着色）：
  ├─ 富文本/HTML 源码 → CodeRichCopy.makePayload(exportAttributed)
  ├─ 图片 → CodeCardImage.render
  ├─ 纯文本 → CodeHighlighter.normalize
  └─ 选区 ⌘C → CodeRichCopy.copyAttributed（直接用屏幕已渲染的 attributed）
```

## 数据流与状态变化

- **词法两遍扫描**（`CodeLexer`）：第一遍沿 UTF-16 标注释/字符串（必须先吃掉内部，防字符串里的 `#`/`//` 误判）；第二遍标识符/数字/标点，按关键字表与位置特征着色（后跟 `(` 是函数、前有 `.` 是成员、后跟 `:` 是属性等）；`compress` 输出同色连续区间（只含非 plain 段）。Diff/Markdown 走行级特例分支。
- **规范化**：`\r\n`/`\r` → `\n`；制表符**按列对齐展开**到 tabWidth 整数倍制表位（行号与缩进对齐都依赖这步）。
- **屏幕 vs 导出**：屏幕行号由 `CodeLineNumberRuler` 画（正文不含行号）；导出用 `exportAttributed` 把行号写进文本（Word 无标尺，靠字符对齐）。
- **配置持久化**：`persist()` 写 `code.preview.theme/fontSize/lineNumbers/wraps` 四键；`isSettingsPreview` 环境下所有写操作/复制操作短路（复制演示假象）。
- **换行容器**：`wrapsEnabled` didSet → `syncWrapContainer` 钉容器宽度到「视图宽 − 左右内边距」，关闭时放开无限宽走横向滚动；`setFrameSize` 每次改尺寸同步。

## 异常和取消处理

- **空代码**：`code` 去空白后为空 → 显示「没有可预览的代码」占位，不着色。
- **超长代码**：`CodeLexer.maxHighlightLength = 300_000`（UTF-16 单元）以上**不着色**直接返回空 token（长日志/大文件保流畅，纯文本仍可读）。
- **着色期间**：`cachedKey != renderKey` 显示「正在着色…」ProgressView，不呈现旧配色；`rebuild` 的 detached Task 以 `renderKey` 快照比对，取消的 Task 不落缓存。
- **复制失败**：`flashCopied(ok: false)` → Toast「复制失败」；图片生成失败 → Toast「图片生成失败」。
- **设置预览隔离**（`isSettingsPreview`）：复制只闪按钮文案、`persist()` 直接 return——预览不写真实配置、不污染剪贴板。
- **标尺文本更新**：`updateText` 用 UTF-16 偏移建 `lineStarts`（与 NSTextView 字符区间一致），`drawHashMarksAndLabels` 只画可见 glyph 对应行。

## 性能边界

- **词法规则复用**（`7da761fe`）：`specs` 静态字典按语言预编译关键字集/注释标记（UTF-16 数组预转换），每次着色零解析开销。
- **行号只画可见行**（`963aeb26`）：二分定位 `lineStarts` 到可见 charRange 起点，逐行用 lineFragmentRect 绘制——1 万行文件滚动时每帧只画几十个数字。
- **着色异步化**：`rebuild` 在 `Task.detached(userInitiated)` 上执行，UI 线程不阻塞；大文件代价集中在一次词法扫描（纯 CPU，未实测耗时）。
- **HTML 源码按需生成**（`fc169712`）：`makePayload(includeRTF:)` 可跳过 RTF 编码；「复制 HTML 源码」只生成 HTML 一种格式。
- 300k 字符着色上限为**源码常量**；具体毫秒数**未实测**。

## 已知限制 / 历史坑

1. **换行容器宽度不能写 0**（v191，`CodePreviewTextView` 注释）：旧实现换行分支把 `containerSize.width` 设 0 交给 `widthTracksTextView`，首帧 0 宽排版 → 整篇空白只剩行号。现钉「视图宽 − 内边距」并在 `setFrameSize` 同步。
2. **代码区底色必须 100% 主题色**（v192.1）：曾为「玻璃感」降到 90%，浅色纯白被窗口底污染成 #F5F5F7、深色抬灰——切主题「背景变了颜色却不对」。玻璃感由圆角/阴影/层次承担，不靠代码区透光。
3. **切主题必须重建语法颜色 + 跟随窗口明暗**（`b195ec47`）：窗口打开时只设一次 appearance，换主题后标题栏停在旧明暗（「上黑下白」用户截图 2026-11-03）；`WindowThemeSync` 挂视图树同步，且窗口必须 `isOpaque = true`（半透明会让标题栏与内容区采样不同底衬出现上下色差）。
4. **切行号保留着色与滚动位**（`5864d5a6`）：`updateNSView` 换 attributed 前记录 `contentView.bounds.origin`，写完 `scroll(to:)` 还原。
5. **语言标记最长前缀匹配**（`1718eb67`）：`markers` 按前缀长度降序——`c++11` 不再命中 `c`、`javascript1.8` 不再命中 `java`。
6. **段落样式不设 lineBreakMode**（`CodeHighlighter.paragraphStyle` 注释）：曾设 `.byClipping` 让自动换行开关彻底失效（容器再窄也裁掉不折行）。
7. **RTF 整块底色是近似**：RTF 没有「卡片」概念，用字符底纹贴文字——Word 里是底色带而非整卡；HTML 表格卡片才是接近截图的效果（主推 HTML）。
8. **独立预览窗已删**（`2d422b82`）：JSON 检视器/代码预览独立窗收敛为 hover 内联，新增消费方应复用 `CodePreviewView` 而非重建窗口。
