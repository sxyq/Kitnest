## 2. 分析方法（二进制码全量提取）

原版二进制符号表已剥离（`nm` 仅 56 个本程序符号），采用**元数据逆向**路线，自研 Mach-O arm64 解析器（`parse_frset_binary.py`，约 380 行，零第三方依赖）：

| 提取项 | 数据源 | 结果 |
|---|---|---|
| 全部函数入口 | `LC_FUNCTION_STARTS`（ULEB128 增量链） | **41,778 个函数入口地址** |
| ObjC 类/方法 | `__objc_classlist`（536 条）+ `__objc_catlist` + `__objc_protolist`，class_t→class_ro_t→method_list_t 全链遍历（含元类类方法） | 531 类 / 4 分类 / 65 协议 / **2,670 方法** |
| Swift 类型 | `__swift5_types` / `__swift5_protos` 描述符遍历（flags&0x1F 区分类/结构体/枚举） | 1,462 描述符 → 去重 1,314 类型 + 82 协议 |
| Swift 存储属性 | `__swift5_fieldmd` 字段记录（{Flags@0, 类型@4, 名称@8} 12 字节布局） | 1,529 描述符 / 6,895 字段 / 4,256 唯一属性名 |

**本二进制的特殊指针编码（实测破译）**：`__DATA`/`__DATA_CONST` 的 8 字节指针 = `(tag << 32) | (vaddr - 0x100000000)`；方法表 name 字段经 `__objc_selrefs` 两级跳转取选择器串；Swift 类元数据位于 `__data`（与 ObjC class_t 同布局）。解析质量用双重基准验证：**档案 191 类清单 191/191 全部命中**；类型编码（如 `{PLCrashHostInfoVersion=QQQ}16@0:8`）逐字段解码正确。

**FrsetNext 侧**：`extract_frsetnext.py` 复刻 reindex.py 的作用域跟踪/多行签名/花括号配对逻辑并增强（补 `init` 捕获 267 个 + 类型声明 724 个），与仓库既有 `docs/perfaudit/函数清单-AST抽取.csv`（2,042 func）口径一致。

## 8. 局限性（如实声明）

1. **纯 Swift 方法不可逐一点名**：原版剥离了符号表，非 @objc 的 Swift 函数只能计数（41,778）不能命名；方法级核对因此以 ObjC 协议面为主。
2. **字段元数据无法归属到类型**：`__swift5_fieldmd` 的描述符自身类型名指针指向 `__swift5_typeref` 的编码未能破译，属性名（4,256 个）只能作全集覆盖信号（926 个在 FrsetNext 源码出现），不能逐类型核对。
3. **「待确认」需人工过目**：204 个类型级待确认 + 9 个功能型待确认，主要靠名称部分匹配判定，建议下一轮结合 UI 行为对照表（`tests/行为对照表.md`）收敛。
4. **同名≠等价**：类型同名只证明命名一致，行为等价仍需 `tests/` 行为对照表把关（本报告是静态结构核对，不替代行为验收）。
