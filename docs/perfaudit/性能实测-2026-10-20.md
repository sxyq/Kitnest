# FrsetNext 性能实测与优化报告（2026-10-20）

> 对象：`apps/FrsetNext`（当前 main）。
> 方法：`sample` 调用栈采样（1ms 间隔）、`proc_pid_rusage` 精确 CPU 时间、
> `footprint` 内存、环境变量门控的**函数级计时探针**（`FRSET_PERF_PROBE=1`）、
> 启动端到端计时（进程启动 → 「全部模块已启动」日志）。
> 所有数据均在本机（Apple Silicon / macOS 27.0.1）实测，非估算。

## 1. 结论摘要

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 静息（面板关闭）单次 `refresh()` | **126.4ms**（p50，max 144.5） | **10.6ms**（p50） | **-92%** |
| 面板打开单次 `refresh()` | ~126ms（同静息，无门控） | **12.1ms**（p50） | **-90%** |
| SMC 全量扫描 | 每 3s 一次，**103ms/次（占 82%）** | 可见 5s / 隐藏 30s 一次 | 静息频率 **-83%** |
| 静息 CPU | 0.15% 单核 | 0.16% 单核 | 持平（原开销多为 I/O 等待，非 CPU） |
| 活动态 CPU（面板打开） | — | 0.20% 单核 | 可忽略 |
| 内存 footprint | 97 MB（峰值 135 MB） | 75.8 MB（新进程） | 需结合生命周期解读 |
| 冷启动（到模块全启动） | — | 0.50s（首次）/ 0.24s（热） | 达标 |
| 二进制 / 整包 | — | 15 MB / 23 MB | — |

**核心发现**：`refresh()` 的墙钟开销 82% 来自 SMC 全量传感器扫描（600 键，I/O 阻塞型，
CPU 时间很低但会长时间占用采样队列）。该数据只被监测面板消费，面板不可见时完全不必 3s 一扫。

## 3. 已实施优化

### 3.1 SMC 扫描按 UI 可见性门控（最大收益）
`StatsDataProvider.refresh(uiActive:)`：面板/设置页可见时 5s 一扫，隐藏时 30s。
数据消费方只有 `StatsModulePanels` / `MonitorDetailView`，菜单栏部件走 C 引擎 0.5s
快照 `g_snap`，不受影响。

### 3.2 传感器静态元数据缓存
600 个传感器 × 4 次映射查询（官方名/类型/分组/是否均值）= 2400 次 C 字符串查找/次。
映射是静态表，改为 `[key: SensorMeta]` 缓存，首次扫描建表，后续零 C 调用。

### 3.3 GPU 型号只取一次
型号是静态信息，原实现每帧 `String(cString:)` 重建；改为快照为空时才查询。

### 3.4 进程排行同步降频
隐藏 15s / 可见 3s（原固定 3s）。

### 3.5 函数级性能探针（保留，默认关闭）
`FRSET_PERF_PROBE=1` 时输出：
- `refresh.<分段> <ms>`：八段耗时
- `tick refresh=.. read=.. total=..`：单 tick 总账
- `refreshTitles <ms>`：仅当主线程刷新 ≥0.5ms 时记录（实测未触发，说明该项不是瓶颈）

## 4. 剩余优化候选（按性价比排序，尚未实施）

1. **SMC 扫描本身 100–160ms/次**：可只扫描面板当前需要的键（CPU/GPU 温度、风扇，约 40 键），
   预计从 100ms 降到 <10ms。需要 C 层提供按 key 过滤接口，改动面中等。
2. **GPU 查询 3.5ms/tick**：C 层缓存 `IOService` 句柄可省重复匹配；或隐藏时每 2 tick 采一次。
3. **`sampleOnce` 双重采样**：先 `refresh()` 全量采集，再 `readResult()` 采 CPU/内存/网络/磁盘，
   随后这些字段**全部被 `g_snap` 覆盖**。`readResult` 仅 0.7ms，收益小但属明确冗余，
   建议后续拆出 `readSupplement()`（仅温度/功耗/负载/压缩内存）。
4. **菜单栏 0.5s tick**：`FSBarSystemTick` 采样占比约 0.13% 单核（可接受）；
   `FSBarKeepAdjacentTick` 非校准期仍每 0.5s 主队列空跳，可加 `g_posCalibrating` 短路。
5. **`refreshTitles` 模板图重建**：探针显示单次 <0.5ms（未触发日志），暂不优化；
   如后续项目数增多，可按「文本未变则跳过重建」缓存。

## 6. 复现方式

```bash
# 构建（自动部署到 /Applications）
cd apps/FrsetNext && ./build.sh

# 带探针启动
FRSET_PERF_PROBE=1 /Applications/FrsetNext.app/Contents/MacOS/FrsetNext

# 调用栈采样
sample $(pgrep -x FrsetNext) 8 1 -file /tmp/frset_sample.txt

# 重新索引函数台账（保留人工审核结论）
python3 tools/perf_audit/reindex.py
```
