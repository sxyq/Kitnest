# 规划：悬浮剪贴板「全新设计」（对标 Frset 新版）

> 状态：**方案待评审，未动代码**
> 参考：B 站 BV15bxJ6LezV（2026-11-01）画面 + 视频文案 + frset.com 官网「Floating Clipboard」卖点
> 目标版本：v190 之后第一个独立迭代

---

## 0. 一句话结论

现有浮窗是「240×290 的小列表 + 底部三个图标」，本质是主面板列表的缩小版；
新版要做的是**一个能独立用完全程的剪贴板工作台**：顶部常驻搜索、一行分类、可调大小的网格卡片、拖拽即粘、全程键盘可达、粘完自动消失。

数据层几乎不用改——`ClipboardFilterKind` 已经是 `all/text/image/link/file/code/color/generated/note` 九类，`ClipboardQuery` 已支持搜索/类型/标签/代码类/分页，`copy(autoPaste:)` 已有。**这次主要是 UI 与交互层的重写。**

## 1. 对标拆解：他到底是怎么做的

### 1.1 截图逐元素（视频 00:04 附近）

| 元素 | 观察到的做法 | 含义 |
|---|---|---|
| 窗口 | 无标题栏、无红绿灯、大圆角（≈12）、深色半透明玻璃 | 悬浮件而不是窗口；背景内容透出来 |
| 顶部 | 左侧 🔍 + 占位「Search Clipboard」，右侧一个小圆形按钮 | 搜索**常驻**，不是点开才有 |
| 分类 | `All Text Image Link File Code Color Tool Note` 平铺一行，末尾一个标签图标 | 分类无胶囊底、选中靠字重/色；标签是独立入口 |
| 内容 | 双列瀑布流：大图卡（VOTE）、文本卡（7 Best Color Picker…）、链接卡（frset.com/sitemap.xml、chatgpt.com/share/…） | 卡片高度随内容，不强制等高 |
| 卡片角标 | 左下＝来源 App 图标（Chrome），右下＝相对时间（9m/2h ago） | 来源与新鲜度是卡片的一等公民 |
| 卡片内容 | 没有标题行，内容直接铺满；链接卡只显示 URL，长 URL 尾部省略 | 信息密度优先，不做多余装饰 |
| 间距 | 卡片间距 ≈8–10，卡片内边距 ≈8–10 | 紧凑，视觉重心在内容 |
| 交互暗示 | 鼠标停在 VOTE 卡上，卡片无强边框 | hover 反馈应轻（微亮/微抬），不要描边闪烁 |

### 1.2 视频文案（作者原话，可直接当需求）

- 「支持**网格/列表**布局」
- 「可**调整卡片大小**」
- 「支持**拖拽粘贴**」
- 「**快捷搜索**（无需点击搜索栏，**按任意键进入搜索**）」
- 「**用完即走**，非常丝滑」

### 1.3 官网卖点（Floating Clipboard 段落）

- **Rich Preview**——悬停即可预览 Markdown / 语法高亮 / JSON / 图片 / 颜色
- **Paste Multiple Items**——一次粘多条
- **Instant Search**——输入即筛
- **Smart Organization**——标签 / 分类
- 分类枚举：Text、Image、Links、Color、Note、Code、File

> 结论：他要解决的不是「多存几条」，而是 **"我现在就要那一条，别让我翻"**。
> 所以重心在：搜索优先、卡片可扫读、键盘闭环、粘完即走。

## 2. 现状 vs 目标

| 维度 | 现在（FloatingClipboardWindow.swift） | 目标 |
|---|---|---|
| 尺寸 | 240×290 固定小窗 | 680×520 默认，可缩放（最小 520×380），记住尺寸 |
| 列表 | 单列 28pt 缩略图 + 两行文字，最多 12 条 | 网格瀑布（S/M/L 三档）+ 列表双布局，分页加载 |
| 搜索 | 点底部 🔍 才出现输入框 | 常驻搜索栏；**按任意键直接开始输入** |
| 分类 | 无 | 九类 tab + 计数 + 标签入口 |
| 卡片 | 统一行样式 | 按类型渲染：图/文/链接/文件/代码/颜色/笔记 |
| 键盘 | 无（只能鼠标双击） | ↑↓←→ 选择、Enter 粘、⌥Enter 纯文本、空格预览、⌘1–9、Esc、⌘⌫ |
| 拖拽 | 无 | 卡片拖到任意 App 即插入（文本/图片/文件） |
| 多选 | 无 | ⌘点击多选，Enter 依次粘贴 |
| 粘贴后 | 窗口留着 | 自动收起（用完即走） |
| 预览 | 单击 → 独立预览窗（已有） | 保留，另加 hover 轻预览（可关） |

## 3. 交互规格（这篇是重点）

### 3.1 打开

| 方式 | 行为 |
|---|---|
| ⇧⌘V（已有热键 `floatingClipboard`，可改键） | 在鼠标所在屏幕居中偏上弹出；**焦点直接落在搜索框**（光标闪烁，已全选） |
| 双击 ⌘（已有 `DoubleTapCommandMonitor`） | 同上，出现在鼠标位置附近 |
| 主面板 / 状态栏入口 | 同上 |

打开时机的三条硬规则：
1. 面板成为 key 但不激活 App（`.nonactivatingPanel` 保持），保证「粘回去」的目标 App 仍是前台。
2. 打开动效 0.16s（`Theme.Motion.fast`）：缩放 0.97→1 + 透明度 0→1，不打断打字。
3. 打开即预加载第一页（30 条）+ 九类计数，**不等用户输入**。

### 3.2 关闭（用完即走）

| 触发 | 行为 |
|---|---|
| Enter / 双击卡片 / 拖拽出 | 粘贴成功后立即收起，**焦点还给原 App** |
| Esc | 第一次：清空搜索；第二次：收起 |
| 点击面板外 | 收起（1.2s 延迟，防误触） |
| 再按一次 ⇧⌘V | 收起（toggle，已有语义） |
| 鼠标移出且失焦 1.2s | 收起（可设置里关） |

### 3.3 搜索：**按任意键就进**

- 面板打开时搜索框已聚焦 → 用户直接敲字即可，**不需要先点输入框**（这是他视频里的核心卖点）。
- 中文输入法组字中（`hasMarkedText`）不拦截任何按键，避免破坏拼音输入。
- 匹配范围：标题 / 正文 / 别名 / 标签名 / 来源 App / URL 域名。
- 120ms 防抖；结果里命中词高亮（正文片段截取命中位置前后 40 字）。
- `⌘F` 聚焦搜索框并全选；`⌘A` 全选文字；`Esc` 两级（先清词后关窗）。
- 无结果时给一行兜底：「没有匹配 · 用 ⌘K 搜索网页 / 问 AI」（复用 Quick Search，第二期）。

### 3.4 分类

- 一行九类：全部 / 文本 / 图片 / 链接 / 文件 / 代码 / 颜色 / 工具 / 笔记，右侧标签图标。
- 点击切换；`←→` 在 tab 间移动（搜索框为空时）；`⌘1…⌘9` 直选。
- 每个 tab 右侧带计数（灰色小字，0 时不显示）。
- 与搜索可叠加：分类 + 关键词同时生效。
- 标签入口点开是浮层（列出全部 tag + 计数），选中后 tab 行下方出现一枚可点掉的 chip。

### 3.5 卡片

按类型渲染，统一骨架：

```
┌────────────────────────┐
│                        │  ← 内容区（占满，无标题行）
│      内容预览           │
│                        │
│ [App 图标]        9m ago│  ← 角标行：来源 / 相对时间
└────────────────────────┘
```

| 类型 | 内容区 | 建议尺寸 |
|---|---|---|
| 图片 | 缩略图等比填充（`scaledToFill` + 裁切），不加载原图 | L（大卡）|
| 文本 | 最多 3 行，行尾省略；等宽字体仅在代码类 | M |
| 链接 | 域名加粗 + 标题/路径 1 行 + favicon | M |
| 文件 | 文件图标 + 文件名 2 行 + 大小 | M |
| 代码 | 前 4 行 + 语言标签（复用 CodePreview 的词法器着色） | M/L |
| 颜色 | 整块色块 + HEX 值 | S |
| 笔记 | 标题 + 2 行正文 + 📝 角标 | M |

状态：
- 默认 / hover（底色 +4% 提升，抬升 1pt 阴影）
- 选中（键盘光标或单击）：`accent` 1pt 描边 + 8% 填充
- 多选：右上角圆圈勾选 + 计数胶囊「已选 3 项」
- 置顶：右上角 📌 小图标
- 拖拽中：0.9 透明度 + 跟随光标

### 3.6 网格 / 列表 双布局 + 卡片大小

- 右上角一个分段控件：`网格 / 列表`（或图标按钮），记忆到 `floating.layout`。
- 网格三档 `S / M / L`（右键工具条或设置里切，`⌘+` / `⌘-` 也能调）：
  - S：3 列，卡片高 ≈96（适合纯文本/颜色/链接）
  - M：2 列，卡片高 ≈132（默认）
  - L：2 列，卡片高 ≈180（图片为主）
- 列表：单列 44pt 行（缩略图 32 + 标题 + 来源/时间 + 右侧操作），一屏 ≈10 行。
- 卡片大小与布局正交：网格档位只影响列数/高度，不影响列表。

### 3.7 键盘闭环

| 按键 | 行为 |
|---|---|
| ↑ ↓ ← → | 在网格里按几何方向移动光标（不是简单 ±1） |
| Enter | 粘贴光标项，收起 |
| ⌥Enter | 以纯文本粘贴（去格式） |
| 空格 | 打开预览窗（选中项），再按空格关闭 |
| ⌘1…⌘9 | 直接粘贴第 1–9 张卡 |
| ⌘⌫ | 删除光标项（带 3s 撤销 Toast） |
| ⌘D | 置顶 / 取消置顶 |
| Tab | 焦点跳到分类行（再按 Tab 回到搜索框） |
| Esc | 清搜索 / 收起 |

> 键盘实现要点：**搜索框永远持有 first responder**，网格「光标」只是一个索引状态（不是 AppKit 焦点），
> 这样不会出现「焦点在卡片上打不了字」的经典问题。

### 3.8 拖拽粘贴

- 任意卡片可拖：文本 → `public.utf8-plain-text` + `public.rtf`；图片 → 临时 PNG 文件 URL + `public.tiff`；文件 → 文件 URL。
- 拖拽反馈用系统 drag image（卡片截图，带圆角与阴影）。
- 拖到目标 App（微信/飞书/编辑器）松手即插入；面板**保持打开**（拖拽不是"用完即走"的场景）。
- 反向不做（不接外部拖入到浮窗），避免与「拖文件进面板归档」冲突。

### 3.9 多选与批量粘贴

- `⌘点击` 加选 / 取消；`⇧点击` 选范围；`⌘A` 全选当前结果。
- 选中 ≥2 时底部出现操作条：「粘贴 3 项 · 复制 · 合并为文本 · 取消」。
- 依次粘贴：每项间隔 120ms（等目标 App 处理），全部完成后收起。
- 合并为文本：换行拼接后一次性复制（不需要辅助功能权限，作为兜底）。

### 3.10 预览

- 空格 / 单击 → 复用现有预览窗（`ServiceLocator.panelPreview`，`.floatingPreview` 源），已实现，不改。
- hover 轻预览：默认关（网格里 hover 太密易误触），设置项可开，开启后 350ms 延迟。

## 5. 技术方案

### 5.1 文件划分（新增/改造）

```
Sources/Features/Clipboard/
├── FloatingClipboardWindow.swift      【改造】面板尺寸/自动收起/键盘路由/粘贴编排
├── FloatingClipboardStore.swift        【新】状态机：分类·搜索·布局·光标·多选·分页·计数
├── FloatingClipboardChrome.swift       【新】顶栏（搜索 + 分类 + 布局切换）
├── FloatingClipboardGrid.swift         【新】LazyVGrid 瀑布 + 列表双布局 + 键盘几何导航
├── FloatingClipboardCard.swift         【新】七种卡片渲染 + 角标 + 状态
├── FloatingClipboardDrag.swift         【新】NSItemProvider 构造（文本/RTF/图片/文件）
└── FloatingClipboardKeyRouter.swift    【新】NSEvent 本地监听 → 语义动作（含输入法保护）
```

复用：`ClipboardThumbnailView`、`ClipboardRowMenuContent`、`ClipboardManager.copy(_:autoPaste:)`、
`ClipboardRepository.fetch/count`、`PreviewImageLoader`、`ClipboardAppIconCache`、CodePreview 词法器。

### 5.2 数据流

```
ClipboardManager.itemsDidChange ──┐
                                  ├─→ FloatingClipboardStore
用户输入(搜索/分类/布局) ──────────┘        │
                                          ├─ query = ClipboardQuery(search, type/codeLike/tag, limit, offset)
                                          ├─ ClipboardRepository.fetch(query) → [ClipboardItem]
                                          └─ 九类计数：一次 GROUP BY（新增 repository.categoryCounts()）
```

- **不新增表**，不动 `ClipboardItem`。
- 分类 → 查询参数映射：text→type=.text, image→.image, link→.url, file→.file, code→`codeLikeOnly`, color→客户端判定（`#RRGGBB`/`rgb()`/`NSColor` 可解析）, note→`noteOnly`, tool→`toolGeneratedOnly`。
- 计数：`SELECT filter_kind, COUNT(*)` 用一条 SQL 的 `CASE WHEN` 表达式完成，打开面板时算一次，写操作后失效重算（2s 内合并）。

### 5.3 键盘路由（关键实现）

```
NSPanel.keyDown
  └─ FloatingClipboardKeyRouter.handle(event) -> Bool（true=已消费）
       ├─ 输入法组字中 → false（放行）
       ├─ ⌘1…9 / ⌘⌫ / ⌘D / ⌘A → 动作
       ├─ ↑↓←→ / Enter / Space / Esc / Tab → 动作
       └─ 可打印字符且焦点不在搜索框 → 聚焦搜索框并转发字符
```
用 `NSEvent.addLocalMonitorForEvents(matching: .keyDown)` 挂在窗口上（`event.window === panel` 才处理），
面板关闭时移除，避免常驻开销。

### 5.4 性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| 打开到可交互 | < 120ms | 窗口常驻内存、只 orderFront、首屏 30 条 |
| 滚动帧率 | 60fps | LazyVGrid、缩略图异步 + 内存缓存（上限 64 张）、卡片无 material |
| 搜索响应 | < 60ms（本地 SQLite LIKE，30 万条内） | 120ms 防抖 + LIMIT 60 |
| 常驻内存增量 | < 30MB | 图片只读 thumbnailPath；不预解码原图 |
| 空闲 CPU | 0% | 无定时器；仅 itemsDidChange 通知驱动 |

### 5.5 权限与边界

- 自动粘贴需要「辅助功能」授权（已有 `pasteToFrontmostApplication` 与授权引导）；未授权时降级为「只写剪贴板 + 提示按 ⌘V」。
- 拖拽出图片需要在临时目录落一个 PNG（`NSTemporaryDirectory`），退出时清理。
- 沙盒：现有签名是 ad-hoc、非商店沙盒；若后续上架，拖拽需改为 file promise。

## 7. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 抢焦点 | 面板要接键盘就得 key，可能抢走前台 App | `.nonactivatingPanel` + 粘贴前记录 frontmost，粘完 hide 再 activate 回去 |
| 输入法 | 拼音组字时拦截按键会吞字 | `hasMarkedText` 时一律放行 |
| hover 误触 | 网格里卡片密集 | hover 预览默认关，350ms 延迟 |
| 玻璃性能 | 多卡片 + material 会掉帧 | material 只铺一层，卡片纯色 |
| 拖拽沙盒 | 上架后 file URL 可能失效 | 预留 file promise 分支 |
| 与主面板抢 key | 两个窗口同时开着 | 谁最后被点击谁 key，另一个保持可见但不抢焦点 |

## 8. 需要你拍板的 6 件事

1. **默认档位**：2 列中卡（接近截图）还是 3 列小卡（信息更多）？
2. **卡片大小按类型自适应**（图片大、文本小）还是**统一档位**？前者更像他，后者更整齐。
3. **多选批量粘贴**这期要不要（要的话得处理"粘到一半失败"的语义）？
4. **搜索增强**：是否要拼音首字母 / 模糊匹配（成本高，建议二期）？
5. **拖拽出去**的默认内容：图片给原图还是缩略图？文本给富文本还是纯文本？
6. **标签行**是否常驻（占一行高度）还是收进右侧图标浮层（截图是后者）？
